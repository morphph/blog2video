拆成 300 个 Agent → Kimi 自己决定 · 你只描述目标,它自己搭组织架构图
大多数人一听到「300 个 Agent」,本能就是甩一句话过去——「帮我研究一下健身 App 市场」——然后期待奇迹。
这是烧钱最快、产出最垃圾的方式。
一句话,等于把所有决定权都交给了 Swarm,而它八成会决定错。
正确的做法,是把这群 Agent 当成承包商,不是许愿池里的神灯。
你得写清楚:要收集什么、什么样的结果才算数、允许用哪些来源、产出长什么格式、遇到矛盾怎么办。
这份东西,我们叫它 spec,需求说明。
这里有个最容易被忽略的点:怎么把任务拆成 300 个 Agent,是 Kimi 自己决定的。
你不用像在别的框架里那样,手动搭 Agent、连线、定结构。
你只描述目标,这群 Agent 自己去搭那张组织架构图。
这份 spec 是整套循环里杠杆最大的一件东西。
因为到后面那一步,它会变成你那个可复用 Skill 的种子。
