# 300 个 Agent 跑一遍，下一遍它就更聪明了？

[SLIDE 1: cover] (0:00 - 0:38)

一个免费的开源模型，一句话就能拉起 300 个 Agent 同时干活，在真实研究任务上的得分，比你付五倍价钱的模型还高。

这是 Kimi K2.6 的 Agent Swarm 模式。我把这篇拆解从头读到尾，越读越觉得，大多数人根本没碰到它的核心。

今天我不教你怎么点按钮。我只想讲清一件事：为什么这套东西，跑得越多、就越值钱。

[SLIDE 2: principle] (0:38 - 1:38)

先说一个有点扎心的事实。

大多数人打开 Kimi，输入一个问题，拿到一段回答，关掉页面。这就是聊天框。它能用，没错。但这只是这个产品大概一成的能力。

剩下那九成，藏在一个你可能从没点开过的模式里。在那个模式下，你写一句话，它能拉起最多 300 个并行的子 Agent，跨越 4000 步协同动作。

更关键的不是它跑得快。而是只要你用对了，它每跑一遍，都会留下点东西。

可能是一个可以复用的 Skill，一份更锋利的需求说明，或者一条约束，专门用来挡住下次再犯今天这个错。

换句话说，昨天跑你任务的那群 Agent，应该比今天跑它的更聪明。这就是整套循环的灵魂。

[SLIDE 3: principle] (1:38 - 2:40)

大多数人一听到「300 个 Agent」，本能就是甩一句话过去——「帮我研究一下健身 App 市场」——然后期待奇迹。

这是烧钱最快、产出最垃圾的方式。一句话，等于把所有决定权都交给了 Swarm，而它八成会决定错。

正确的做法，是把这群 Agent 当成承包商，不是许愿池里的神灯。

你得写清楚：要收集什么、什么样的结果才算数、允许用哪些来源、产出长什么格式、遇到矛盾怎么办。这份东西，我们叫它 spec，需求说明。

这里有个最容易被忽略的点：怎么把任务拆成 300 个 Agent，是 Kimi 自己决定的。

你不用像在别的框架里那样，手动搭 Agent、连线、定结构。你只描述目标，这群 Agent 自己去搭那张组织架构图。

这份 spec 是整套循环里杠杆最大的一件东西。因为到后面那一步，它会变成你那个可复用 Skill 的种子。

[SLIDE 4: checklist] (2:40 - 3:42)

这是新手最爱跳过的一步，也是跳过代价最高的一步。

你提交 spec 之后，Kimi 不会马上开跑。它会先把执行计划摆给你看：要派多少个子 Agent、每个负责什么、谁依赖谁、整套要花多少步预算。

读它。一个拆错了的两百 Agent 的 Swarm，烧的是真金白银和真实的几个小时。而检查这张计划，不花你一分钱。

你就盯三件事：它理解任务范围了吗？Agent 的数量配得上任务的大小吗？产出计划跟你真正要的东西对得上吗？

这里有个细节值得记住。那 4000 步，是整个 Swarm 的总协调预算，不是每个 Agent 都能跑 4000 步。

300 个 Agent 一起上，平均每个才约 13 步。短、专、窄的小任务。这个数字反过来告诉你，你的任务到底适不适合这个形态。

[SLIDE 5: principle] (3:42 - 4:48)

现在开跑。最多 300 个子 Agent 分波次并行点火。第一波先处理那些完全独立、谁也不靠的子任务。

结果一落地，协调器立刻拉起下一波，去做那些依赖前面结果的任务，一直到整张依赖图跑完。

这里藏着真正的结构性技巧：每个子 Agent 都在自己独立的、有边界的上下文窗口里工作。

为什么这很重要？因为一个 Agent 单独干长任务，会越干越蠢。

不是它笨。是它的上下文窗口会被自己填满，填到溢出，然后开始有损压缩。从那一刻起，它后面每一步推理都更差。

而 Swarm 给每个子任务都配了独立的、划好范围的上下文，最后只把结构化的结果回传给协调器。所以那些会逼疯单个 Agent 的任务，它扛得住。

为什么敢这么浪费？因为它够便宜。输入每百万 token 零点九五美元，输出四美元，重复内容命中缓存只要一毛六。

便宜带来的不是省钱。便宜真正改变的，是你愿意尝试什么。你能负担得起把第一次结果直接扔掉、重跑一遍——这本身就是一种新能力。

[SLIDE 6: image] (4:48 - 5:46)

Swarm 的产出，不是窗口里的一段文字。它是能直接塞进你工作流的结构化交付物。这一点,是很多介绍里都漏掉的。

一次启动，落地的可能是 PDF、表格、数据集、幻灯片，还有能跑的代码。因为这些格式，Kimi 是原生就能吐出来的。

所以写 spec 的时候，永远把产出放在最前面。

你说「一份全面的报告」，等于给了 Agent 提前收工的许可。你说「一份 40 页的 PDF，加一个两万行的 CSV，再加 14 张能直接导出的图表」，才是给了它一个明确的质量靶子。

差别就在产出这一层的具体程度。

我给你看一个贯穿全程的真实例子，是一个量化金融的研究任务，审计股票因子的衰减。它的产出确认长这样：一个 Excel 文件，一张表，40 行 7 列，外加一段 200 词的简报夹在封面页里。

这不是聊天框里的一段话。这是你拿来就能用的东西。

[SLIDE 7: principle] (5:46 - 6:54)

现在到了整套循环里,唯一不属于 Kimi 的那一拍。

Swarm 有个已知的毛病：除非你明确要求它去核查，它会产出一堆听起来很自信、但引用严重不足的论断。而且独立的子 Agent 之间，有时候会自相矛盾。

「看起来做完了」和「它是对的」，是两个星球的事。

这里就该 Opus 4.8 上场了。它的角色不是再生成什么更漂亮的东西——它的唯一职责，是证伪，不是夸奖。

Anthropic 说，它放过自己代码里缺陷的概率，比上一代低了大约四倍。它也是第一个在「不加批判地报告有问题的结果」这件事上拿到零分的 Claude。这个零分,是好事。

你花高价 token，不是用来生成的。你是用它，去抓那个会在下一步被永久存进 Skill 的隐藏缺陷。

为什么非得是另一个模型来把关？因为没有任何一个模型能全面碾压。

就拿一项 Agent 能力的核查基准来说，四个模型各有胜负，谁也没赢者通吃。便宜的并行量，只有在有个可信的东西在检查它的时候，才是超能力。

[SLIDE 8: principle] (6:54 - 7:54)

这一拍，才是让这套循环真正「自我改进」的关键。

一次你以后还会重复的运行结束后，告诉 Kimi：把这整套流程存成一个可复用的 Skill。输入格式、有效的 Agent 步骤、产出格式，全都包进去。

然后,神奇的事情发生了。第一次跑，花你 20 分钟。这之后每一次跑，只要 30 秒。

但我要在这里把一个误会讲清楚。这才是「自我学习」的诚实版本。

模型并没有在你两次运行之间偷偷重训自己的权重。变聪明的，是模型周围那套系统。

你的 Skill 库在每个项目之后都更厚一点。以后每一群 Swarm，都会自动套用这些已经攒下的 Skill。

竞争对手一个礼拜抄不走这个库。因为它是从你几个月的真实运行里,一点点长出来的。

[SLIDE 9: image] (7:54 - 8:42)

Skill 抓的是流程。还有一招,抓的是领域本身。

把你最好的作品传进去——一份谈成了的方案、一份打磨过的报告、一套漂亮的幻灯片——Kimi 会把它的结构和文风指纹,也存成一个 Skill,以后每次 Swarm 自动套用。

复利就长在这里。你喂进去的每一份 PDF、每一段记录、每一张表格，都会变成那 300 个并行 Agent 可以扎根的上下文,而不是退回去靠通用的训练数据瞎猜。

你喂得越多，之后每一次跑得就越准。报告会慢慢不再有那股「通用 AI 味」，开始读起来像你的活儿。

[SLIDE 10: principle] (8:42 - 9:48)

第五步抓住了一个错误。第八步，是确保这群 Agent 再也不犯这个错。

把那个诚实模型给出的修改清单拿过来，别只是把这一次的产出补好。要把这个教训，烤进一个项目级的约束文件里，让 Kimi 每次开工自动读它。

这就是循环在从自己的失败里学习。第一次被抓到的偏差，到第二次就成了一条硬规则。

跑过几个项目之后，你这份约束文件，会变成一份能自己执行自己的活文档。而那个核查的关卡，每跑一次要抓的东西，就越来越少。

我知道你可能会想：把关的越来越闲，不是浪费吗？正好相反。它越闲，说明错误正在被提前消灭，系统在自己加固自己。护城河,恰恰就长在这个过程里。

[SLIDE 11: image] (9:48 - 10:48)

现在,回报来了。

第二次跑，不是从零开始。它从你在前面几步攒下的 Skill、领域知识、还有那份约束文件开始。同一套流程,新的文件,只要一点点设置。

这就是「复利」从一个口号，变成发票上一个实数的时刻。

第一次做竞品监控，要写完整的 spec，还要过一遍核查。到第四次，它就是一句 30 秒的提示词，对着存好的 Skill 跑一下。而且产出更锋利，因为它继承了前面每一次的修正。

第一次 20 分钟，第五十次 30 秒。这个落差，就是你为什么要去搭一个循环、而不是写一句提示词的全部理由。

[SLIDE 12: image] (10:48 - 11:42)

最后一招：一旦这个循环稳定了、有 Skill 撑着了，你就不用再手动去启动它了。

给 Kimi 一个触发条件——一个时间表、一个新文件落盘、或者一个竞品的定价页面——让它主动把整套循环跑完，只把交付物和异常浮出来给你看。

竞品监控就是最干净的例子。第一次你手动搭、手动核。等它变成一个后台 Agent，它会每周并行检查每一个竞品，然后在零边际时间成本下，往你收件箱里丢一份简报。

循环里唯一剩下的人类，是你设的那个问题，和你对答案做的那个决定。

[SLIDE 13: summary] (11:42 - 13:18)

往后退一步看全局。

当那些封闭的实验室还在一次次发布「更聪明一点的聊天机器人」时，一个开源模型,已经在并行跑 300 个 Agent了——而且你每喂它一次,它就在系统层面更聪明一点。

这个指纹，我们其实已经见过一次。一个开源的发布，重新定义了封闭前沿以为自己拥有的东西，然后整个领域一夜之间重新校准。那次叫 DeepSeek。

一个长在开源权重上的、会自我学习的 Swarm，是同一个形状。

那些还在争论「哪个模型赢了」的人，是在回答一个已经不再重要的问题。

现在真正的问题，不是哪个模型最聪明。而是你能同时跑多少个、谁在检查它们的活、以及你的这套配置，今天有没有比昨天更锋利。

所以,如果你今天只带走一句话,我希望是这句：真正的杠杆,从来不在哪个模型更聪明,而在你能不能让一次运行留下点东西,让明天那群 Agent 比今天的更聪明。

模型没变。是你在它周围搭的那套系统,在一点点变厚。

大多数人读完这篇,还会继续把 Kimi 当聊天框用。少数人,会在这周就把这个循环搭起来。搭起来,核查它,蒸馏它,然后看着它每跑一次,都更便宜、更锋利一点。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
