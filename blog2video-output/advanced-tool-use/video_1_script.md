# Video 1: Claude 用工具的方式彻底变了！三招省下 85% 的 Token

[SLIDE 1: cover] (0:00 - 0:30)

你知道吗？一个 AI Agent 接上 GitHub、Slack、Sentry 这些常用工具，对话还没开始，光工具说明书就吃掉了十万个 Token。比它真正干活花的还多。

这里是 AI 精读。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Anthropic 官方开发者博客，关于 Advanced Tool Use 的最新实践。

[SLIDE 2: principle] (0:30 - 2:00)

很多人觉得，给 Agent 接的工具越多，它就越强。但现实是，工具一多，模型反而变笨了。

为什么？每个工具的定义和参数说明，都要塞进 Context Window，也就是上下文窗口。五个工具服务器的定义就要吃掉五万五千个 Token。再加上 Jira，直接突破十万。

你可以想象一下出差打包行李箱。箱子就这么大，说明书塞了百分之80，衣服就没地方放了。上下文窗口也一样，工具定义占满了，真正的对话内容就被挤没了。

Anthropic 的工程师测试发现，Opus 4 在工具过多时，选对工具的准确率只有百分之49。连一半都不到。

所以核心问题不是"怎么接更多工具"，而是"怎么让模型按需获取"。Anthropic 给出了三招。

[SLIDE 3: comparison_cards] (2:00 - 4:00)

第一招，Tool Search，工具按需搜索。

做法很简单。在工具定义里加一个 defer_loading: true 的标记。模型不再预先加载所有工具，而是需要时才搜索拉取。

效果非常炸裂。Token 消耗从七万七千直接降到八千七百，省了百分之85。Opus 4 的准确率从百分之49飙到百分之74，Opus 4.5 从百分之79.5升到百分之88.1。

这就像手机里的 App Store。你不会把所有 App 同时装满内存，需要哪个搜一下装一个就行。

第二招，Programmatic Tool Calling，程序化调用。

传统模式下，模型每调一次工具就做一次完整推理。一个任务连续调十几次工具，Token 像滚雪球一样越滚越大。程序化调用让模型写一段代码，在沙箱里批量执行，只把最终结果返回。Token 从四万三千多降到两万七千多，减少百分之37，同时消除了 19 次以上的推理传递。

第三招，Tool Use Examples，使用示例。

很多工具参数结构复杂，光靠定义文档，模型经常填错。给一到五个真实调用示例就行。准确率从百分之72直接拉到百分之90。

道理很简单。新员工入职，光给岗位说明书是不够的，得有前辈的实操案例才能上手。

[SLIDE 4: checklist] (4:00 - 4:40)

来一份实操清单。

第一，超过十个工具的项目，把低频工具标记为 defer_loading: true，开启 Tool Search。

第二，频繁连续调用、中间数据量大的场景，开启 Programmatic Calling，让模型用代码编排。

第三，参数经常填错的工具，补上一到五个真实示例。数量不用多，这个范围效果最好。

记住，三招可以叠加使用，不是非此即彼。

[SLIDE 5: summary] (4:40 - 5:00)

一句话总结：AI Agent 用工具，不是越多越好。按需加载、批量执行、示例教学，三招组合下去，省钱又提准。
