# Video 2: Claude Code组队实战：从启动到管理的完整攻略！

[SLIDE 1: cover] (0:00 - 0:25)

知道了 Agent Teams 很强，但具体怎么用？怎么分配任务？怎么避免队友打架？今天手把手教你从零搭建一个AI开发团队。

这里是 AI 精读。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Claude Code 官方文档中关于 Agent Teams 实战操作的部分。

[SLIDE 2: principle] (0:25 - 2:00)

首先，怎么启动？设置一个环境变量：CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS。在 settings.json 里加上，或者终端里 export 都行。

然后，直接用自然语言告诉 Claude："创建一个4人团队，重构这几个模块，每个队友用 Sonnet。" Claude 就会自动建团队、分任务、协调执行。不用写配置文件。

底层架构长什么样？想象一间办公室。Team Lead 是项目经理，坐在中间。每个 Teammate 是独立工位上的工程师。墙上有一块共享看板，就是 Shared Task List，所有人都能看到待办、领任务、标完成。工位之间还有即时通讯，就是 Mailbox，队友可以直接发消息讨论。

这里有个值得一提的细节。团队配置文件存在本地的 ~/.claude/teams/ 目录下，任务列表存在 ~/.claude/tasks/ 目录下。这意味着你可以直接打开文件看团队状态，甚至手动编辑任务列表来调试。

[SLIDE 3: comparison_cards] (2:00 - 4:00)

团队启动了，怎么看它们在干什么？这就涉及两种显示模式。

第一种叫 In-process 模式。所有队友都在你当前这一个终端里运行。用 Shift 加方向键下 来切换查看不同队友的工作状态。优点是什么终端都能用。缺点是同一时间只能看一个队友。

第二种叫 Split Panes 模式。像监控室的多屏幕墙一样，每个队友占一个独立窗口。你同时看到所有人的进度，点哪个窗口就跟哪个队友说话。但这个模式需要 tmux 或者 iTerm2 的支持。

默认是自动选择。如果你在 tmux 里，就用 Split Panes。否则就用 In-process。

再说控制操作。你可以要求队友提交方案先审批再动手。随时让某个队友关闭。任务完成后，让 Lead 说"清理团队"来统一收尾。

还有一个高阶功能：质量门禁。你可以通过 TeammateIdle Hook 和 TaskCompleted Hook 设置自动检查。就像工厂流水线上的质检环节，每完成一道工序，自动跑一轮检查。不合格就打回重做，确保最终产出的质量。

[SLIDE 4: checklist] (4:00 - 5:15)

现在来聊最佳实践。这些都是官方踩过坑之后总结出来的。

第一条，给队友充足的上下文。这一点最重要。队友不会继承 Team Lead 的对话历史。你跟 Lead 聊了半天的需求背景，队友一个字都看不到。所以分配任务时，必须把相关信息写清楚。

第二条，团队规模控制在三到五个人。太多了反而协调成本高，队友之间容易冲突。

第三条，每个队友分配五到六个任务。太少了浪费，太多了容易超负荷。

第四条，避免文件冲突。每个队友负责不同的文件。虽然有文件锁，但最好从源头避免两人改同一个文件。

第五条，先从调研任务开始。让队友先读代码、跑测试，熟悉环境再动手改。

最后说说当前的限制。不支持嵌套团队，你不能让一个队友再组建自己的小团队。每个会话只能有一个团队。Lead 角色一旦确定就不能换人。In-process 模式下队友断了不能恢复。知道这些，你就不会踩坑。

[SLIDE 5: summary] (5:15 - 6:00)

总结一下。Agent Teams 的核心心法就四句话。给队友充足上下文。控制团队在三到五人。合理拆分任务粒度。善用质量门禁。像管理真实团队一样管理AI团队。

你现在就可以做一件事。打开终端，设置 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 环境变量，用自然语言描述一个三人团队，亲自体验一次 Agent Teams。
