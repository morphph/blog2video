# 巨头今天抄走你的产品，用户凭什么留下？

[SLIDE 1: cover] (0:00 - 0:32)

Anthropic 的官方创业手册，把用 AI 白手起家这条路，从第一天，一直写到了终局。

今天，我们接着上一集，讲 Scale 阶段，规模化阶段。这也是这个系列的最后一集。

上一集的结尾，你手里已经有一台能自己运转的公司。这最后一关，要从几千个用户，走到上百万个用户。它要回答的，也是整套打法的最后一个问题：一家公司，怎么从一个赌注，变成一门真正的生意。

[SLIDE 2: principle] (0:32 - 0:45)

前四关，问的其实是同一件事：怎么活下来。想法是真的吗，产品配存在吗，生意配长大吗。

到了 Scale 这一关，问题第一次换了：怎么变得难以替代。

[SLIDE 3: quote] (0:45 - 0:55)

这一关，藏着全片最硬的一个拷问：如果一个资金雄厚的巨头，今天原封不动抄走你的产品，你的用户，会留下吗？

[SLIDE 4: image] (0:55 - 1:11)

过去每一关，增长都是你贴着用户、凭手感调出来的。现在不行了。从几千人到上百万人，从一个市场到很多个市场，你需要的是系统化的增长——一台不靠你的手感，也能持续运转的增长机器。

[SLIDE 5: principle] (1:11 - 1:54)

那"难以替代"从哪来？这里有全集最反直觉的一个判断：护城河，不是 Scale 阶段的新工程，它是回溯出来的。

你以为要从今天开始砌墙。其实砌墙的材料，前四关已经替你攒下了：你灌进产品里的领域专长，你和用户依赖的那些工具、平台之间的集成深度，以及只属于你的系统数据和工作流。

一直在一个方向上、一套基础设施上持续构建的人，此刻手里，第一次有了真正难以复制的东西。前四集里每一次忍住、每一份文档、每一个系统，都是在给这一刻攒本金。Scale 做的事，只是第一次把它们记成资产。

[SLIDE 6: checklist] (1:54 - 2:32)

再说这一关什么时候算通关。前几关的出口都是里程碑：拿到证据，拿到 PMF，增长可复制。这一关的出口，是一个门槛事件：公司离了你的日常运营，也能持续运转。

落到现实里，是三种形态之一：不再需要外部资本的持续盈利；具备公开上市的条件，也就是 IPO-ready；或者被收购。三种形态，要求是同一套：增长系统化、经得起审计，护城河扛得住审视，组织运营成熟。

当这些都成立，恭喜你——你的创业，从一个赌注，变成了一门生意。

[SLIDE 7: principle] (2:32 - 3:09)

但要走到那道门槛，先要过一道最难的关。它不是技术关，是心理关：把运营层，真的交出去。

上一集，你已经把系统建了起来。这一集的功课分两步：第一步，把这些系统养到完全可信；第二步，真的信它。卡住绝大多数创始人的，是第二步。

这道门还特别窄，两边都是失败模式。交得太多、太快——尤其是交给 AI 自动化系统——关键决策就会在缺少你独有背景信息的情况下被做出。抓得太久，你自己就是瓶颈。没有安全的默认选项。

[SLIDE 8: image] (3:09 - 3:38)

真正的功课，是把只活在你脑子里、没被写下来的机构知识，一条一条，编码成有文档、可审计、可转交的系统。

有个特别好用的自测：让 Claude 把所有经过你的工作流、决策、审批盘一遍，然后推演，你消失一周，每一条会怎样。会停摆的那些，就是交接没完成的地方。而日常事务的接管和自动化，可以直接交给 Claude Cowork 去跑。

[SLIDE 9: image] (3:38 - 4:09)

接下来说这一关的新税：外部审视。

公众投资人、分析师、监管机构、企业采购团队、潜在收购方，全都带着更高的怀疑入场。他们审的不止是产品能力，更是产品周围的组织：治理、合规姿态、财务控制，甚至你讲公司故事的方式。

大客户签多年合同之前，要看另一套东西：产品文档、支持手册，以及 SLA——白纸黑字的服务等级承诺，出了问题多久响应、多久恢复。

[SLIDE 10: image] (4:09 - 4:39)

好消息是，这套东西可以用建产品的方式建出来。Claude 起草和维护文档这一层；Claude Code 按企业标准加固代码，搭起日志、监控、事故响应，让 SLA 真正可执行；Claude Cowork 跑运营那一层：工单路由、续约追踪、报表节奏。

三层合起来，一个小团队，就有了一家大组织的支持姿态。这正是签合同前，要你证明的东西。

[SLIDE 11: checklist] (4:39 - 5:39)

增长这边，也有一堵墙在等你：有机增长的天花板。

靠创始人亲自卖、靠口碑、靠一次好时机的发布，能带你走很远，但走不到上百万用户。撞墙的信号有三个：用户曲线变平；获客成本上升；以及最扎心的一个——销售管道，只在你亲自介入的时候才动。

这时候，你需要一个真正的 GTM 引擎。GTM，go-to-market，就是把产品系统性推向市场的整套动作：市场怎么分层，故事怎么讲，卖给谁，怎么卖。绝大多数创始人从来没建过这些。但它不需要很大——建产品的那套 AI 基础设施，可以直接把它启动起来。

有个细节我特别喜欢。到了这个阶段，一段演示视频加一份销售材料，已经不够用了，企业买家要亲手做技术评估。所以要建一个真正能跑的 demo 环境——你在开董事会的时候，它在替你签单。

[SLIDE 12: comparison_cards] (5:39 - 5:52)

最后，回到护城河本身。大多数人把护城河当一个词用，其实它是两种方向相反的力：第一种让你难被复制，第二种让你难被离开。混为一谈，就会漏掉一半。

[SLIDE 13: image] (5:52 - 6:48)

先说难被复制。第一种原料，是领域知识。把你知道的一切——行业黑话、监管的坑、边缘情况、为什么显而易见的方案行不通——持续灌给 Claude，放进产品够得着的地方。

再用 Skills，也就是可复用的技能包，把重复的领域流程固化成每次都以同样方式执行的例程，比如"怎么审一份商业租约"。几个月积累下来，这会变成一层通用 AI 追不上的专有知识底座。

它会直接变成产品逻辑。举个例子：美国有一类编号叫三四零B的特殊药品折扣项目，通用的 AI 医疗计费工具，处理这类理赔会直接出错——而你的产品，为它写了专门的逻辑。

每撞到一个通用竞品必错的边缘情况，就加一条基于真实场景的测试。日积月累，你的测试套件，就是一张护城河地图。

[SLIDE 14: image] (6:48 - 7:45)

第二种原料，是用户数据。用户每天在你产品里接受什么、拒绝什么，这些行为信号回流成产品改进，改进带来更多使用，使用又产生更多信号——飞轮就转起来了。几千个用户在你产品里打磨出来的行为指纹，锁死在时间里，竞争对手花钱也买不到。

有个练习值得做：让 Claude 基于你的数据，起草一页护城河叙事——你的飞轮怎么转、转了多久，以及为什么一个资源充足的对手今天从零开始，两年之内也复制不了。这一页纸，就是你面对巨头拷问时的答案。

真实的样本已经有了。Carta Healthcare 用 Claude 驱动临床数据抽取平台，一年处理两万两千例手术病例，数据抽取时间省了百分之六十六。这种深度，不是从天上掉下来的，是一路攒出来的。

[SLIDE 15: image] (7:45 - 8:36)

第二种力，方向完全相反：不是挡对手进来，是抬高用户离开的成本。

用户在你的产品上跑得越久，它就嵌得越深。他们在上面搭了自动化，训练了团队，接上了自己的数据源。他们打磨的提示词、固化的流程、标准化的输出，全是围绕着你的产品成形的。到这一步，换掉你，就不再是一个产品决策，而是一场全公司的运营工程。

建设动作也和第一种力完全不同：铺集成的表面积。用 Claude Code 快速接上用户依赖的数据管道和工具；再往深一步，建好 API、webhook 这些接口，配上 SDK 开发工具包，让客户不只是使用你的产品，而是在你的产品之上，构建他们自己的东西。这是最深的一种绑定。

[SLIDE 16: comparison_cards] (8:36 - 9:11)

照例，代价也要说清楚。

第一，交接的窄门是真实的，机构知识的编码是持续的苦工，不是一次性动作。就算你天生擅长授权，什么该交、什么该留，也从来不是显而易见的。

第二，外部审视躲不掉。走到这一关，你的角色会从造东西的人，变成一个面向公众的高管：给分析师做简报，跑上市路演。这些活，几乎没有一样是建造者天生喜欢的。但三种通关形态，全都要求它们过关。精益的结构可以保住，这笔税，省不掉。

[SLIDE 17: summary] (9:11 - 10:17)

最后，把这五集收拢在一起。

Idea 阶段，不见证据不动工。MVP 阶段，速度免费之后，判断力是唯一稀缺的东西。Launch 阶段，找到 PMF 是产品问题，守住它是组织问题。Scale 阶段，公司离了你也能转，创业从一个赌注，变成一门生意。

四关走完，你会发现 AI 改变的是同一件事：它把季度压成了周。验证，从几个月变成几个下午；原型，不再需要一个技术栈对口的联合创始人；发布，从赛前冲刺变成日常工作流；连规模化的运营重量，也能交出去了。

创始人的工作没有变：找到一个真问题，做出解决它的东西，再把它做成一家有分量的公司。变的是路。当造东西这件事不再稀缺，瓶颈就不再是你能造什么，而是你选择造什么。
