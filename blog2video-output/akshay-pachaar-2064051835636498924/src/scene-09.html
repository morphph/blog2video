// 三件事串起来 · 循环闭合
回路闭合的样子
01
一行装饰器埋点,声明配置
02
生产环境出故障
03
编程 Agent Ollie 读 trace + 源码,定位根因
走遍整张 span 树 → 给你一份 diff
04
你批准 —— 唯一的手动步骤
没批准不改代码、不动 git;人 = 吞吐瓶颈
05
用原始输入重跑,新旧 trace 并排对比
06
通过 → 修复存下,失败锁成回归测试
↑ 下一个失败,进入同一个循环
把这三件事串起来,循环就闭合了。
一行装饰器把 Agent 埋上点,声明一下配置。
生产环境出故障。
一个内置的编程 Agent——在 Opik 里它叫 Ollie——读 trace、读你的源码,走遍整张 span 树,定位根因,给你一份 diff。
注意,整条路径里只有一个手动步骤:你批准。
没有你的显式批准,它不改任何代码,不动你的 git。
这一步既是安全闸,也意味着这个回路并非全自动——规模化的时候,人就是那个吞吐瓶颈。
这是个真实的取舍,不是缺点也不是噱头。
你一批准,它就用原始失败 trace 里一模一样的输入,把 Agent 重跑一遍,把新 trace 流式推给你做并排对比。
通过了,这个修复就存下来,原始那个失败,被锁成一条回归测试。
然后,下一个失败,进入同一个循环。
