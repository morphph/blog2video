# Video 1: Claude 有 17 个开关，你开了几个？

[SLIDE 1: cover] (0:00 - 0:30)

你用的 Claude，可能是全网最弱的那一版。不是模型不行，是它身上一大半开关你从来没打开过。X 上有一篇 260 万阅读的长文，作者叫 Anatoli Kopadze，把 Claude 藏在各个角落的 17 个功能列了一遍。今天不聊每一个怎么配——只聊一件事：为什么这篇文章被收藏了四千七百次，但只点了九百个赞。

[SLIDE 2: principle] (0:30 - 1:45)

我第一眼看这篇文章的统计就觉得不对劲。260 万人看过，4751 个人点了收藏，但只有 990 个人点了赞。收藏比点赞高五倍。这个比例在内容平台上是有含义的。点赞是"我喜欢"，收藏是"我以后要做"。一篇高收藏低点赞的清单文，翻译过来就是：大家把它当作待办事项存了起来，然后再也没打开过。

而文章本身从头到尾在说同一句话。第一节讲 Projects，作者说"如果你还没用过 Projects，这是这篇文章里你最该先去开的"。第三节讲 Adaptive Thinking，作者说"大多数 Claude 用户从来没把这个打开过"。第四节讲 Memory，作者直接写："默认是关的，大多数人不知道它存在。"

你品一下。一个产品有 17 个功能，作者却要在每一段都写一句"大多数人没开"——这不是写文章，这是写控诉。

[SLIDE 3: image] (1:45 - 4:00)

我把这 17 个功能挑了几个有反差感最强的来讲。

第一类是认知层面的反差。很多人觉得 Claude 这种 AI 一打开就是一张白纸，每次重新介绍自己，每次重新解释项目背景。这个状态在产品里有专门的修复方案，叫 Projects。你建一个 project，把你的文档传进去，把"我是谁、我在做什么、回答时该注意什么"写在 instructions 里——之后你打开这个 project，Claude 就像一个跟了你半年的同事，背景知识不用再讲。

顺带说一句，很多人还以为 Claude 只能产文字，不会做出能跑的东西。这也是错的。Artifacts 这个功能在免费版就能用，你让它做一个习惯打卡的小网页、一个互动的图表、一个流程图——它直接在对话边上开一个面板，渲染一个能点能用的真东西。作者那句话很扎心："免费版就能用，但大多数人从来没试过。"

但 Memory 比 Projects 更进一步。Memory 是跨 project 的人物画像。你跟 Claude 聊得越多，它记住的越多——你的工作、你在做什么项目、你喜欢什么沟通风格。下次开一个全新的 chat，它已经知道你是谁。

这两个东西不是新功能，已经在产品里很久了。Memory 默认就是关的。Projects 大多数人从来没建过。所以你每天打开 Claude 重新自我介绍——不是 Claude 没本事，是你用的这个版本，记忆开关没打。

[SLIDE 4: image] (4:00 - 5:05)

再往下还有一个 Adaptive Thinking，也叫扩展思考模式。打开之后，Claude 会先一步一步把思路推一遍，再给你答案。整个推理过程你能看到。简单问题不用开。但只要遇到要做权衡、要做判断的问题——比如两个 offer 怎么选、一个项目要不要砍——开和不开的差距非常明显。作者写得很直接："大多数 Claude 用户从来没把这个打开过。"你下次面对一个真正难选的事，把同一个问题问两遍——开 thinking 一遍，不开一遍——自己对比。

[SLIDE 5: principle] (5:05 - 7:00)

第二类是输出层面的反差。很多人吐槽 Claude 给的答案太软、太正确、太"五条建议"。文章里 5 到 9 号，五个 prompt，全部解决这个问题。逻辑是同一个：给 Claude 一个具体的角色。

比如第 6 号叫 the hard mentor，毒舌导师。原文那段 prompt 大概意思是：你是一个建过公司又失败过的老板，你见过一百个人犯一样的错。你的工作不是鼓励我，是在我做出贵的决定之前提醒我盲点在哪。挂上这段 prompt 之后，你描述一个想法，它不会再说"听起来不错"，它会一条一条挑你的漏洞。

第 9 号叫 devil's advocate。你告诉 Claude 你已经做了一个决定，让它专门给你做反方辩护——三个最现实的失败路径，最被低估的风险，最不愿意面对的假设。这种 prompt 的有效性，作者总结得很到位：默认的 Claude 会找你想法里的优点来支撑你；但你给它"魔鬼代言人"的角色之后，它就只剩攻击你。五分钟的攻击，可能比你自己反复纠结一周都管用。

还有第 8 号是难对话陪练。你跟 Claude 描述对方的性格、你想说什么、为什么难——Claude 直接扮演那个人。你说弱的话，它会反驳你。结束以后再跳出角色给你做一个复盘。我自己试过一次，那种"你不是在被安慰、你是在被对面打"的真实感，比反复在脑子里演练有用得多。

我说一个很反直觉的判断。你给 Claude 换一个更强的模型，它的回答可能没什么变化。但你给它一段"你是个毒舌导师"的 system prompt，它立刻翻脸。这两件事的杠杆完全不在一个量级。大多数人花精力在等下一代模型，但其实你眼前这一代模型的 90% 的能力，都被一个软绵绵的默认人格挡住了。

[SLIDE 6: image] (7:00 - 9:05)

第三类是产品层面的反差。很多人对 Claude 的印象还停留在"网页里那个聊天框"。但作者列了三个完全不在聊天框里的东西。

Claude in Chrome 是一个浏览器扩展。装上以后，Claude 能看你当前打开的那个 tab，能点链接、能填表单、能跳 URL。文章里给的例子是：我现在在一个招聘列表页，你帮我把所有职位的标题、公司、薪资范围、前三个要求抓出来，按薪资排序做成表格——多页就翻到下一页继续。

Claude Cowork 是一个桌面 app。桌面 app 的意思是，它直接读你电脑里的文件。不用复制粘贴。它能看你的文件、改你的文档、新建文件、整理文件夹。

Scheduled Tasks 是定时任务。你只配置一次，Claude 在你设定的时间自动跑——每周一早上 7:30 把过去 24 小时的 AI 和加密新闻挑五条最重要的，写两句摘要，存到你 briefs 文件夹里。你睡觉的时候它已经在干活了。

这三个东西很多人完全不知道。但它们已经发布，已经能用。

我要在这里加一个 tradeoff，不只讲爽点。这三个产品分别是浏览器扩展、桌面 app、和需要在 Cowork 里配置的定时任务——你想全部用上，得跨三四个不同的产品环境去装去登录去配置。文章那句"几分钟就能搞定"对技术用户成立，对非技术用户其实是一个不小的认知成本。所以不要一次性全开，挑一个你这周真的会用的，先把那一个跑起来。

[SLIDE 7: image] (9:05 - 10:10)

文章里第 16 节最让我意外。作者写："大多数人都不知道这个产品存在。"

这个产品叫 Claude Design。是 Anthropic Labs 单独做的一个工具，专门做视觉类的东西——产品的一页纸介绍、pitch deck、原型图、落地页布局。你描述你想要什么，Claude 直接给你做出来，可以导出 PPTX、Canva、PDF 或 HTML。访问地址就是 claude.ai/design。

我自己也是看这篇文章才知道。一个能把三小时 Figma 工作压缩到十分钟对话的产品，连入口都不需要登录跳转，直接打那个 URL 就行。但这个产品就是没什么人知道。

这就是我说"Claude 是被低估的"的真正含义。低估不是说它的能力被低估，是说它已经做出来的产品，连存在感都没建立起来。

[SLIDE 8: principle] (10:10 - 11:25)

最后一类是给做事的人准备的。如果你已经在用 Cowork 或 Claude Code，文章里第 13 和第 14 是两个最值钱的开关。

第 14 节讲 CLAUDE.md。你在你的项目文件夹里建一个叫 CLAUDE.md 的文件，里面写你的规矩——代码风格、写作风格、不能用的词、文件该放哪。每次 Claude 启动这个项目，自动读一遍。不用你提醒。规矩写一次，全部 session 永久生效。

第 13 节讲 Cowork 里的 Skills。Skills 是预先打包好的能力。比如你装一个做 PowerPoint 的 skill，Claude 就自动知道怎么生成 ppt。装一个处理 PDF 的 skill，它就会按那个工作流去做。作者的比喻是：手机本身是好用的，装了 app 之后它能做的事多得多。

这两个东西的共同点是：它们是配置文件，不是聊天指令。你不需要每次都提醒 Claude "记得短段落"、"记得不要用 delve 这个词"——你写一次进文件，永远生效。

[SLIDE 9: image] (11:25 - 12:15)

文章最后一节是给 API 开发者的。叫 Prompt Caching。

如果你的 API 请求里每次都带着一段巨大的、不变的上下文——一段长 system prompt、一份参考文档、一段 codebase——你每次调用都在为重新处理这些 token 付钱。Prompt Caching 把这段内容缓存到服务端，下一次命中就只算便宜价。缓存命中的 token 最高省 90%。响应速度还更快。

启用方式就是一行配置：在你想缓存的 content block 加上 cache_control 字段。缓存 5 分钟过期，每次命中刷新计时。

这个功能很多大规模在调 API 的人都还没接。一行字段，账单立刻减一大块。

[SLIDE 10: quote] (12:15 - 14:15)

我从头看完这篇文章，最后一段就一句话："你现在比每天用 Claude 的大多数人，都更懂它。"

听起来像鸡汤，但你想想前面那 17 节——每一节作者都在重复同一句话："默认是关的"、"大多数人没开"、"大多数人不知道这个产品存在"。

所以这篇文章真正讲的不是"Claude 有什么"，是"为什么大多数人用的那个 Claude，是出厂最弱配置的那一版"。能力差距不是瓶颈。配置差距才是。

这是一个很常见的模式。一个工具的能力上限，是工程师写出来的；但一个工具的实际能力，是用户开了几个开关决定的。你看那 17 项里，几乎一半都有一个明确的 toggle 或一个明确的入口——Memory 那个开关、Projects 那个新建按钮、Adaptive Thinking 那个图标、claude.ai/design 那个网址。每一个 toggle 没点开，对应的能力就当作不存在。

我们这两个月聊了一堆 Claude Code 内部架构、Harness 工程、Agent 怎么协同、prompt 怎么分层。这些视频是给搭东西的人看的。但今天这一期是反过来的——对绝大多数只是在用 Claude 的人来说，瓶颈根本不在那些花哨架构上。瓶颈在你有没有去点开"启用 Memory"那个 toggle，有没有去 claude.ai/design 那个网址看一眼，有没有给你的项目建一个 CLAUDE.md。

收藏 4751 次、点赞 990 次——那 4751 个人里，大概率有一大半到今天还没真的去开过一个开关。我希望你不要也是。

[SLIDE 11: summary] (14:15 - 14:40)

挑一个。就一个。不要全部。今天就去开。Memory 也行，Projects 也行，给 Claude 写一段毒舌导师的 system prompt 也行。最不济，把 claude.ai/design 这个网址收藏起来下次试一试。

知道它存在，已经是一半。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
