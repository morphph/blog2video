// LAYER 2 · 重要但偶尔才用
整理好的英文文档

不能什么都塞进 L1 — 每样都表面积大,只偶尔用
条件格式 数据透视表 图表 数据校验 复制移动
$ getPivotTableInfo()# 一句调用拉进文档
›
批量改动用 suspendLayout / resumeLayout 包住 — 否则每改一次整张表重建
›
聚合方式传裸整数 8 = sum — 友好枚举运行时不存在
零 token 直到任务需要它 — 一句调用 = 一次 cache miss
但你不可能把所有东西都塞进 L1。
像条件格式、数据透视表、图表、数据校验、复制移动这些操作，每一样都重要，每次会话里都会冒出来那么几次，但每一样又都有足够多的细节，
要是全写进系统提示词，就会拖累所有用不到它的任务。
这就是典型的第二层，L2。
他们的做法，是把这些能力写成一份份整理好的英文规范，按需才取，就跟 skill 文档一模一样。
模型在自己写的代码里调一句，就能把对应的文档拉进来。
但注意，这些不是把函数签名堆在一起的类型说明。
它们是手写的散文，每份几百行，讲的是把一件事做对的那条正确路子，包括那些原始 API 永远不会告诉你的知识。
拿数据透视表那份规范来说。
它不只是列方法，它是按正确的顺序，把整套配方教给你。
它会告诉你一些你本来只能靠反复栽跟头才学得到的事：比如你必须用一对挂起和恢复布局的命令，把这一批改动包住，否则每改一次，整张表就重建一次；再比如，
聚合方式得传一个裸整数进去——比如8代表求和——因为运行时根本就没有那个友好的枚举值给你用。
这些都不是什么古怪的坑，这就是把透视表做对，本来该有的样子，只不过被一个已经替你踩过坑的人，提前写下来了一次。
而它最妙的性质是：在任务真正需要它之前，它一个 token 都不花。
一个从不碰透视表的任务，永远不必为透视表的文档买单。
调一句话，就是它全部的发现成本——一次缓存未命中，很快就被服务掉了。
