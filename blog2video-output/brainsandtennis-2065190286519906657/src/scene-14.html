值得看一眼 token 到底花在哪了，因为这套分层会直接体现在系统提示词的形状上。
提示词的主体是 L1，量级大概是几百行——核心读写操作、execute_code 的约定、关键的几个类型、还有几乎每个任务都会用到的那一小撮方法，外加执行和安全准则。
这部分每次调用都常驻，所以也是他们拼了命要压紧的地方。
L2 是叠在上面薄薄一层，大概五十行。
注意，这五十行不是规范本身,而是一份"祝福过"的方法白名单,加上几个指针——告诉 Agent 那些文档存在、什么时候该去取。
规范的实际内容，在被调出来之前，根本不进提示词。
L3 基本就五行——那份 skill 文档的名字和描述，外加散落别处的一些参考指引。
而那份七万行的原始参考，整个躺在磁盘上,永远不碰提示词。
所以你看，整个预算，正好镜像了那条频率曲线：绝大部分提示词花在百分之80的常用场景上,一点点用来给那百分之15立路标,几乎没有花在长尾上。
这恰恰就是缓存分层那套框架，一开始就预言的分配方式。
