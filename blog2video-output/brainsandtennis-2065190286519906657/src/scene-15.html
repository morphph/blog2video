表格只是他的例子。
这套结构,能迁移到任何领域。
那些系统提示词、那些整理好的规范里的压缩,本质上是在编码你的用户、以及他们要做的任务的分布——而在你自己的领域里,这个分布,你比任何人都懂。
所以你的活儿,就是回答三个问题。
第一,什么东西包进 L1?
是频率曲线最陡那一段、最家常的操作。
把它们做到 token 效率极致、速度极快,还要会汇报后果。
在这儿砸不成比例的功夫,因为 Agent 每个任务都在付这个代价。
第二,什么东西推到 L2?
是那些重要但偶尔才用的能力。
把它们写成整理好的、英文的、带着各种坑的提醒的规范,一步就能取到。
编码进去的是那条正确路子和各种约束,而不只是函数签名。
第三,你的逃生舱 L3 是什么?
是那份原始的、完整的底层素材,再加一份教 Agent 去挖它的 skill。
它不需要好用,它只需要能到达、足够完整、并且能在有限步数内被找到。
这三个位置放对了,你就造出了一个在常用场景上飞快、在偶发场景上够用、在罕见场景上也永远卡不死的 Agent——同时还把上下文保持得足够小,让模型一直保持锋利。
