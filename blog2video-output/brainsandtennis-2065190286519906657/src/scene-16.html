// 更大的窗口诱人多塞;更好的本能是 CPU 几十年前定的那套
摘要进缓存 · 细节按需 · 原始底座留作最后一招
最后一个观察,我觉得是全篇最值得记住的判断。
什么东西算 L1,并不是固定的,它会随着模型变强而漂移。
早年那些弱模型,需要小小的、单一用途的工具,每件事都得给它掰开揉碎。
今天的模型,能一口吞下一份更大的 L2 规范,能直接在更多的 L3 原始细节上推理而不噎住。
所以随着模型变强,昨天的 L3 会变成明天的 L2,昨天的 L2 会塌进 L1。
Agent 的责任范围向外扩张,整个层级,往下滑一级。
但你可能会觉得——模型越强、上下文窗口越大,这套分层的脚手架不就该被淘汰了吗?
恰恰相反。
分层本身,永远不会消失。
因为相对于"你能往里塞的一切",上下文永远是稀缺的;而噪声,永远在扣你的准确率。
没有哪个模型大到,能让"在对的时间、把对的东西、放到它面前"这件事,不再重要。
更大的上下文窗口,总在诱惑人们往里贴更多东西。
但更好的本能,是 CPU 几十年前就想明白的那一个:摘要放缓存,细节按需取,原始素材留作最后一招。
把你 Agent 的上下文,造得像一套内存分层。
准确率,自然就跟上来了。
