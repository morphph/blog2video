顺着这个思路，文章问了下一个问题。
框架要不要用？
市面上框架不少。
Anthropic 自己的 Agent SDK，AWS 的 Strands，还有 Rivet、Vellum。
它们的好处很明确。
帮你把调用模型、定义解析工具、串联调用这些底层脏活累活包起来，让你快速起步。
但代价也很实在。
框架会多出一层抽象，把底层真正发给模型的 prompt 和模型的响应给挡住了。
出了问题你很难 debug。
而且它会诱惑你，在其实更简单就够用的时候，忍不住去加复杂度。
文章给的建议很直接。
先直接调 LLM 的 API，很多模式几行代码就实现了。
真要用框架，也一定要搞懂底层在干什么。
对引擎盖下面发生的事情做错误假设，是客户出错最常见的来源。
