# Video 1: Claude官方教你造"技能包"：再也不用重复教AI做事了！

[SLIDE 1: cover] (0:00 - 0:30)

你有没有这种体验：每次打开 Claude，都要重新解释一遍你的代码风格、文档格式、工作流程。说白了，就是每次都在"重新培训"同一个助手。现在 Claude 官方给出了解法。

这里是 AI 精读。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Anthropic 官方发布的 Claude Skills 构建完全指南。

[SLIDE 2: principle] (0:30 - 2:30)

这份指南开头就说了一句话，很有意思：与其每次对话都重新教 Claude，不如教它一次，然后永远受益。

怎么做到的？答案就是 Skill。

Skill 是什么？说出来你可能不信。它本质上就是一个文件夹，里面放一个叫 SKILL.md 的 Markdown 文件。没有 SDK，没有编译，没有部署。官方说，十五到三十分钟就能从零建好一个可用的 Skill。

打个比方。你是一个团队负责人，来了一个新员工，你会怎么做？口头讲一遍流程？下次再来一个新人，你还得再讲一遍。聪明的做法是什么？写一份入职手册。新人来了直接看手册，不用你每次口头教。

Skill 就是你给 Claude 写的"入职手册"。

你把工作流程、偏好设定、领域知识写进去，Claude 读一次就记住了。下次再遇到类似任务，它自动按照你的规范来。而且，同一个 Skill 可以在 Claude.ai、Claude Code 和 API 三个平台通用。写一次，到处能用。

[SLIDE 3: comparison_cards] (2:30 - 4:30)

那 Skill 的文件夹里到底放什么？

核心只有一个必选项：SKILL.md。这个文件分两部分。顶部是 YAML frontmatter，写上 Skill 的名称和描述。下面是 Markdown 正文，写具体的指令和工作流。

除此之外，还有三个可选目录。scripts 放可执行脚本，比如 Python 或 Bash。references 放参考文档，按需加载。assets 放模板、字体、图标这些素材。

但这里最精妙的设计，是它的三层渐进式加载机制。

你可以把它想象成一个餐厅的菜单系统。第一层是门口的招牌，写着"川菜馆，招牌菜麻婆豆腐"。这就是 YAML frontmatter，永远会被加载到 Claude 的系统提示里。Claude 靠这个来判断：这个 Skill 跟当前任务有没有关系。

第二层是你坐下来之后拿到的完整菜单。这就是 SKILL.md 的正文内容。只有当 Claude 判断这个 Skill 跟你当前的任务相关时，才会加载这部分。

第三层是问厨师推荐。这就是 Skill 文件夹里的其他文件。只有在 Claude 需要更深入的信息时，才会主动去查阅。

为什么要这么设计？因为 Token 是有成本的。如果每次对话都把所有 Skill 的全部内容塞进去，那上下文窗口很快就爆了。渐进式加载，按需取用，既省 Token 又不丢专业能力。

[SLIDE 4: checklist] (4:30 - 5:30)

那什么样的任务适合做成 Skill？你可以对照这三个信号。

信号一：你发现自己每次跟 Claude 对话都在重复同一段提示词。比如每次都要说"用 TypeScript，不要用 any 类型，文件名用 kebab-case"。这种重复性的偏好设定，非常适合写成 Skill。

信号二：你有一套固定的工作流程。比如"先从设计稿提取颜色，再生成组件代码，最后跑一遍测试"。这种多步骤的工作流编排，正是 Skill 擅长的。

信号三：你的团队里不同人用 Claude 的效果参差不齐。有人写的提示词效果好，有人写的不行。Skill 可以把最佳实践固化下来，让全团队的 Claude 使用水平拉齐。

[SLIDE 5: summary] (5:30 - 6:00)

总结一下。Skill 就是给 Claude 写的"工作手册"。一个文件夹，一个 SKILL.md，就能让 Claude 永久记住你的工作流。三层加载保证效率，三端通用保证灵活。

你现在就可以试试：在电脑上建一个文件夹，放一个 SKILL.md 文件。顶部用 YAML 写上名称和描述，正文把你最常重复给 Claude 讲的工作流写进去。十五分钟搞定。
