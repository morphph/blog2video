# Video 3: MCP+Skill组合拳：让Claude从"能连"变成"会用"！

[SLIDE 1: cover] (0:00 - 0:40)

你的 MCP 连上了 Notion、Linear、Sentry。然后呢？用户的反馈是什么？不是"好厉害"，而是提 support ticket 问："怎么用你的集成做 X？"每次对话都从零开始，用户还觉得是你的连接器不好用。

这里是 AI 精读。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们继续精读 Anthropic 的 Skill 构建指南，聊聊 MCP 和 Skill 到底怎么配合。

[SLIDE 2: principle] (0:40 - 2:20)

很多做 MCP 集成的人没意识到一个问题。MCP 解决的是连接：Claude 能做什么。但连上了不等于会用。

打个比方。MCP 是给你一个专业厨房，炉灶、烤箱、食材全都有。但一个没做过菜的人走进去，面对满冰箱的食材，根本不知道先拿什么、怎么配。

Skill 就是菜谱。第一步做什么，第二步做什么，什么情况下换方案。

没有 Skill 会怎样？用户连上工具，不知道下一步该做什么。每次对话都从头开始，效果参差不齐。用户觉得是你的 MCP 不行，但真正缺的是工作流引导。

加上 Skill 呢？预设的工作流自动激活，执行结果一致，最佳实践内嵌在每次交互里。

[SLIDE 3: comparison_cards] (2:20 - 5:00)

那 Skill 加持 MCP，具体有哪些玩法？官方总结了五大模式，我挑最实用的三个讲。

第一个，顺序工作流编排。适合固定流程的场景。比如新客户入驻：创建账户、配置支付、开通订阅、发欢迎邮件。没有 Skill，用户得一步步手动告诉 Claude 下一步做什么。有了 Skill，自动按顺序执行，一气呵成。

第二个，多 MCP 协调。想象设计到开发的交接流程：Figma MCP 导出设计稿，Drive MCP 存储素材，Linear MCP 创建任务，Slack MCP 通知团队。四个 MCP 协同工作，Skill 就是项目经理的 SOP 手册，把跨平台流程串成一条线。

第三个，上下文感知工具选择。同一个需求，不同条件用不同工具。大文件走云存储 MCP，协作文档走 Notion MCP，代码走 GitHub MCP。Skill 帮 Claude 判断当前该调哪个。

另外两个模式也值得关注：迭代优化，适合报告生成这种需要反复打磨的场景。领域专业知识，比如金融合规检查，Skill 提供超越工具本身的判断力。

[SLIDE 4: checklist] (5:00 - 6:00)

来看一个真实案例。Sentry 做了一个 sentry-code-review 的 Skill。功能是自动分析 GitHub PR 里 Sentry 检测到的 Bug，给出修复建议。

Sentry MCP 提供错误数据，GitHub MCP 提供代码变更，Skill 把两者串起来，形成完整的代码审查流程。这就是多 MCP 协调模式的典型应用。

官方还给了一个调试技巧：对于关键验证，用脚本而不是语言指令。比如检查文件是否存在，别让 Claude 用自然语言判断，写个脚本跑一下就行。代码是确定性的，语言理解不是。

[SLIDE 5: quote] (6:00 - 6:30)

而且 Skill 不只是个人工具。它是一个开放标准，像 USB 接口一样。一次构建，到处能用。

目前有三种分发方式。个人用户可以打包上传到 Claude.ai 的 Settings 里。组织管理员可以在工作区统一部署，这个功能 2025 年 12 月 18 日已经上线了。开发者还可以通过 Skills API 编程接入，配合 Claude Agent SDK 构建自定义 Agent。

[SLIDE 6: summary] (6:30 - 7:00)

总结一下。MCP 让 Claude 连得上工具，Skill 让 Claude 用得好工具。做 MCP 集成的人，不配套 Skill，等于只建了厨房没写菜谱。

你现在就可以做一件事：选你用得最多的一个 MCP 集成，比如 Notion 或 Linear。把你每次都要手动告诉 Claude 的使用步骤，写成一个 Skill，放到 Settings 里的 Capabilities 下面。
