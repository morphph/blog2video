# 让 Codex 自己跑 3 天，靠的不是模型

## Hook

OpenAI 的 Codex 最近上线了一个新命令，叫 /goal。你给它一个目标，它能自己连续跑几个小时，甚至几天。作者 Chris Hayduk 是 OpenAI 内部做蛋白质结构搜索的 FDE，他真用这个模式跑过几天的科研任务。今天不聊 /goal 怎么用——只聊一个反直觉的发现：Agent 能不能跑这么久，瓶颈根本不在模型。

## Goal 模式的本质是一个循环

先说清楚 /goal 到底在做什么。它本质上就是一个循环。Agent 执行一个动作，给这个动作打分，判断分数有没有达到你设定的目标。没达到，继续。达到了，停。

听起来很简单对吧？但作者说，正因为它是一个循环，整套机制能不能跑下去，完全取决于循环里最不起眼的那一步——判断是否完成。

模型负责执行，模型负责打分，但**何时算结束**这个判断，是你给的。你没给清楚，整个循环就崩了。

## 模糊目标会出现两种相反的故障

过去这半年模型变得太聪明，我们都被宠坏了。日常聊天的时候，你随便说一句"帮我把这段代码改好一点"，GPT-5.5 都能猜得八九不离十。

但这种偷懒的提示风格，到了 /goal 模式里就是灾难。

作者观察到两种相反但同源的故障。第一种，模型工作几分钟就放弃了，因为它判断不出来什么叫"更好"，干脆就觉得"差不多了"。第二种更可怕，模型永远停不下来，盲目乱改，因为目标本身就无法满足。

你看，同一个模糊指令，可以让 Agent 早退，也可以让 Agent 死循环。差别只在它当时怎么解释那个模糊。

## 一个好目标长什么样

作者给了一个非常具体的对照。

坏目标：让这段代码变得更好。

好目标：把某个具体文件里代码的运行时间降低百分之20，同时不能让现有的单元测试和集成测试出现任何回归。

差别在哪？好目标里有一个明确的量化数字——百分之20。还有一组明确的约束——测试不能挂。Agent 拿到这种目标，每跑一轮都能精确算出"我离终点还差多少"。循环就能正常闭合。

## 把质性目标拆成 checklist

但很多任务你没法直接量化。比如作者举的一个真实例子——把一篇 NeurIPS 投稿改成 ICML 的格式。

ICML 的格式规则保存在一个 LaTeX 文件里，又长又乱，根本没法直接对照打分。作者的做法很聪明。他先让 Codex 读完这个 LaTeX 文件，提取出一份 markdown 格式的 checklist——总共超过 200 条格式和风格规则。

然后真正的 /goal 指令变成了：根据这份 checklist，把论文改成 ICML 格式，不要动技术内容。

Agent 的完成判断也变得极其简单：当 200 条规则全部打勾时，任务完成。

这里有一个非常关键的洞察。每一条规则其实本身可能还是模糊的，但模型对"单条规则是否完成"的判断力，远远强于对"整体目标是否完成"的判断力。把一个大目标切成 200 个小判断，整体的终止判断质量反而暴涨了。

而且作者还要求模型每完成一条就在文件里打勾。状态写到硬盘上，他自己也能随时刷一眼，看 Agent 进度到哪了。

## 反馈循环必须够快

第二件事，反馈循环的速度。

Agent 要打分，就得运行某种测试。这个测试跑得越快，Agent 拿到反馈越快，整个循环就越能高速转动。

作者举了自己的真实场景。他在搜索更好的蛋白质结构预测模型架构。如果每次都用完整的训练集来评估一个新架构，一轮要跑好几天。Agent 根本没法迭代。

他的解决方法是用一个叫 NanoFold 的数据集。这是他自己公开发布的、小但采样很好的数据集。再配上小一号的模型。单次评估时间从几天压缩到几分钟。

这里藏着一个反直觉的工程判断。你可能会想，用小数据集小模型评估出来的结论，怎么能保证可靠？作者的回答是：在架构搜索这个阶段，方向性信号已经够了。**循环速度带来的回报，远远大于评估保真度的损失。**

这是一种故意的、有意识的降保真。当然它有边界——如果你正在做的优化对规模特别敏感，小数据集上有效的方向迁移到大数据集不一定还有效。但在大多数早期探索阶段，速度优先是对的。

## 让 Agent 把记忆写在硬盘上

最后一件事，也是我读完最受启发的一件事。

Codex 自带很强的上下文压缩能力。但作者直接说，即便有这种 compaction，让模型在几天的任务里维持连贯，依然非常难。

他的解法不是去优化上下文窗口，而是干脆把记忆搬出模型，放到文件系统里。

他给 Agent 准备三个 markdown 文件。

第一个叫 PLAN.md，记录高层计划。你可以提前在里面写几条初步思路，给 Agent 一个起点。

第二个叫 EXPERIMENTS.md，记录每一次实验的标题、做了什么、结果是什么。这是一份策展过的、干净的清单。

第三个叫 EXPERIMENT_NOTES.md，是 Agent 的草稿本。按时间顺序写它实时的思考流，你可以翻它来审计 Agent 走没走偏。

三个文件里，作者明确说 EXPERIMENTS.md 最重要。为什么？因为 Agent 真正需要的不是"下一步做什么"，而是"之前哪些尝试失败了、为什么失败"。失败的记忆比计划更值钱。

我看到这里很受触动。我们一直在讨论怎么让模型记得更多、上下文窗口更大、压缩算法更好。但作者直接绕过了这条路。他说：**模型记不住没关系，让它把记忆写在硬盘上。**

## Synthesis

回过头看，作者讲的三件事其实是同一件事——你在为 Agent 搭一个可以闭合的循环。

量化目标，是给循环装一个明确的终点。紧反馈，是给循环装一个高速的引擎。外置记忆文件，是给循环装一个跨越上下文窗口的状态机。

最反直觉的是，这三件事没有一件和模型本身的能力有关。它们全是循环外面的脚手架。模型还是那个模型，但你愿不愿意为它搭好这个脚手架，决定了它能跑五分钟还是五天。

一句话总结：Agent 能跑几天，不是因为模型记得住，而是因为你让它把记忆写在硬盘上。

## Closing

如果你正准备让 Codex 跑长任务，先别急着写 prompt。先想清楚三件事——什么状态叫完成、单轮反馈要多少秒、你给它准备几个 markdown 文件来思考。把这三件事定下来，再按下回车。
