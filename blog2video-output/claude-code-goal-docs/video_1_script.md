# 让另一个模型来判断"做完了没"？

[SLIDE 1: cover] (0:00 - 0:25)

Anthropic 在 Claude Code 里加了一个一行命令，叫 /goal。表面上是让 Claude 自己一直跑到事情完成。但它真正藏着的，是一个更大的设计选择。今天不聊怎么用，也不教你写条件——只聊这个选择。

[SLIDE 2: image] (0:25 - 1:45)

机制其实很简单。你输入 /goal，后面跟一个完成条件。比如说，test 目录下所有测试通过，并且 lint 步骤干净。Claude Code 收到这一行，立刻开始第一轮工作，条件本身就是任务说明。

每一轮结束之后，系统不会把控制权还给你。它会调用另一个小模型，默认是 Haiku，把你的条件加上目前为止的对话历史，扔给它判断一句话：达成了，还是没达成。

如果是达成，goal 自动清除，记录一条完成。如果是没达成，小模型会顺手给一句理由，作为下一轮的指导喂回主模型，让它继续。

[SLIDE 3: principle] (1:45 - 3:05)

我读完文档最有感觉的是这一点。大多数人看到这个命令，会以为重点是"Claude 现在能自己一直跑"。不是。重点是 Anthropic 把"判断做完了没"这件事，从干活的那个模型手里拿走了，交给一个独立的、级别更低的小模型。

这在 LLM 系统设计里有个名字，叫 generator-evaluator 分离。一个负责生成，一个负责评分，职责切开。以前这种分离通常发生在一整个任务的最后一步，做一次质量打分。

/goal 把这件事压到了每一轮对话的粒度上。每一轮结束，评估器都来一次。这不是新功能，是把一个架构选择，做成了一行命令。

[SLIDE 4: comparison_cards] (3:05 - 4:30)

文档里有一张对比表，我觉得它比所有功能介绍都更有立场。它把三种"让 Claude 继续跑"的方式放在一起。

第一种是 /goal。上一轮结束，下一轮就开始，直到评估器说条件达成才停。第二种是 /loop。它按时间间隔触发，比如每五分钟跑一次，直到你叫停。第三种叫 Stop hook。每轮结束之后跑你自己写的脚本或者 prompt，由你来决定要不要继续。

这三个不是替代关系。区别也不在能跑多久，而在"谁来触发下一轮"。条件达成、时间到了、还是你的代码说了算。这是一个触发器选择问题，选错就是浪费 token，或者根本停不下来。

[SLIDE 5: principle] (4:30 - 6:05)

讲到这里，有一个最容易被忽略的限制，必须单独拎出来。那个负责判断的小模型，不能调用任何工具。它看不到文件系统，跑不了测试，连一次 grep 都做不了。它能看到的，只有 Claude 自己在对话里"晒"出来的内容。

这条约束直接决定了什么条件能写，什么条件写了等于没写。

举个例子。"代码没有 bug"——这个条件评估器没法判断，它没办法跑代码。"性能优化了"——也不行，没数据可看。

但"npm test 退出码是零"就有效。为什么？因为 Claude 在干活的时候，真的会去跑 npm test，结果会打到对话历史里，评估器读到那段输出，就能判断。

这就把"写条件"这件事，从一个意图表达问题，变成了一个工程问题——你要想清楚，怎么让主 agent 主动产生可被验证的证据。

[SLIDE 6: checklist] (6:05 - 7:50)

任何设计都有代价。这个设计的代价至少有三层。

第一层，评估器可能判错。Haiku 这种小模型能力有限，可能给出错误的"达成"，让一个没完成的任务被提前清除；也可能给出错误的"没达成"，让明明做完的事继续烧 token。

第二层，条件必须自带证据。这听起来简单，但实际写的时候，你会发现一半你想表达的目标，都没办法在对话里直接呈现证据。条件设计的难度，被低估了。

第三层，token 会累积。评估本身很便宜，因为用的是小模型。但只要条件没达成，主轮就会一直跑，主模型一直在烧。文档自己也建议你在条件里加一句兜底，比如最多跑二十轮就停。

还有一点也要交代。/goal 本质上是已有的 Stop hook 机制的语法糖，所以它受 hooks 系统的权限约束。在某些受管的企业环境里，可能根本启用不了。

[SLIDE 7: summary] (7:50 - 9:10)

我不觉得 /goal 是一个"新功能"。它是一个被压缩成一行命令的架构表态——让 agent 继续跑下去的那个开关，不应该握在干活的那个模型手里。

这件事的影响，远不止 Claude Code 这一个产品。任何在做 agentic loop 的人，都可以把这套思路套用过去：生成和评估分离，评估器轻量化，评估器的反馈作为下一轮的指导。

一句话总结。让 agent 跑下去的开关，不该握在干活的那个模型手里。
