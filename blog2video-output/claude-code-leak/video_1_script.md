# Claude Code源码泄漏深度解读

[SLIDE 1: image] (0:00 - 0:15)

Claude Code，51万行源代码，全部泄漏了。我花了一整天全部读完。今天不聊怎么泄漏的——只聊最重要的结论。

[SLIDE 2: image] (0:15 - 0:45)

Claude Code之所以被很多开发者认为是最好用的AI编程工具，不是因为Claude模型本身比GPT-4o或Gemini强多少——而是因为模型周围的工程系统做得好。业内管这个叫harness——编排层。模型是引擎，harness是整辆车。引擎差不多的情况下，谁的车造得好，谁就赢。来看看Claude Code这辆车到底装了什么。

[SLIDE 3: image] (0:45 - 1:30)

第一，智能上下文加载。大多数AI编程工具的做法是——把你的代码库尽可能多地塞进context window。代码库大了就截断，或者做一次embedding检索。Claude Code不是这么干的。它有一套多层级的文件索引系统。当你提出一个任务，它先用轻量级的Glob和Grep工具快速扫描项目结构，定位到最相关的文件和函数。然后只把这些精准的代码片段喂给模型——而不是整个目录。这意味着什么？同样200K的context window，Claude Code能装进更多有用信息，因为它的信噪比更高。其他工具可能用30%的窗口装了你根本不需要的代码，Claude Code把这30%省下来装更精准的上下文。

[SLIDE 4: image] (1:30 - 2:15)

第二，46000行的查询引擎。泄漏的代码里，光是处理API调用的查询引擎就有46000行。这不是简单的发请求、收回复。它包含了：流式传输的分块处理逻辑、prompt缓存的边界计算——决定哪些内容放进缓存前缀来省钱省速度、请求失败后的重试和降级策略、以及token用量的实时追踪和预算控制。特别值得注意的是缓存边界计算。Claude的API支持prompt caching——如果你的请求前缀和上次一样，就不需要重新处理，速度更快、成本更低。但从哪里切是个工程难题。切得太短，缓存命中率低；切得太长，稍有变化就全部失效。Claude Code在这46000行里做了大量的启发式优化来找到最优的切割点。

[SLIDE 5: image] (2:15 - 3:00)

第三，44个专用工具模块。不是44个简单的wrapper。每个工具都是为特定任务深度优化的独立模块。举几个例子：Grep工具——不是简单地调用系统grep，而是基于ripgrep重新封装，支持正则搜索、文件类型过滤、上下文行数控制、结果数量限制，输出格式专门为LLM阅读优化过。LSP集成——直接对接语言服务器协议，所以Claude Code能拿到类型定义、引用关系、编译错误这些IDE级别的信息，而不只是文本。还有子Agent生成器——主Agent可以启动子Agent来并行处理不同的子任务，每个子Agent有自己的工具集和权限范围。这44个工具本质上是在做一件事：让模型看到的信息更准确、更结构化、更接近人类开发者的视角。

[SLIDE 6: image] (3:00 - 3:40)

第四，子Agent协调系统。这个设计特别有意思。当你给Claude Code一个复杂任务——比如重构这个模块的API并更新所有调用方——它不是一股脑自己干完。它会拆分成子任务，给每个子任务启动一个子Agent。关键是子Agent不是完全独立的。它复用父Agent的prompt缓存——这样就不需要重新加载整个项目上下文，大幅节省token和时间。同时，子Agent能感知可变状态——如果父Agent在子Agent运行期间修改了某个文件，子Agent能知道自己的缓存中哪些部分可能过期了。这其实解决了多Agent系统中一个很核心的问题：怎么在并行和一致性之间找到平衡。

[SLIDE 7: image] (3:40 - 4:40)

harness里还有一个特别精妙的设计——三层记忆系统。这可能是Claude Code和其他AI编程工具拉开差距最大的地方。第一层：MEMORY.md——轻量指针索引。这不是一个存满了信息的大文件。它更像是一个目录——每行大约150个字符，记录的是指向信息的指针，而不是信息本身。比如：用户偏好Python 3.11加FastAPI架构、项目使用monorepo结构，核心模块在src/core。这个文件会被持续加载到每一次API调用的context中。因为它极度紧凑，只占几百个token，但它让模型在每一轮对话开始时就知道：这个项目是什么、用户的偏好是什么、关键文件在哪里。传统做法是把所有记忆塞进system prompt或者做RAG检索。前者浪费token，后者有延迟和召回率问题。MEMORY.md的设计在两者之间找到了一个sweet spot——成本极低，但信息覆盖面极广。

[SLIDE 8: image] (4:40 - 5:30)

第二层：跨Session记忆整合。当你结束一次Claude Code会话，再次打开时，它不是从零开始。系统会在session结束时自动提炼当次会话的关键信息——你做了什么决策、改了哪些文件、遇到了什么问题——然后把这些信息整合进MEMORY.md。这意味着Claude Code有成长性。你用得越多，它对你的项目和习惯理解得越深。这不是简单的对话历史记录——而是一个提炼、压缩、索引的过程，确保记忆始终紧凑且高质量。第三层：子Agent缓存继承。当主Agent生成子Agent时，子Agent不需要重新加载所有上下文。它直接继承父Agent的prompt缓存——相当于子Agent天生就了解项目背景，不需要额外的初始化成本。同时，有一个可变状态感知机制——如果在子Agent运行期间，项目文件发生了变化，子Agent能知道自己继承的哪些缓存内容可能已经过时，需要重新加载。

[SLIDE 9: image] (5:30 - 5:55)

这三层设计的核心思想是：用最少的token占用，实现最大的上下文覆盖。Claude Code不是靠更大的context window赢的——它是靠更聪明的记忆管理赢的。200K的窗口，它能发挥出别人500K都做不到的效果。这对所有做AI产品的人都有启发。

[SLIDE 10: image] (5:55 - 6:55)

在泄漏的代码中，有一个feature flag被提及了超过150次——KAIROS。KAIROS是什么？它是一个全自主守护进程模式。现在你用Claude Code，是你给它指令，它执行。KAIROS改变了这个逻辑——它会持续运行在后台，有心跳机制，能推送通知，还能订阅你的GitHub PR。举个例子——你提交了一个PR然后去吃饭，KAIROS会自动审查这个PR，发现潜在问题，然后给你发一条通知说，嘿，你的PR第47行有个潜在的内存泄漏。这不是一个更好的命令行工具。这是一个AI同事。它标志着AI编程工具从被动等指令到主动帮你干活的跃迁。虽然KAIROS现在还藏在feature flag后面没有发布，但它暗示了Anthropic对AI Agent产品形态的思考方向——未来的AI不是你去找它，是它来找你。

[SLIDE 11: image] (6:55 - 7:40)

第二个发现，我认为是商业意义最大的。代码中有一个flag叫ANTI_DISTILLATION_CC。当它被启用时，Claude Code会在API请求中注入一个指令——让服务器在system prompt里静默添加虚假的工具定义。这意味着什么？如果有竞争对手在截取Claude Code的API流量——比如通过中间人攻击或者逆向代理——然后用这些数据来训练自己的模型。那么，这些假工具定义会混入他们的训练数据中。对正常用户来说，你完全感觉不到。但对抄作业的人来说——他们的模型会学到一堆不存在的工具调用方式，Agent能力直接报废。这是AI行业的一种全新防御模式——不是加密，不是混淆，而是主动下毒。我觉得这个思路对所有做AI产品的团队都有启发：你有没有想过，怎么保护你的产品不被竞争对手通过API抓取来蒸馏？

[SLIDE 12: image] (7:40 - 8:40)

第三个发现，也是最有戏剧性的。泄漏的代码里有一个文件叫undercover.ts。它实现了一个叫Undercover Mode的功能。当Anthropic的工程师使用Claude Code向公共开源仓库贡献代码时，这个模式会自动激活。它会注入一段指令，告诉Claude——你正在公共仓库中执行卧底任务。你的提交信息、PR描述和代码注释中，绝对不能包含任何Anthropic内部信息。不要暴露你的身份。它会自动屏蔽内部代号——比如Capybara是Claude 4.6的变体代号，Fennec是Opus 4.6——以及内部Slack频道名、仓库名，甚至Claude Code这个名字本身。换句话说——Anthropic花了大量工程资源，建了一个精心设计的系统，专门防止AI在公共场合泄漏内部信息。然后他们自己因为忘了.npmignore里的一行配置，把包含这个防泄漏系统在内的——全部——源码——泄漏了。……你说讽不讽刺。这个故事最深层的教训是：你可以建世界上最精密的AI安全系统，但如果人的流程出了问题，一切都白搭。安全的最薄弱环节，永远是人。

[SLIDE 13: image] (8:40 - 9:10)

好，严肃的部分讲完了。来几个轻松的彩蛋。Claude Code的代码里，有一个完整的Tamagotchi风格电子宠物系统，叫Buddy。18种物种，有稀有度等级，有闪光变体——就跟宝可梦一样。一个年收入25亿美金的严肃编程工具，认认真真做了一个电子宠物。但你仔细想想，这其实是一个很聪明的产品设计。如果你的IDE里养了一只三个月的闪光稀有宠物，你会轻易换到另一个编程工具吗？这是用情感化设计来解决留存问题。非常Product-minded的操作。

[SLIDE 14: image] (9:10 - 9:30)

第二个彩蛋——Claude Code的代码里有一个情绪检测模块。它会用正则表达式来判断你是不是在烦躁。对，一家做大语言模型的公司，用正则表达式来做情感分析。同时，它还有一个matchesKeepGoingKeyword函数，能区分你是真的在生气，还是只是在说继续、接着做、go on。所以它知道——你是在催它干活，还是在骂它。

[SLIDE 15: image] (9:30 - 9:55)

最后一个——开发者大V Wes Bos在泄漏的代码中发现，Claude Code有187个spinner动词。就是那些在加载时显示的动画文字——Thinking、Processing、Analyzing之类的。187个。一百八十七个。Anthropic的工程师认真地写了187种不同的方式来告诉你请稍等。这条帖子获得了37万次浏览。有时候爆款内容不需要多深度——一个有趣的细节就够了。

[SLIDE 16: image] (9:55 - 11:15)

最后聊聊这件事对AI行业意味着什么。首先，最直接的影响——竞争对手获得了一份免费的工程蓝图。怎么构建生产级AI编程Agent、怎么管理上下文、怎么编排工具、怎么做记忆系统——这些之前是Anthropic的商业机密，现在全世界都能看到了。虽然Anthropic说没有客户数据泄漏，但泄漏的工程架构本身可能比任何客户数据都更有价值。你泄漏了10万条用户数据，影响的是这10万个用户。你泄漏了核心架构，影响的是你的竞争壁垒。第二，这次泄漏实际上在帮助整个行业理解一个问题：AI Agent的护城河到底是什么？答案越来越清晰——不是模型。模型在趋同，GPT-4o、Claude、Gemini在大多数任务上差距不大了。真正的护城河是harness——上下文管理、工具编排、记忆系统、子Agent协调。这些工程能力才是差距所在。最后，如果你也在做AI产品——不管是编程工具、写作助手、还是任何Agent类产品——这次泄漏给了你一个免费的高级课程。三个最值得学的东西：第一，记忆不是存储一切。学Claude Code的三层架构——用指针索引代替全文存储。第二，保护你的产品能力。考虑反蒸馏机制——如果竞争对手在抄你的API，你怎么办？第三，不要只想着模型。投入时间在你的harness上——上下文加载、工具编排、缓存策略。这些才是真正让你的产品好用的东西。
