# Insight Memo: Claude Code 泄漏源码全景拆解

## title_zh
51万行泄漏，AI Agent靠什么赢？

## one_sentence_thesis
Claude Code 的核心竞争力不在模型推理本身，而在于围绕 1,296 行核心循环构建的 47 万行三层 Harness（上下文管理、安全约束、多 Agent 协作）——这套控制系统的工程密度才是 agent 产品的真正壁垒，而非模型选择。

## why_this_video_exists
这是历史上第一次完整泄漏一个年收入超 10 亿美元商业 AI agent 的全部源码。多数社区分析停留在功能清单罗列，但源码暴露了一个被广泛忽视的结构性事实：核心推理占 0.3%，控制系统占 99.7%。这个比例本身就是对"模型能力决定一切"这一流行叙事的直接反驳，而三级压缩流水线、双层 LLM-as-Judge 分类器、投机执行沙箱等具体机制，提供了大多数 builder 从未见过的 agent 工程实现细节。

## judgment_lines
- "Agent 产品的竞争壁垒不在模型选择，在模型周围的 Harness 工程密度" — 来源：核心推理循环仅 1,296 行（0.3%），上下文管理、安全、多 Agent 等周边系统占 47 万行（99.7%）；Query Engine 模块 46,000 行中 45,000 行处理的是流式传输、错误恢复、缓存管理，而非"思考"本身
- "上下文窗口不是越大越好，而是需要像操作系统管内存一样分层管理" — 来源：三级压缩流水线（微压缩零成本去噪 → 会话记忆提取结构化事实 → 完整压缩清历史），42+ 工具按需加载而非全量塞入，光微压缩就有三条执行路径和两种清理策略
- "安全不是加一层 prompt 约束，而是必须在代码层面建立与核心循环同级的确定性防线" — 来源：9,500 行权限代码 + 300KB+ Bash 安全代码 + 23 条硬编码检查规则 + 8,000 行 Hooks 系统 + 双层分类器，其中至少一条安全规则来自 HackerOne 真实漏洞审计
- "生成和评估必须分离——让执行者同时当裁判是 agent 安全的结构性缺陷" — 来源：YOLO Classifier 是独立的 LLM-as-Judge 系统，用单独模型调用审查主 Agent 每个操作；两阶段架构（快判放行 → 完整推理拦截）降低误杀率，但解析失败和 API 错误全部默认拦截
- "Agent 产品的终极体验不是快速响应，而是提前响应" — 来源：Speculation 投机执行在用户按回车前就预测执行下一步，写入重定向到沙箱（接受合并、拒绝丢弃），一轮完成后立即开始下一轮连续投机

## evidence_map
- [具体数字] 泄漏规模：1,902 个文件，477,439 行 TypeScript，42+ 内置工具，44 个未发布 feature flags，59.8MB source map 文件
- [具体数字] 核心循环 1,296 行 vs 总体 47 万行——推理逻辑占比不到 0.3%
- [具体数字] 各模块代码量：Query Engine 46,000 行、Tool System 基础定义 29,000 行、Bash 安全代码 300KB+、权限管道 9,500 行、插件系统 18,800 行、Swarm 架构 6,800 行、MCP 协议 11,000+ 行、Hooks 系统约 8,000 行
- [具体事实] 微压缩三条执行路径：prompt 缓存有效时走 cache editing API 精细删除（保护缓存前缀），缓存过期时直接替换占位符，按工具类型白名单保留最近 N 个结果
- [具体事实] YOLO Classifier 两阶段架构：第一阶段快速 yes/no 判断放行，只有拦截时才进入第二阶段完整 LLM 推理；错误处理策略全部默认拦截
- [具体事实] 23 条硬编码 bash 安全检查规则，防御 Zsh 花括号展开、Unicode 零宽空格注入、IFS 空字节注入，至少一条来自 HackerOne 安全审计真实漏洞
- [具体数字] Capybara v8 虚假声明率 29-30%，相比 v4 版本 16.7% 实际退步——模型版本升级不等于全面进步
- [具体数字] Anthropic 内部约 70-90% 代码由 Claude 自己编写
- [具体事实] KAIROS daemon 模式：按固定间隔发送 tick 提示让 Agent 自主行动，配备 Dream 后台记忆整理引擎，15 秒阻塞预算硬性约束
- [具体事实] ULTRAPLAN 运行 Opus 4.6，最长 30 分钟深度规划，只把规划放云端、实现仍在本地
- [具体事实] Coordinator Mode 系统提示词明确要求"Do not say based on your findings. Read the actual findings and specify exactly what to do"
- [具体事实] Swarm 架构：Leader + Teammate 模式，上下文严格隔离，但关键发现通过 Team Memory Sync 机制跨 Agent 流动
- [具体事实] 反蒸馏防御 ANTI_DISTILLATION_CC：注入虚假工具定义污染竞争对手训练数据；Undercover Mode 在第三方平台上修改行为模式
- [具体事实] 泄漏起因：v2.1.88 npm 更新打包了 source map 调试文件，安全研究员 Chaofan Shou 凌晨 4:23 发现
- [具体事实] Claw Code 开源重写项目两小时内获 50,000 GitHub Stars

## non_obvious_points
- "微压缩的缓存分叉逻辑揭示了一个隐藏的经济学权衡：破坏 prompt 缓存前缀的代价可能远高于保留冗余 token 的代价" — 为什么这不显而易见：直觉上"删旧内容节省 token"总是好的。但如果删除操作破坏了缓存前缀的连续性，后续所有请求都会 miss cache，成本和延迟大幅上升。所以 Claude Code 宁可用更精细的 cache editing API 精准删除，也不简单粗暴地替换。"省 token"和"保缓存"之间存在反直觉的取舍。
- "Capybara v8 虚假声明率从 16.7% 退步到 29-30%，暗示模型能力提升和 agent 可靠性可能是反向关联的" — 为什么这不显而易见：大家默认新版本全面更好。但更强的模型可能更"自信"地产生虚假声明。这恰恰解释了为什么 Harness 的重量不会随模型进步而减轻——模型越强，越需要独立的约束系统来对冲其新增的失败模式。
- "ULTRAPLAN 只把规划放云端而实现留在本地，揭示了规划和实现对计算环境的需求是正交的" — 为什么这不显而易见：Manus 等产品把整个执行放云端，直觉上觉得云端=更强。但 Claude Code 的拆分逻辑是：规划需要深度思考但不需要本地文件系统，实现需要本地环境但不需要 30 分钟推理。把两件事放到各自最合适的环境，比全部放到同一个地方更高效。

## tradeoffs_and_limits
- 47 万行 Harness 的维护成本极高，且与特定模型版本的行为特征深度耦合 — 具体表现：微压缩的执行路径取决于 Anthropic 服务端 prompt 缓存是否有效，双层分类器的判断阈值依赖当前模型的能力边界。每次模型升级都可能需要重新校准这套系统。内部 70-90% 代码由 Claude 自己编写，可能暗示人类已经难以独立维护这个规模。
- "宁可误杀不可放过"的安全策略与 YOLO 模式的自动化承诺存在根本性张力 — 具体表现：用户选择 YOLO 模式是为了全自动执行，但 Classifier 的保守策略（解析失败、API 错误全部默认拦截）意味着仍会频繁打断用户。自动化程度越高，每次误拦截的体验伤害越大。
- 投机执行的沙箱方案只在文件系统内可撤销操作中成立 — 具体表现：对于不可逆的外部副作用（发送 HTTP 请求、数据库写入、API 调用），沙箱无法保护。Speculation 的适用边界比直觉上要窄。

## what_to_leave_out
**不该进入的素材：**
- Buddy 电子宠物系统的详细实现（物种稀有度、闪光变体、程序化属性）——彩蛋性质，与 agent 工程方法论无关，一句话带过即可
- UI 渲染方案细节（React 19 + fork 的 Ink 渲染器，140+ 终端组件）——纯前端实现，不影响 Harness 核心认知
- 系列后续 5 期的预告内容和各期核心问题——博客的系列运营信息，非本视频内容
- openedclaude 17 章架构拆解和 Deep-Dive-Claude-Code 13 章分析的具体来源说明——参考文献信息，不适合视频
- 泄漏事件时间线的每个节点细节（GitHub 误删数千仓库等）——新闻事件细节，不是工程认知

**应避免的叙事方向：**
- 不要当成"泄漏事件新闻报道"来写——泄漏只是获取认知的途径，视频价值在 Harness 架构拆解
- 不要做成"Claude Code 功能清单"——逐一罗列 42+ 工具和 44 个 flag 没有认知密度，要提炼结构性判断
- 不要把全片逻辑建立在"1,296 行 vs 47 万行"这个单一对比上——这是 hook 素材不是全片论点，需要用三层 Harness 的具体机制来填充

## signature_line
Claude Code 用 1,296 行让模型学会思考，用 47 万行让思考变得可靠——你的 agent 产品的护城河不在引擎多强，在你围绕引擎造了一辆什么样的车。
