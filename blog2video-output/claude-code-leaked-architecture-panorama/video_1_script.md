# 47万行源码泄漏：最强Agent只用1296行思考？

[SLIDE 1: cover] (0:00 - 0:25)

Claude Code的完整源码泄漏了。1902个文件，47万行TypeScript。我把所有技术分析全部读完了。今天不聊泄漏八卦——只聊一个数字：1296。

这里是精读AI。AI世界很吵，每期帮你从全球顶级AI团队的一手文献里，读透一篇最值得读的。今天我们精读的是LoreAI对Claude Code泄漏源码的深度技术分析。

[SLIDE 2: principle] (0:25 - 1:15)

先说这个让我最震撼的数字。Claude Code的核心引擎——就是真正让模型思考的那个循环——只有1296行。用户说一句话，拼系统提示词，调模型，模型要用工具就执行，结果喂回去，继续循环。没有状态图，没有DAG编排器。就是一个while循环。

1296行，占47万行的百分之零点二七。

剩下那百分之九十九点七三在干什么？全部在做一件事——让这个循环在真实世界里跑得可靠、安全、可控。业内管这个叫Harness。我的判断是：最好的Agent架构不是最复杂的核心，而是最简单的核心加最精密的周边。

[SLIDE 3: image] (1:15 - 2:30)

Harness里工程密度最高的部分，是上下文管理。光查询引擎就4万6千行。为什么需要这么多？因为大模型的上下文窗口是稀缺资源。关键不是装不装得下，是该不该装进去。

Claude Code设计了一条三级压缩流水线。第一级叫微压缩。不调模型，纯规则驱动。按工具类型白名单，保留最近几个工具结果，把更早的清掉。听起来简单，但这一刀下去有个巨大的陷阱。

[SLIDE 4: comparison_cards] (2:30 - 3:45)

陷阱就是缓存经济学。Anthropic的API会缓存你发过去的prompt前缀。下次请求如果前缀一样，不重新处理，省钱省时间。所以微压缩每次动刀前都要算一笔账：这一刀下去，会不会让服务端缓存失效？

源码里有三条执行路径。第一条，用户在连续对话，缓存还活着。走精细路径，用cache editing API删掉特定工具结果，但不动prompt前缀。第二条，用户离开一段时间回来，缓存早过期了，直接替换成占位符，不用小心翼翼。第三条处理白名单之外的边界情况。

我认为这是整个源码里最反直觉的工程判断：破坏缓存前缀的代价，可能高于保留冗余token的代价。你宁可让上下文多几百个没用的token，也不能让缓存失效重新算一遍。上下文管理的工程难度远超调用模型本身。

[SLIDE 5: image] (3:45 - 4:30)

第二级是会话记忆压缩。不做摘要，提取结构化事实——项目结构、用户偏好、任务进度。存到本地记忆目录。提取事实，不是叙事。

第三级才是完整压缩，用一次独立的模型调用总结整段历史。之前的消息全部移除。

三级流水线，三个粒度，三种成本。微压缩去噪声，记忆压缩提事实，完整压缩清历史。42个以上的内置工具也不是一开始全塞进去，核心工具启动时加载，扩展工具按需加载。所有设计指向同一个原则：上下文窗口里每一个token都要值回票价。

[SLIDE 6: principle] (4:30 - 5:30)

再来看安全层。仅Bash安全相关代码就超过300KB，权限系统9500行。核心设计原则六个字：宁可误杀，不可放过。

最典型的是YOLO Classifier。YOLO模式让Agent自动执行命令不需要人确认。但哪些命令可以自动？Claude Code的答案是两阶段架构——生成和评估必须分离。模型先生成要执行的命令，然后一个独立的分类器判断是否安全。默认拦截，只有明确判定安全才放行。

这不是保守。你想想不对称风险——误拦截的代价是什么？用户多点一次确认按钮，三秒钟。误放行的代价呢？一条rm -rf删掉整个项目。宁可误杀不可放过，不是价值观，是数学。

[SLIDE 7: image] (5:30 - 6:10)

安全规则也不是拍脑袋写的。源码里有23条硬编码规则，其中包含HackerOne真实漏洞的防御。比如Unicode零宽空格绕过——攻击者在命令里插入肉眼看不见的字符，骗过正则检查。这不是理论场景，是有人真的提交过的漏洞报告。

还有一个让人警醒的内部数据。Capybara基准测试显示，最新v8模型的虚假声明率是百分之二十九到三十。而早期v4只有百分之十六点七。模型越强，虚假声明越多。这意味着什么？模型越聪明，可能需要越重的Harness来约束它。

[SLIDE 8: quote] (6:10 - 7:15)

现在说说44个未发布的feature flag。它们暴露了Agent产品的终极瓶颈——不是模型速度，而是人机交互的等待损耗。

第一个叫Speculation，投机执行。模型预测你会批准当前操作，不等确认就在沙箱里先跑。甚至支持连续投机，一口气预测好几步。你确认了，结果直接用，零等待。你拒绝了，沙箱丢弃，没有副作用。但这个方案有个硬前提——只在写操作可撤销时成立。

第二个叫KAIROS Dream引擎。Agent在你不说话的时候也在思考。用tick提示驱动空闲整理，15秒阻塞预算。趁你打字的间隙预加载文件、规划下一步。从等指令到主动思考，从工具到同事。

[SLIDE 9: image] (7:15 - 7:55)

聊几个轻松的。代码里有一个完整的Tamagotchi风格电子宠物系统，叫Buddy。18种物种，有稀有度等级，有闪光变体。一个年收入25亿美金的编程工具，认认真真做了电子宠物。但你想想——如果你在IDE里养了一只三个月的闪光稀有宠物，你会轻易换工具吗？这是用情感设计解决留存。非常Product-minded。

[SLIDE 10: image] (7:55 - 8:30)

还有一个叫反蒸馏防御。启用后，Claude Code在API请求里静默注入虚假工具定义。如果竞争对手截取API流量训练模型，这些假工具会污染训练数据。正常用户完全感觉不到。但抄作业的人——模型会学到一堆不存在的工具调用，Agent能力直接报废。不是加密，不是混淆，是主动下毒。

最讽刺的是Undercover Mode。Anthropic工程师向公共仓库贡献代码时自动激活，防止AI暴露内部信息。然后他们自己忘了.npmignore里的一行配置，把整个防泄漏系统连同全部源码一起泄漏了。

[SLIDE 11: principle] (8:30 - 9:15)

最后说一个容易被忽略的tradeoff。内部百分之七十到九十的代码由Claude自己编写。47万行，大部分不是人写的。这意味着人类工程师已经很难独立维护这个系统。Harness越厚，产品越可靠，但维护负担也越重。而维护者本身也是AI。这是一个递归依赖——你用AI构建了约束AI的系统，然后需要AI来维护这个约束系统。Claw Code两小时拿下5万Star，证明市场饥渴。但这个递归依赖往下走，终点在哪，没人知道。

[SLIDE 12: summary] (9:15 - 10:00)

回到那个核心数字。1296行核心循环，47万行周边控制。如果你在做Agent，这份泄漏源码给了一个清晰信号：你的竞争力不在核心逻辑多聪明，在Harness建得多厚。

给你一个具体的行动。打开你的Agent代码仓库，统计核心模型调用逻辑和周边控制代码各多少行。如果后者不到前者的十倍，你的Harness还不够。

1296行让AI学会思考，47万行让AI学会克制。最强Agent的秘密不是更聪明——是更知道什么时候该停下来。
