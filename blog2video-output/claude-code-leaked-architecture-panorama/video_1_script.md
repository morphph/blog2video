# 口播稿：47万行源码泄漏：最强Agent只用1296行思考？

[SLIDE 1: cover] (0:00 - 0:45)

59.8MB。这是一个调试文件的大小。它本不该出现在公开的 npm 包里，但它就这么被打包发布了。一个安全研究员凌晨四点二十三分发现了它，然后 Claude Code 的完整源码就这样泄露给了全世界。1902个文件，47万7千行 TypeScript，全部暴露。两小时之内，一个叫 Claw Code 的开源重写项目拿到了五万个 GitHub Star。

这里是精读AI。AI世界很吵，每期帮你从全球顶级AI团队的一手文献里，读透一篇最值得读的。今天我们精读的是 LoreAI 对 Claude Code 泄露源码的深度技术分析。

[SLIDE 2: principle] (0:45 - 2:30)

这份源码最让我震撼的不是它有多大，而是一个比例。Claude Code 的核心引擎叫 QueryEngine，整个模块四万六千行。但真正让模型思考的核心循环，只有1296行。用户说一句话，构建系统提示词，调用模型，模型要用工具就执行，把结果喂回去，继续循环，直到给出回答或者预算花完。没有状态图，没有 DAG 编排器，就是一个 while 循环。

1296行，占47万行的百分之零点二七。

剩下那百分之九十九点七在干什么？答案是 Harness。最好的 Agent 架构不是最复杂的核心，而是最简单的核心加最精密的周边。1296行让模型学会思考，47万行让思考在真实世界里可靠运转。我把这套 Harness 拆成三层来讲。第一层，上下文管理，解决模型该看什么。第二层，安全与约束，解决模型不能做什么。第三层，未来架构，解决模型不够快、不够聪明怎么办。

[SLIDE 3: comparison_cards] (2:30 - 7:00)

先说上下文管理。这是整个 Harness 里工程密度最高的部分。Claude Code 设计了一条三级压缩流水线。

第一级叫微压缩。不调用模型，纯规则驱动。它按工具类型白名单，保留最近几个工具结果，把更早的清掉。但怎么清，有讲究。调用 API 的时候，Anthropic 会缓存你发过去的 prompt 前缀。下次请求如果前缀一样，就不重新处理，省钱省时间。所以微压缩每次动刀，都要先想一个问题：这一刀下去，会不会让服务端缓存失效？

上下文管理的工程难度远超调用模型本身，因为缓存经济学引入了路径分叉。源码里有三条执行路径。如果用户一直在连续对话，缓存还活着，微压缩走精细路径，通过 cache editing API 告诉服务端删掉特定工具结果，但不动 prompt 前缀，缓存继续有效。如果用户离开一段时间回来，缓存早就过期了，那就没必要小心翼翼，直接把旧的工具输出替换成占位符。第三条路径处理工具白名单之外的边界情况。破坏缓存前缀的代价可能高于保留冗余 token 的代价，这个判断本身就需要精密的工程权衡。光这一个微压缩，就有防循环依赖的内联常量、防子 Agent 污染全局状态的主线程隔离，成本几乎为零，但设计密度极高。

第二级是会话记忆压缩。它不做摘要，而是从对话中提取结构化事实。项目结构、用户偏好、任务进度，持久化到本地记忆目录。提取的是事实，不是叙事。第三级才是完整压缩，用一次独立的模型调用总结整段历史，之前的消息从模型视野中移除。三级流水线，三个粒度，三种成本。微压缩去噪声，记忆压缩提事实，完整压缩清历史。

工具系统也在做同样的事。Claude Code 内置了42个以上的工具，但不是一开始全塞进上下文。核心工具启动时加载，扩展工具按需加载。每个工具用 Zod schema 做输入验证，输出太大就存到外部，给模型一个摘要加指针。所有设计指向同一个原则：上下文窗口是稀缺资源，关键不是装不装得下，而是该不该装进去。

再说安全层。这一层的代码量同样惊人。仅 Bash 安全相关代码就超过300KB，权限系统九千五百行。核心设计原则是六个字：宁可误杀，不可放过。

最典型的是 YOLO Classifier。YOLO 模式让 Agent 自动执行命令不需要人确认，但哪些命令可以自动执行？Claude Code 的答案是两阶段架构。生成和评估必须分离。模型先生成要执行的命令，然后一个独立的分类器判断这条命令是否安全。分类器默认拦截，只有明确判定安全才放行。这不是保守。在不对称风险下这是唯一理性的选择。误拦截的代价是什么？用户多点一次确认按钮，三秒钟的事。误放行的代价呢？一条 rm -rf 就能删掉整个项目。

安全规则也不是拍脑袋写的。源码里有23条硬编码规则，其中包含 HackerOne 真实漏洞的防御。比如 Unicode 零宽空格绕过，攻击者在命令里插入肉眼看不见的字符骗过正则检查。这不是理论场景，是有人真的提交过的漏洞报告。

[SLIDE 4: quote] (7:00 - 9:00)

最有意思的是藏在44个 feature flag 后面的未发布功能。它们暴露了 Agent 产品的终极瓶颈。

第一个叫 Speculation，投机执行。模型预测你下一步会批准当前操作，于是不等你确认就在沙箱里先跑起来，甚至支持连续投机，一口气预测好几步。如果你确认了，结果直接拿来用，零等待。如果你拒绝了，沙箱结果丢弃，没有副作用。投机执行暴露了一个关键判断：Agent 产品的终极瓶颈不是模型速度，而是人机交互的等待损耗。但这个方案有个硬前提，只在写操作可撤销时才成立。

第二个叫 KAIROS Dream 引擎。它让 Agent 在你不说话的时候也能思考。用 tick 提示驱动空闲整理，设定了15秒的阻塞预算。Agent 趁你打字的间隙，整理上下文、预加载可能用到的文件、规划下一步。

还有一个让人警醒的内部数据。Anthropic 自己的 Capybara 基准测试显示，最新的 v8 模型虚假声明率是百分之二十九到三十，而早期的 v4 只有百分之十六点七。模型越强，可能需要越重的 Harness 来约束它。内部百分之七十到九十的代码由 Claude 自己编写，这意味着人类工程师已经很难独立维护这个系统。47万行 Harness 的维护负担本身就是一个 tradeoff。

[SLIDE 5: summary] (9:00 - 10:00)

回到那个核心数字。1296行核心循环，47万行周边控制。如果你在做 Agent 开发，这份泄露的源码给出了一个非常清晰的信号：你的竞争力不在核心调用逻辑写得多聪明，而在周边 Harness 建得多厚。

给你一个具体的行动：打开你的 Agent 代码仓库，统计核心模型调用逻辑和周边控制代码各多少行。如果后者不到前者的十倍，Harness 还不够厚。

1296行让AI学会思考，47万行让AI学会克制。最强 Agent 的秘密不是更聪明，是更知道什么时候该停下来。
