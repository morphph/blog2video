[SLIDE 1: cover] (0:00 - 约0:30)

你有没有遇到过这种情况——

每次开新会话，都要重新告诉 Claude：
"我用 TypeScript，用两空格缩进，别给我加注释，项目结构是这样的……"

说一遍还好。说第十遍，你就会开始怀疑，这是在用 AI 帮你工作，还是你在帮 AI 补课。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Claude Code 官方文档——关于一个叫 CLAUDE.md 的文件，它能让你只说一次，Claude 永远记住。


[SLIDE 2: principle] (约0:30 - 约2:00)

CLAUDE.md，就是你写给 Claude 的规则手册。

你把它放在项目根目录，每次 Claude 开始工作，它会自动读这个文件。不需要你提醒，不需要你重复，就像新员工入职第一天，HR 给他一本《公司守则》——以后所有行为，都以这本册子为准。

重点来了：这不只是一个文件，是一套作用域体系。

你可以理解成公司的三层规章制度——集团规则、部门规则、个人习惯，层层叠加，各司其职。写一次，每次会话自动加载，完全不需要你再开口。


[SLIDE 3: comparison_cards] (约2:00 - 约3:30)

我们来拆开这三层，看看分别放在哪、管什么。

**第一层：项目级。** 文件放在 `./CLAUDE.md` 或者 `./.claude/CLAUDE.md`。这是给团队用的。你把编码规范、项目架构、工作流程写在这里，所有人拉代码、打开 Claude Code，立刻同步这套规则。这个文件应该提交到 git，是团队共识的载体。

**第二层：用户级。** 文件放在 `~/.claude/CLAUDE.md`，也就是你的主目录下。这是你的个人偏好。比如你喜欢回答简短一点，不喜欢 Claude 加太多注释——这些只影响你自己，不影响别人。

**第三层：组织级。** 这是重头戏。IT 部门可以把 CLAUDE.md 放到一个托管策略位置——macOS 是 `/Library/Application Support/ClaudeCode/CLAUDE.md`。这个文件有一个特性：任何人都不能通过个人设置把它排除掉。公司终于能统一管住所有开发者的 AI 使用方式了。


[SLIDE 4: checklist] (约3:30 - 约4:30)

知道了体系，再说几个容易被忽略的实操细节。

文件别写太长。官方建议控制在 200 行以内。超过这个，Claude 对指令的遵循度会下降。内容多的话，用 `@path/to/import` 语法引用其他文件，就像便签上写"详见附件"，最多支持 5 层嵌套。

指令要具体，不要模糊。比如"格式化代码"这种说法没用。要写成"用两空格缩进"、"函数超过 50 行就拆分"——越具体，Claude 越能准确执行。

项目大了，用 `.claude/rules/` 目录。你可以把规则拆成多个文件，用 YAML frontmatter 里的 paths 字段指定范围——比如只对 TypeScript 文件生效的规则单独放一个文件，像不同房间的门禁卡，进哪个房间才刷哪张卡。

规则不能互相矛盾。如果你在两个地方写了冲突的指令，Claude 会随机选一个——结果完全不可预测。
