[SLIDE 1: cover] (0:00 - 约0:30)

你有没有想过，Claude Code 里有一个默认开启的功能，会让它悄悄给自己写笔记？

不是你写给它的规则，是它自己记录的东西。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Claude Code 官方文档。

上期我们讲了怎么用 CLAUDE.md 手写规则。但其实 Claude 还有一套自动记忆系统。这期，我们来看 Auto Memory 到底怎么用。


[SLIDE 2: principle] (约0:30 - 约2:00)

先问你一个问题：你雇了一个助手，每次开会之前，他都会翻翻上次的便签，把重要的事情提前记住。你需要教他怎么记吗？不需要，他自己会记。

Auto Memory，就是这个逻辑。

Claude 在帮你写代码的过程中，会自动判断——这件事下次还会用到吗？如果值得记，它就写下来。构建命令、调试时发现的坑、你的代码风格偏好，全都能自动积累。

关键是：默认就是开启的。你什么都不用做，它已经在帮你记了。

但这里要注意一个容易混淆的点。

CLAUDE.md，是你写给 Claude 的规则——你的项目规范、你的工作要求，是你主动写进去的。

Auto Memory，是 Claude 写给自己的笔记——它在工作过程中自己积累的经验，你不需要干预。

一个是你写的规则，一个是它写的笔记。两件事，分开放。


[SLIDE 3: comparison_cards] (约2:00 - 约3:30)

那这些笔记，到底存在哪里？怎么组织的？

存储路径是 `~/.claude/projects/` 加上你的项目名，再加上 `memory/` 目录，里面有一个入口文件，叫 MEMORY.md。

这里有一个设计细节，很值得说。

每次新会话开始的时候，Claude 只会加载 MEMORY.md 的前 200 行。超过 200 行的内容，直接不加载。

你可能会想：那多记几条不就超了？

Claude 也知道这个问题。所以它会主动把详细内容拆出去，放到独立文件里。比如调试相关的放 debugging.md，API 规范放 api-conventions.md。MEMORY.md 只保留索引，详细内容按需去读。

就像手机桌面只能放有限的图标，常用的放桌面，其他的放文件夹，需要了再找。

还有一点：这些 memory 文件，都是普通的 markdown 文件。你随时可以打开来改，也可以直接删。

另外要知道，Auto Memory 是按项目隔离的。你在项目 A 里的笔记，不会出现在项目 B 里。同一个 git 仓库的不同 worktree，会共享同一份 memory。


[SLIDE 4: checklist] (约3:30 - 约4:30)

知道了原理，怎么真正用起来？

运行 `/memory` 命令。这是查看和管理 Auto Memory 的入口，你可以在里面浏览所有 memory 文件，确认 Claude 记了什么，也可以直接打开某个文件去编辑。

建议你做三件事。

翻一遍现有的记录。看看 Claude 自动攒下了哪些内容，有没有记错的，删掉就好。

如果你想让 Claude 记住某件事，直接对它说就行，比如"记住，我们这个项目只用 pnpm，不用 npm"。它会把这条存进 Auto Memory。

把那些你反复要手动解释的规则，主动写进 CLAUDE.md。Auto Memory 是 Claude 自己攒的，CLAUDE.md 是你的主动规划。两个配合用，效果最好。

如果你不想用 Auto Memory，可以在 `/memory` 里关掉，或者设置环境变量 CLAUDE_CODE_DISABLE_AUTO_MEMORY 等于 1。


[SLIDE 5: summary] (约4:30 - 约5:00)

总结一下。

Auto Memory 是 Claude 的自学笔记本。默认开启，自动积累，不需要你操心。但它不是黑盒，所有文件都是普通 markdown，你随时可以审查、编辑、删除。

记住 200 行这个限制。Claude 会自动拆文件来应对，但如果你发现它好像忘了某些东西，可以去检查一下 MEMORY.md 有没有超。

今天的行动只有一件事：运行 `/memory`，翻翻 Claude 给自己记了什么。删掉不准的，留下有用的，再想想哪些规则值得写进 CLAUDE.md。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
