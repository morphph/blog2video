Claude Code，51万行的源代码泄漏了。
很多人的第一反应是去扒它的system prompt写了什么，或者去看它调了哪些工具。说实话，这些确实有意思，但如果你只盯着这些看，你看到的只是表面。
我把这些代码的分析都看了一遍，最大的感受是——Claude Code根本不是一个"大模型加一段prompt再接几个工具"的东西。它更像一个完整的AI操作系统。
为什么这么说呢？因为它最关键的设计不是某一个点做得好，而是把好几个本来很分散的能力做成了一个稳定的闭环。
今天我从五个角度来拆一下，Claude Code到底泄漏了什么真正值钱的东西。

第一，prompt不是一段咒语，是一整套动态配置系统。
很多人对prompt的理解还停留在"写一段很厉害的话，模型就会变聪明"。但Claude Code完全不是这么干的。
它的prompt是在运行时动态拼接出来的。前面一层是稳定的规则，你可以理解成系统的宪法——核心身份、安全约束、行为边界，这一层几乎不变。后面一层是这次会话的实时配置——你的项目记忆、你连了哪些工具、你在什么环境工作——全部动态拼进去。
这个差别很大。当你把prompt当文章来写，你优化的只是表达。但当你把prompt做成配置系统，你优化的是整个agent的行为逻辑。
它甚至会根据你是不是在公共仓库工作来注入完全不同的指令。有一个叫Undercover Mode的模块，检测到你在非内部仓库时会自动激活，告诉模型不要暴露任何Anthropic的内部信息。而讽刺的是——这个防泄漏模块自己也跟着源码一起泄漏了。

第二，多agent不是炫技，是职责拆分。
这点我觉得特别关键。
现在很多人做agent的思路还是一个agent从头干到尾。查资料、写代码、测试、判断完成——全是同一个。问题在哪？它既是运动员又是裁判，天然会对自己宽容，最后做成"差不多就行"。
Claude Code不是这样的。它会把探索、规划、实现、验证拆给不同的子agent。探索型agent是只读的，只能搜索和分析，不能改文件。规划型也是只读的。实现型才有写入权限。
更精妙的是子agent之间的协调——子agent直接继承父agent的缓存，不需要重新加载上下文。同时有一个可变状态感知机制，如果父agent改了文件，子agent能知道自己的缓存可能过期了。
这解决了多agent系统最核心的问题：并行效率和状态一致性的平衡。背后其实是很经典的软件工程思想——关注点分离。

第三，最值钱的地方可能不是生成，而是验证。
这点很多人会忽略。大家总觉得AI编程最重要的是"写出来"。但真正做过系统的人都知道，难的从来不是写——是怎么确认它写的是对的。
Claude Code有一层专门的验证逻辑。它会强制跑build、测试、linter、类型检查。不同类型的改动有不同的验证方式。甚至它会主动找边界情况——不是确认能跑，是想办法把它搞坏。
为什么这层重要？因为大多数agent失败不是因为完全不会做——而是做了个80分，然后特别自信地说"我已经完成了"。
所以从做产品的角度看，顶级agent的核心能力不只是生成能力，而是验收能力。

第四，工具调用不是能调就行，是必须被治理的。
很多人理解agent调工具很简单——模型说一句，拿到结果，结束。但真实系统不是这样的。
Claude Code的工具执行链路是：执行前做输入校验、权限检查、风险判断；执行后有hooks机制和上下文补充——把结果格式化成模型最容易理解的形式。
它甚至重新封装了grep、find这些系统工具，不是功能不够，而是原始输出是为人类终端优化的，不是为大语言模型优化的。
还有一个反蒸馏机制——它会在API请求里静默注入虚假的工具定义。如果有竞争对手截取API流量训练模型，这些假工具会污染训练数据。对正常用户透明，但对抄作业的人是毒药。
这背后就是一个核心原则：防御性编程。默认事情会出问题，你不能假设一切都正常。

第五，它已经在认真处理agent的生命周期了。
这个特别重要。很多agent demo第一次用特别惊艳，问题都出在后面。任务断了怎么办？上下文脏了怎么办？会话怎么恢复？

Claude Code有一个三层记忆系统。最上层叫MEMORY.md——不存具体信息，只存指针，每行150个字符，告诉模型"信息在哪"而不是"信息是什么"。只占几百token，但让模型随时知道项目全貌。中间层是跨session的记忆整合——每次会话结束自动提炼关键信息，下次打开不从零开始。底层是子agent的缓存继承。
这三层用最少的token占用实现了最大的上下文覆盖。Claude Code不是靠更大的context window赢的，是靠更聪明的记忆管理赢的。
它还有一个叫KAIROS的守护进程模式，在代码里被提到150多次。有心跳、推送通知、PR订阅——AI不等你输入指令，它自己主动行动。这决定了它到底是一个工具还是一个AI同事。
这些东西听起来不炫酷，但特别值钱。因为它决定了你的东西是demo还是产品。

所以如果问我，Claude Code这次到底泄漏了什么？
我会说，它真正透露出来的是——agent的竞争已经不是模型能力的竞争了，开始进入系统工程能力的竞争。
以后你再看一个agent产品，不要只看它会不会说。你看五件事：
它有没有规则系统——prompt是静态的还是动态编排的？ 它有没有分工——是一个agent从头干到尾，还是有探索、规划、验证的拆分？ 它有没有验证——做完之后谁来验收？ 它有没有工具治理——调用前有没有校验，调用后有没有兜底？ 它有没有生命周期——断了能不能恢复，记忆能不能持续？
这才是行家看门道的地方。
顶级agent的秘密不在于它多会说——而在于它背后有没有一套认真编织起来的系统。
