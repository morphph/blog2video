# Video 1: PRD已死？AI让软件开发流程彻底反转

[SLIDE 1: cover]

你写了三天的产品需求文档，排版精美、逻辑严密。结果隔壁同事用 AI，一小时就搞出了可运行的原型。你的文档，还有人看吗？

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 LangChain CEO Harrison Chase 的博客。

他说了一句很重的话：PRD，作为软件开发起点的时代，结束了。

[SLIDE 2: principle]

先解释一下传统流程。以前做软件，就像开餐厅上菜。先写菜谱，也就是 PRD。再画摆盘图，也就是设计稿。最后厨师下厨，工程师写代码。

Idea，PRD，Mock，Code。四步瀑布，一步接一步。

为什么要这么走？因为写代码太贵了。一个功能动辄几周，所以你得先用文档对齐所有人，避免返工。PRD 就是这条流水线的发令枪。

但 AI Agent 出现后，代码成本暴跌。Harrison Chase 的原话是：anyone can write code now。任何人都能写代码了。

这意味着什么？你不需要先写菜谱了。直接炒出一盘菜端上桌，大家尝了再改。

[SLIDE 3: comparison_cards]

那新流程长什么样？Harrison Chase 画了三个阶段。

传统流程：Idea 到 PRD，PRD 到 Mock，Mock 到 Code。瓶颈在最后一步，代码写得太慢。

现在很多团队的状态：Idea 直接到 Code。三方围着原型给反馈。瓶颈变了，不是写代码慢，而是要 Review 的原型太多。

以前 Reviewer 桌上只有几个项目。现在谁都能用 Agent 搞出原型，Review 队列直接爆了。就像外卖平台，以前厨师不够用，现在 AI 当了厨师，但质检员不够了。

第三阶段，他认为的终局：Idea 同时产出 Doc 加 Code 的捆绑包，提交 Review。文档不再是起点，而是解释意图的说明书。

他还提了一个大胆的想法：未来的 PRD，可能就是一组结构化的、有版本控制的 Prompt。

[SLIDE 4: checklist]

那你现在能做什么？

下次有新功能想法，别急着写文档。先用 AI Agent 花一小时搭出可运行的原型。再写一份简短的需求说明，解释设计意图。用原型加文档的组合包，发起评审。

让 Review 的人看到活的东西，而不是一堆抽象描述。

[SLIDE 5: summary]

所以 PRD 死了吗？没有。死掉的是 PRD 作为起点的那套瀑布流程。文档本身在进化，从发令枪变成了说明书，从 Word 文档变成了给 AI 的精确指令。

记住这句话：代码生成成本趋近于零的时候，写什么不再是难题，判断该不该写才是。

流程变了，那做产品的人呢？下期聊：谁会被淘汰，谁能活下来。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
