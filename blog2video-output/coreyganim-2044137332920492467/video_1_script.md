# Routines：AI编程不再需要你在场

[SLIDE 1: cover] (0:00 - 1:03)

Anthropic 刚刚给 Claude Code 加了一个新功能，叫 Routines。听起来像个小更新，但它改变了一件根本的事：AI 编程助手不再需要你坐在电脑前了。你合上笔记本，它还在干活。这不是"更好的自动补全"，这是 AI 从对话工具变成后台服务。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Anthropic 官方博客发布的 Claude Code Routines。

[SLIDE 2: image] (1:03 - 2:14)

先说最基础的。一个 Routine 是什么？

你可以把它理解成一个"打包好的 Claude Code 任务"。里面有三样东西：一段 prompt，告诉 AI 该做什么。一个或多个代码仓库，给它工作的上下文。还有一组 connector，让它能连接外部工具，比如 Slack、Linear 这些。

打包好之后，这个任务就不在你的电脑上跑了。它跑在 Anthropic 托管的云端。你关机、睡觉、出门，它照样执行。

而且关键的一点：运行过程中没有权限弹窗，没有审批流程。它是完全自主的。你设定好规则，它自己干。

[SLIDE 3: image] (2:14 - 3:55)

一个 Routine 怎么启动？Anthropic 给了三种触发方式。

第一种是定时触发。你可以设成每小时、每晚、每周跑一次。最短间隔是一小时。

第二种是 API 触发。每个 Routine 有一个专属的 HTTP 端点。你往这个端点发一个 POST 请求，带上 Bearer token，它就启动了。调用后会返回一个 session URL，你可以直接点进去看 AI 正在做什么。

第三种是 GitHub 触发。有人开了 Pull Request，或者发布了新 Release，Routine 自动响应。还支持按作者、标题、分支、标签这些条件做过滤。

这三种触发器可以叠加。一个 Routine 可以同时绑定定时触发、API 触发和 GitHub 事件触发。这意味着什么？AI 代理可以直接嵌入你现有的 DevOps 工具链，而不是独立存在。

[SLIDE 4: image] (3:55 - 5:25)

光说触发器太抽象。来看 Anthropic 给的几个真实用例，你就明白这东西能干嘛。

第一个，积压工单维护。每天晚上定时跑一次，读取当天新开的 issue，自动打标签，根据代码区域分配负责人，然后往 Slack 发一份总结。第二天早上团队到了，待办已经整理好了。

第二个，报警分诊。监控系统检测到错误率超标，直接调 Routine 的 API 端点，把报警内容传过去。Routine 拉出 stack trace，关联最近的 commit，然后开一个 draft PR，附上修复建议和报警链接。值班的人打开的不是一个空白终端，而是一个已经写好修复方案的 PR。

第三个，代码审查。有人开了 PR，GitHub 触发器自动启动。Routine 按你团队自己的 review checklist 来审，在代码行上直接留评论，标出安全、性能、风格问题。人类 reviewer 可以把精力放在设计层面，而不是机械检查上。

[SLIDE 5: image] (5:25 - 6:54)

第四个，部署验证。CD 流水线部署完成后，调 API 触发 Routine。它跑冒烟测试，扫错误日志找回归，然后在发布频道里发一条"通过"或"不通过"。

第五个，文档漂移检测。每周跑一次，扫描本周合并的 PR，找出文档里引用了已变更 API 的地方，自动开更新 PR。

第六个，这个最有意思——跨语言 SDK 移植。一个 SDK 仓库合并了 PR，Routine 自动把这个改动移植到另一种语言的 SDK 里，开一个对应的 PR。两个仓库自动保持同步，不需要人手动重新实现。

[SLIDE 6: principle] (6:54 - 8:28)

这里有一个很重要的设计细节，值得单独说。

Routine 做的所有操作，都以你的个人身份执行。它开的 PR，用的是你的 GitHub 账号。它发的 Slack 消息，用的是你的 Slack 身份。它创建的 Linear ticket，也是你的名字。

这不是技术限制，我认为这是一个刻意的信任边界设计。Anthropic 没有给 Routine 创建一个独立的 bot 身份，而是把它绑定在你个人账户上。好处是什么？可追溯。每一个操作都能追到具体的人。坏处呢？如果你的 Routine 在凌晨三点开了一个奇怪的 PR，那上面挂的是你的名字。

而且 Routine 目前不支持团队共享。它属于你个人的 claude.ai 账户，也占你个人的每日运行额度。团队协作场景下，这会有摩擦。

[SLIDE 7: image] (8:28 - 9:56)

还有一个技术细节值得注意。

每次 GitHub 事件触发 Routine，都会启动一个全新的 session。不支持跨事件复用 session。这意味着什么？Routine 本质上是无状态的。每次执行，它都要重新 clone 仓库，重新理解上下文，从零开始。

对于简单任务，这不是问题。但如果你的仓库很大，或者任务需要理解之前几次执行的历史，这个架构就会有效率损耗。

另外，分支权限也有限制。默认情况下，Routine 只能 push 到 claude/ 前缀的分支。你可以手动解除这个限制，但默认是保守的。还有一点，所有连接的 MCP connector 默认全部包含。如果你不主动去掉不需要的，就可能违反最小权限原则。

[SLIDE 8: image] (9:56 - 11:09)

最后说说限额。Pro 用户每天 5 次，Max 用户 15 次，Team 和 Enterprise 25 次。

这个数字本身就传递了一个信号：Anthropic 把 Routines 定位为高价值的精准任务，而不是廉价的批量自动化。你不会拿每天 5 次的额度去跑 lint 检查。你会用它来做那些真正需要 AI 理解力的事情——审代码、分诊报警、移植 SDK。

Enterprise 用户如果启用了 extra usage，超出上限后可以按用量付费继续跑。但这个限制本身说明，至少在当前阶段，Routines 是一个受控的、渐进式的发布。

[SLIDE 9: summary] (11:09 - 12:29)

回头看这个功能，它改变的不是 AI 写代码的质量。Claude Code 之前就能写代码，而且写得不错。Routines 改变的是 AI 工作的模式——从"你问我答"的对话模式，变成了事件驱动的后台服务模式。

这是一个范式的变化。AI 编程助手的工作单位，不再是一次对话，而是一个持续运行的服务。它可以响应 GitHub 事件，可以接收 API 调用，可以按计划执行。当然，它目前还有明确的限制：无状态、个人绑定、次数受限。但方向已经非常清晰了。

AI 编程助手的下一步，不是写得更好，而是不需要你在场就能工作。
