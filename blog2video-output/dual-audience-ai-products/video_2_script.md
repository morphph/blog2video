[SLIDE 1: cover] (0:00 - 0:25)

你听说过 UX 用户体验，也听说过 DX 开发者体验。但你听说过 AX 吗？Agent Experience——AI Agent 的使用体验。Agent 选工具不看广告、不看品牌，只看文档清不清晰、API 好不好用、响应快不快。它零容忍失败，也不会点"联系销售"。

这里是 AI 精读。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们继续聊双受众 AI 产品的核心概念和技术基础。

[SLIDE 2: principle] (0:25 - 2:00)

先来理清 UX、DX 和 AX 的关系。

UX 是给用户铺红毯，DX 是给程序员修高速路，AX 是给 AI Agent 建专用车道。三条道各走各的，但目的地相同——让你的产品被顺畅使用。

区别在哪？人类用户容忍度高。页面加载慢三秒，他骂两句，但仍然会等。开发者碰到 SDK 的坑，翻翻 Stack Overflow 也能绕过去。

但 Agent 完全不同。API 返回一个模糊的错误信息，它不会猜，直接放弃，换下一个工具。没有结构化文档？它根本发现不了你。

这个概念最早由 Netlify CEO Mathias Biilmann 提出。他的判断是：AX 已经成了产品设计的新战场。你的对手不只是功能更强的产品，而是文档写得更好的产品。

[SLIDE 3: comparison_cards] (2:00 - 4:30)

理解了 AX，下一个问题是：Agent 通过什么方式连接你的产品？答案是三大协议。

第一个，MCP，Model Context Protocol，Anthropic 出品。它解决的是 Agent 怎么调用工具。你可以把它理解成"AI 的 USB-C 接口"。以前每个工具都要写专门的对接代码，有了 MCP，一个标准接口全兼容。

第二个，A2A，Agent2Agent Protocol，Google 出品，超过 150 个组织参与。它解决的是 Agent 之间怎么协作。MCP 是 Agent 调工具，A2A 是 Agent 调 Agent。就像企业间有标准合同，统一格式才能高效合作。

第三个，llms.txt。你知道 robots.txt 吧？它告诉搜索引擎"你能爬哪些页面"。llms.txt 做类似的事：告诉 AI"我这个网站能做什么、API 怎么用"。相当于给 Agent 写了一份自我介绍。

三者的分工很清晰：MCP 管"怎么用"，A2A 管"怎么合作"，llms.txt 管"怎么被发现"。缺一不可。

[SLIDE 4: quote] (4:30 - 5:15)

说到这儿，分享一个让我印象很深的案例。

Supabase 被 Agent 选为默认的 Postgres 工具。注意，不是因为功能最强，也不是价格最低——而是因为文档写得最好。

这就是 AX 的力量。Agent 只看文档清晰度、API 质量和响应速度。你投再多广告它看不到，销售团队再强它不会接电话。唯一能打动它的，是技术文档和 API 接口。

[SLIDE 5: summary] (5:15 - 6:00)

从 UX 到 DX 再到 AX，产品设计进入了多受众时代。MCP、A2A、llms.txt 三大协议，就是连接人类世界和 Agent 世界的桥梁。

你现在就可以做一件事：给你的产品做一次 AX 审计。检查 API 文档是否机器可读，错误信息是否结构化，有没有 MCP Server 或 llms.txt。列出 Agent 使用你产品时的所有卡点，逐个消除。
