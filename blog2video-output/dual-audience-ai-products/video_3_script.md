# Video 3: API文档就是新Landing Page！12周落地双受众AI产品实操指南

[SLIDE 1: cover] (0:00 - 0:25)

Netlify有一个Agent部署的Bug。Agent调CLI发起部署，返回了一条人类才看得懂的报错信息。Agent读不懂，一遍遍尝试，全部失败。后来工程师只改了一行代码，把报错换成结构化输出，Agent立刻一次部署成功。一行代码，就是Agent时代胜负的分水岭。

这里是 AI 精读。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们来聊实操——怎么把你的产品改造成Agent友好型。

[SLIDE 2: principle] (0:25 - 2:00)

先说一个核心观点：API docs are the new Landing Page。API文档就是你的新首页。

为什么？传统产品靠精美的Landing Page吸引人类用户。人会被设计打动，会点按钮，会联系销售。但Agent不看你的首页。Agent只看三样东西：文档是否清晰、API质量如何、响应速度够不够快。文档写得不好，Agent直接跳过你，选下一家。

这意味着产品需要双轨界面。一条轨道是GUI，给人用的图形界面，漂亮、直觉、有引导。另一条轨道是API加MCP加A2A，给Agent走的专用通道，结构化、可预测、零歧义。

打个比方。这就像银行同时开了柜台和网银。柜台是给你我这样的人用的，有窗口、有服务员、能问问题。网银API是给自动化系统用的，24小时运转，不需要排队。两条通道，服务不同客户，但后端是同一套系统。

另外一个概念叫 Agent SEO。传统SEO是让Google搜到你，Agent SEO是让AI Agent找到你、选中你。怎么做？确保你有llms.txt、有机器可读的定价页、有即时发放的API密钥。Agent不会填表单、不会"联系销售"，它只接受自助流程。

[SLIDE 3: comparison_cards] (2:00 - 4:00)

知道了方向，怎么落地？原文给了一套12周框架，分三个阶段。

第一阶段，第1到第4周，API-First基建。这是打地基。梳理所有API端点，统一错误返回格式，确保每个接口都有结构化的、机器可读的文档。记住Netlify的教训——一条人类可读但机器看不懂的报错，就能让Agent完全卡死。这四周的目标：让Agent调你的API时，永远能拿到明确的成功或失败信号。

第二阶段，第5到第8周，Agent接入层。地基打好了，开始装门窗。这阶段做两件事：搭建MCP Server，让Agent通过标准协议调用你的工具；创建llms.txt文件，放到网站根目录，告诉AI"我是谁、我能做什么、怎么调用我"。这就像给Agent写了一份产品说明书。

第三阶段，第9到第12周，AX优化。精装修阶段。接入A2A协议，让你的服务能和其他Agent协作。搭建Agent使用监控面板，观察Agent怎么用你的产品、哪里出错最多。最后，打通Agent支付通道——让Agent能自主完成从选择到付费的全流程。

三个阶段，就像装修房子：打地基、装门窗、精装修。不需要推倒原来的产品从零开始。

[SLIDE 4: checklist] (4:00 - 5:15)

三个真实案例，看看头部公司怎么做的。

第一个，Supabase。它成为Agent默认的Postgres工具，靠的不是功能最强。靠的是文档质量最好。Agent选工具，文档清晰度排第一位。Supabase把每个API都写到了机器友好的程度，所以被Agent"选中"了。

第二个，Stripe。它推出了Agent Toolkit，专门给Agent提供支付能力。效果多明显？YC W26批次有一家叫Sponge的公司，直接基于Stripe Agent Toolkit构建了自己的产品。你提供Agent友好的基建，就会有创业公司围绕你壮大。

第三个，又是Netlify。就是开头提到的那个案例。仅仅修改了一行CLI错误输出，从人类可读的自然语言换成结构化格式。这一行改动，就让Agent从"无法部署"变成"成功部署"。小改动，大效果。

[SLIDE 5: summary] (5:15 - 6:00)

总结一下核心公式：文档即产品，Agent即用户，小改动即大杠杆。

你不需要等12周全部走完才见效。本周就可以开始第一步：梳理你产品的API端点，检查每个接口的错误返回是不是结构化的，然后创建一个llms.txt文件放到网站根目录。这三件事，就是你的Agent友好型改造的起跑线。
