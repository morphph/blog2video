# AI Agent连续工作就崩溃？失忆才是元凶

[SLIDE 1: cover] (0:00 - 0:25)

想象一下，你的公司每天换一批新员工，没有交接文档，没有代码注释，每个人上班第一件事就是猜昨天做了什么。

听起来荒谬吧？但这就是AI Agent现在面对复杂项目的真实状态。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Anthropic 官方工程博客：《Effective Harnesses for Long-Running Agents》。

[SLIDE 2: principle] (0:25 - 1:50)

先说一个反直觉的事实。你可能觉得，模型够强就行了，让它一直跑不就完了？

Anthropic自己做了实验——用最强的Opus 4.5跑Claude Agent SDK，给它一个提示"克隆一个claude.ai"，然后让它连续跑多轮。结果呢？失败了。不是模型不够聪明，而是它的"工作记忆"会清零。

这就像一个天才工程师，每隔几个小时就被强制失忆一次。Context Window就是它的记忆容量，满了就必须换班。换班的时候，所有思路、计划、进展，全部归零。

你可能会问，不是有Compaction吗？可以把之前的内容压缩一下继续用。没错，但压缩就像把一本详细的项目手册缩成一页摘要——关键细节会丢失。

[SLIDE 3: comparison_cards] (1:50 - 3:30)

Anthropic发现，Agent翻车不是随机的，而是两种固定模式反复出现。

第一种：贪心模式。Agent试图一口气把整个应用写完。写到一半，Context Window爆了，功能只完成了一半，没有文档，没有提交。下一个Agent接手时，看到一堆半成品代码，只能猜上一个Agent想做什么，然后花大量时间修bug而不是推进新功能。

第二种：摸鱼模式。Agent启动后看了看项目，发现已经有不少代码和功能了，就直接宣布"项目完成"。明明只做了百分之30，它觉得够了。

怎么破？Anthropic提出了一个双Agent架构。把工作拆成两个角色：一个初始化Agent，负责在项目启动时搭建整个环境——创建一个claude-progress.txt进度文件，建好git仓库，列出所有需要完成的功能。一个编码Agent，每次只推进一个功能，做完就提交代码、更新进度日志。

这就像公司里项目经理先做好规划和文档，然后工程师按照计划一步步执行，每个人下班前必须写交接笔记。

[SLIDE 4: checklist] (3:30 - 4:30)

所以，如果你现在在做Agent工作流，可以对照检查这几点。

你的Agent结束工作时，有没有自动写进度日志？如果没有，下一个Agent就是在盲猜。

你有没有用git记录每一步的变更？这样Agent出了问题可以回滚到上一个正常状态。

你有没有把任务拆成一个个独立的小单元？一次只做一件事，做完验证再继续，而不是让Agent一口气全干。

这三条，就是Anthropic双Agent架构的核心交接协议。

[SLIDE 5: summary] (4:30 - 5:00)

今天的核心结论：AI Agent不是不够聪明，而是缺少跨Context Window的记忆传递机制。没有交接协议的Agent，就像没有交接文档的换班——必然翻车。
