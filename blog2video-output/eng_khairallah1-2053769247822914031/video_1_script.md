# 8 万个 Skill 没人装，问题在哪？

[SLIDE 1: cover] (0:00 - 0:57)

Claude 社区有 8 万个免费 Skill。每周还在以千为单位增长。但 99% 的用户连一个都没装。这不是因为难用——是因为绝大多数人理解 Skill 的方式从一开始就错了。

[SLIDE 2: principle] (0:57 - 2:45)

先讲第一个 reframe，也是整篇文章里最颠覆我的一句话。

大多数人第一次听说 Skill，反应都差不多——"哦，就是把 prompt 存下来嘛"。我之前也这么想。

不是的。

saved prompt 是一次对话的起点。它告诉模型"你可以从这里开始聊"。但 Skill 给的是完全不同的东西——它告诉模型"这件事从头到尾该怎么做，好的输出长什么样，出问题怎么处理，要用哪些工具，最后怎么交付"。

你品一下这两句话的差距。一个是对话开场白，一个是完整的作业 SOP。

这就是为什么作者一直用"员工"这个词。saved prompt 像随手交代一句话，员工怎么理解全看悟性。Skill 像入职培训手册，谁来都能按这个流程跑出一致的结果。

[SLIDE 3: image] (2:45 - 3:48)

所以我说"员工"不是修辞，是工作方法。一旦你接受这个比喻，你接下来要做的事就完全变了——你要"招人"，就是去找别人写好的 Skill；你要"培训"，就是写 SKILL.md；你要"考核"，就是跑测试；你要"管理"，就是每周迭代。

这件事的隐含意思是——你之前每次用 Claude 都从零开始打 prompt 的工作方式，相当于公司里每来一个任务都重新面试一遍员工。听起来荒唐，但这就是大多数人现在干的事。

[SLIDE 4: principle] (3:48 - 4:45)

第二个认知冲击，来自一个简单的数字对比。

社区里现在有超过 8 万个 Skill，每周还在以"thousands"为单位增长。Anthropic 官方也已经发布了覆盖 PDF、Word、PPT、表格、设计的标准 Skill。

但绝大多数用户连一个都没装。

我看到这个数字的时候楞了一下。这不是某个能力还不存在、需要被发明出来——这是能力已经堆在仓库里，仓库门也开着，没人进去拿。

[SLIDE 5: image] (4:45 - 6:36)

为什么会这样？文章给了我一个非常锐的解释。

市面上几乎所有 Claude Skills 教程，都停在"怎么安装"这一步。装完就结束了。原文有一句话我特意标了下来——这等于教你怎么雇人，但不教你怎么管人。

这句话戳到了 AI 工具普及里最大的一个盲点。我们花了大量时间讨论模型能力、prompt 技巧、Agent 架构，但真正的杠杆缺口——已经有人写好的标准化能力包没被 adoption——几乎没人讲。

所以普通用户和高级用户的差距，可能根本不在写 prompt 的水平，而在有没有进入 Skill 生态。同样一个人，用裸 Claude 和用 30 个调好的 Skill，产出完全是两个量级。

这也是为什么这篇文章值得读——它不是又一份安装指南，它是在告诉你"为什么 8 万个员工在外面排队你一个都没招"。

[SLIDE 6: principle] (6:36 - 7:36)

讲完两个 reframe，给一个可以立刻用的动作。

如果你今天写了一个 Skill，恭喜你，但它大概率只值 70 分。

为什么这么说？因为原文给了一个非常硬的标准——一个 Skill 在跑过三个场景之前，都不算 production-grade。

[SLIDE 7: image] (7:36 - 8:25)

哪三个场景？happy path，最常见的输入，覆盖你百分之八十的用例。edge case，奇怪的输入，缺数据、格式异常、信息冲突。stress test，最大最乱最复杂的版本，看这个 Skill 在极限情况下会不会崩。

三个场景都过了，才能拿出去给客户看。任何一个场景失败，失败本身就告诉你该补哪条指令。

[SLIDE 8: image] (8:25 - 10:34)

这只是第一关。真正决定 Skill 价值的是后面那一关——每周 refine 一次。每次用完发现哪里不对，立刻回去更新 SKILL.md。原文说，这样坚持一个月之后，输出会"和人类专业人士不可区分"。

注意这个时间——一个月。不是写完那一刻，是迭代到第四周。

这就是为什么我说"装完就放着"是最大的错误。如果套用员工比喻——这相当于你招了人不分配工作，不给反馈，然后抱怨他没产出。

文章里还有两条具体到几乎刻薄的工程约束，我特别想拎出来。

第一条，SKILL.md 必须控制在 500 行以内。不是建议，是上限。

第二条更狠——"vague language is banned"。"format nicely"、"handle appropriately"这种含糊话，全部禁止。每一条指令必须 specific、必须 testable。

你看这两条规则，表面是格式约束，本质是在逼你做一件事：把你脑子里"我大概知道怎么做"的隐性经验，转译成"任何人按这个执行都能复现"的显性流程。

这一步本身就是把个人手艺变成可规模化资产的过程——和 Skill 是不是被 Claude 执行，已经无关了。换句话说，你哪怕从来不用 Claude，认真写一次 SKILL.md，对你本人的工作方法都是一次升级。

[SLIDE 9: image] (10:34 - 11:31)

最后聊聊代价，再回到那个被很多人当 hook 的数字。

讲 ROI 之前我必须诚实地说一件事——把 Skill 当员工来管，是有管理成本的。

原文专门提到，Skill 越多，元管理成本越高。你需要维护一份"主文档"——列出所有 Skill、当前状态、上次 refine 是哪天。这跟管理一个真实的小团队没什么区别，只不过员工换成了文件夹。

所以这不是装完即用的魔法。这是一个新的工作方式，需要时间投入、需要纪律、需要每周五雷打不动的 review。

[SLIDE 10: image] (11:31 - 13:48)

但代价讲完，我们看看回报。

一个 Skill，每周给你省 30 分钟。一年 52 周，就是 26 小时。

10 个 Skill 跑起来，就是 260 小时——大约 6.5 个完整工作周。

但你如果只把它理解成"省时间"，你就低估它了。

作者真正的主张藏在最后一句——"Let Claude handle the execution while you handle the strategy"。让 Claude 干执行，你干策略。

这不是效率提升，是工作层级跃迁。从亲自写每一封邮件、整理每一份报告、跑每一次分析——跳到只决定方向、只把关结果。

所以回到 Hook 我说的那句话——为什么我觉得过去半年自己用错了。因为我一直把 Claude 当 prompt 的对话框，每次重新组织语言、重新解释背景。我没意识到——我面前其实有 8 万个等着上岗的员工，而我连第一个都没招进来。

你以为 Skill 是 prompt 的升级版——其实它是你雇的第一个数字员工，而 8 万个员工正在外面排队等着上岗，你一个都没招。

[SLIDE 11: summary] (13:48 - 14:24)

如果你今天只带走一个动作——挑你重复最多的那件事，写一个 SKILL.md。500 行以内，禁止任何模糊措辞，跑三场景测试，然后每周五迭代一次。一个月以后再回来看输出。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
