# 模型越强，卡住你的反而是你自己

今天我带你精读一篇文章——《A Field Guide to Fable: Finding Your Unknowns》。作者 Thariq，推特叫 @trq212，Anthropic Claude Code 团队的人，也是 Fable 5 这代模型的发布参与者，讲的是一手经验。它戳一个特别扎心的问题：当模型强到某个程度，活儿干得好不好，瓶颈已经不在模型了，在你——在你能不能把自己都没想清的东西讲清楚。听完这一讲，不管你写不写代码，你都能拿到一套方法：在事情变贵之前，把你不知道的东西挖出来。

## 地图不是疆域，中间那道缝就是未知

作者说，跟 Fable 5 一起干活，反复在教他一个老道理：地图不是疆域。你看我身后这张图最上面，左边是地图，右边是疆域。地图，是你交给 Claude 的东西——prompt、skills、context。疆域，是活儿真正发生的地方——codebase、真实世界，还有它们实际的约束和坑。

地图和疆域永远对不齐，中间那道缝，作者给它起名叫 unknowns、未知，整篇文章都围着它转。这道缝为什么要命？因为 Claude 撞上一个未知时没法停下来问你，只能凭对你的最佳猜测自己做决定。活儿越大，撞上的未知越多，猜错一步，后面可能全歪。

> "Fable is the first model where I find the quality of the work is bottlenecked by my ability to clarify its unknowns."

Fable 是第一个让他觉得，工作质量被「我澄清未知的能力」卡住的模型。你品品——以前活儿干不好我们都怪模型笨，他说不是了，是我讲不清，卡住了它。

而且光提前规划还不够：你可能写到一半才冒出一个未知，它甚至会反过来告诉你，你压根该换一种思路。所以跟 Fable 协作，是在实现之前、之中、之后反复发现未知的过程——这个「前、中、后」，就是这张图的主时间轴。

## 用四个象限，把未知拆开看

那你的未知到底长什么样？你总得先看见它，才能挖它。你看图上这里冒出一个 2×2 四象限——就是 Rumsfeld 那个有名的 known 和 unknown 矩阵。

第一格，已知的已知，你 prompt 里明说的。第二格，已知的未知，你还没想清、但你知道自己没想清的。第三格开始有意思，未知的已知——那种太显然、你不会专门写下来、但一看到就认得的东西，比如视觉设计：你说不清要什么风格，但稿子摆面前你一眼知道对不对，这是藏在脑子里却调不出来的隐性知识。第四格最麻烦，未知的未知——你压根没考虑过的那块，连「好」的上限在哪都不知道。

作者说，顶尖的 agentic coder 未知其实很少，像 Boris、Jarred 那种人，跟 codebase、跟模型行为都深度同步；但关键是，他们也假设未知一定存在，绝不装全知。所以他给了一个重新定义：减少你的未知、为你的未知做规划，这件事本身就是 agentic coding 那门核心技能——不是你多会写 prompt，而是你多会管理未知。好消息是，这能练。

## 太具体和太模糊，你会两头都输

在动招之前，作者先给你看一个陷阱。你看图上这里，左右两个红框——左边「太具体」，右边「太模糊」，两支红箭头都往下汇到底下那个绿框。

太具体，你把话说死，Claude 就严格照指令走，哪怕换个方向更合适也不给你拐；太模糊，Claude 就自己拿主意，照所谓行业最佳实践做一堆未必适合你的假设。作者点破本质：当你不为未知做准备，你会两头都输——既不知道哪段路要提前扫雷，也不知道哪段路本是坦途、你却还想让 Claude 拐个弯。这是一个对称的陷阱，两个方向都输，输法还正好相反。

好在 Claude 恰恰能帮你更快挖未知：它搜 codebase、搜互联网快得离谱，从失败里迭代也快。而整段最重要的一步，就是两支箭头汇到的那个绿框——给 Claude 关于你「起点」的 context：告诉它你站在思考流程的哪一步、你对这个问题和 codebase 有多少经验，让它像个 thought partner、思想伙伴那样跟你一起想。接下来这套工具箱，就沿着这条时间轴排开，按需取用，不是每次全上。

## 实现前：五个便宜的探测

先看时间轴最左边，实现之前，五招。每一招你都留意它冲着哪一格未知去，这是心法，别听成一堆零散 tips。

第一招，盲点扫描，Blind Spot Pass，冲着最难缠的未知的未知。你在 codebase 一个没碰过的新区域写功能，身上一定挂着一堆未知的未知——不知道该问什么、「好」长什么样、有哪些坑。做法很简单：让 Claude 帮你做一次盲点扫描，把这些未知找出来讲给你听，关键是给它「你是谁、你懂什么」的 context，它才知道你的盲点在哪。

第二招，头脑风暴和原型，冲着第三格那种「看到才知道」的标准。作者判断很硬：越早在原型阶段把这些标准说出来越值钱，因为拖到实现阶段才发现，代价贵得多——spec 上一个小改动，可能导致代码里天差地别的实现。所以你只想看「一个按钮加进这个框长啥样」，就拿 HTML 假数据 mock 出来看一眼，别先去接后端。

第三招，访谈，Interviews。头脑风暴做完你多半还有未知，这时反过来，让 Claude 来访谈你，一个问题一个问题地问，而且优先问那些「你的回答会改变架构」的问题——把有限的问答花在最贵、最难反悔的决策上。

第四招，参照物，References。有时你就是描述不出你要什么。作者甩出一句特别反直觉又特别可操作的判断：绝对最好的参照物，是源代码。有个库已经实现了你想要的行为，那别费劲描述了，直接把 Fable 指向那个文件夹，哪怕它是另一种语言——它读的是底层代码，不只是截图。

第五招，实现计划，Implementation Plans。差不多能动手了，让 Claude 先出一份计划给你 review，诀窍是让它把最可能变的部分放最前面——数据模型、type interface、面向用户的 flow，逼它把「你其实可能要改」的东西主动浮出来，机械性的 refactor 埋最底下就行。

## 实现中：让它一边干一边写笔记

时间轴往右推一格，实现之中，只有一招，但它点破一个重要真相。这招叫实现笔记，implementation-notes。对计划满意了，作者会开一个全新的 session，把 spec、原型塞进去让 agent 实现。

但接下来这句是灵魂：无论事前规划得多充分，总有未知的未知在暗处潜伏。agent 真干起来，可能因为撞见代码里一个 edge case 就不得不换打法——你计划里根本没料到。作者的办法是，让 Claude Code 维护一个临时文件 implementation-notes.md，把每个决策记下来：撞上逼你偏离计划的 edge case，就选保守那个选项，记到「Deviations」下面，然后继续走。这招承认了——再好的地图也挡不住疆域冒出新东西，那就让它一边走，一边把新发现画进地图。

## 实现后：推介，和一场你必须及格的测验

再往右推一格，实现之后，两招。第一招，推介和讲解，Pitches and explainers。交付一件东西最重要的环节之一，是拿到别人的 buy-in 和批准。搭一个 pitch 有两个作用：reviewer 跟你当初一样带着同样一堆未知起步时，它加速对方理解；专家想确认你已经把他们会预见的失败点都考虑过时，它加速批准。你看，未知这条线又回来了——推介的本质，是替对方消掉他们的未知。

第二招，也是最后一招，测验，Quizzes。这招我特别喜欢。一段很长的 session 之后，Claude 干的比你意识到的多得多，你光读 code diff 只能得到很浅的理解，因为很多行为依赖已有的 code path。那就让 Claude 在给你补足一大堆 context 之后，就这次改动考你一场 quiz。作者的标准很硬：只有满分通过，他才会 merge——不是「大概看懂了」就合并，是「我能被考满分」才敢合并。

## 把这张图再走一遍：发布 Fable 那支视频

八招讲完，我们用一个真实例子把整套方法串一遍——发布 Fable 那支 launch video，完全由 Claude Code 剪辑。剪视频对作者是全新领域，他怎么下手？从他已知的东西出发，也就是第一格 known knowns。

他知道 Claude 能剪、能转录，但不确定准，于是让 Claude 讲讲 Whisper 怎么工作、能不能用 ffmpeg 精准剪掉「呃」「嗯」和长停顿——这是一次盲点扫描。他想要一个跟他说的每个字逐字同步的 UI，不确定能不能做到，于是让 Claude 用 Remotion 加转录做个原型验证——这是原型那招。最后视频看着有点发闷，他知道是 color grading 调色的问题，但并不真懂，本想让 Claude 做几个变体来挑，很快意识到：自己根本不知道调色的「好」长什么样——这不就是第四格、未知的未知吗？于是他改让 Claude 教他什么是 color grading，先把自己的未知发现出来——又绕回了盲点扫描。同一套方法，针对不同象限的未知，反复用。

## cheap now，永远小于 expensive later

我们走到这张图最后一块，右下角写着一句：cheap now，小于 expensive later，这是整套方法底层的经济学。作者说，模型越强，你用对方法能达成的越多，所以一个长周期任务返回一个错结果，别急着骂模型，很可能是你需要花更多时间去定义你的未知。

> "Every explainer, brainstorm, interview, prototype, and reference is a cheap way to find out what you didn't know before it gets expensive to fix."

每一个 explainer、每一次 brainstorm、每一场 interview、每一个 prototype、每一份 reference，都是在事情变贵之前，用一个很便宜的方式，把你原本不知道的东西挖出来。

你回头看这一整张图就全通了：最上面，地图对不齐疆域，那道缝就是未知；往下，四象限教你把未知看清；再往下，太具体和太模糊那两个红框、两支箭头汇成的双输陷阱；接着是沿着前、中、后铺开的一整套探测——实现前的盲点扫描、头脑风暴加原型、访谈、参照源码、实现计划，实现中的实现笔记，实现后的推介和测验；最后全收在右下角这句：现在便宜地问一句，好过将来昂贵地返一次工。所以作者留了句特别干脆的行动指令，我也交给你：你的下一个项目，就从「让 Claude 帮你找出你的 unknowns」开始。
