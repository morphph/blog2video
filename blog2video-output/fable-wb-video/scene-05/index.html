这一段只有一招，但它点破了一个特别重要的真相。
这招叫实现笔记，implementation notes。
对计划满意了，作者会开一个全新的 session，把 spec、原型这些 artifact 塞进 prompt，让 agent 去实现。
但接下来这句话是灵魂：无论你事前规划得多充分，总有未知的未知在暗处潜伏。
agent 真干起来，可能因为在代码里撞见一个 edge case，就不得不换一种打法——你计划里根本没料到。
作者的办法是，让 Claude Code 维护一个临时文件，叫 implementation-notes.md，把干活过程中做的每个决策都记下来，好让「下一次尝试」从这些笔记里学到东西。
而且交代它：撞上一个逼你偏离计划的 edge case，就选保守的那个选项，把它记到「Deviations」下面，然后继续走。
这一招承认了一件事——再好的地图，也挡不住疆域里冒出新东西；那就让它一边走，一边把新发现画进地图。
