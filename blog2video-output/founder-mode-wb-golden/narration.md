# 有一种运营公司的方式，商学院根本不知道它存在

有一个现象，硅谷最成功的一批创始人身上都发生过：公司做大之后，所有人都来告诉他们该怎么管，他们照做了，结果把公司管坏了。今天我要给你讲的，就是 Paul Graham——Y Combinator 的联合创始人——写的一篇文章，叫《Founder Mode》。这篇文章要解决的扎心问题是：为什么一套听起来完全正确、几乎人人都在推荐的管理建议，落到创始人手里却是灾难？听完这一讲你会拿到一张图，一张能把「两种运营公司的方式」讲清楚的图。不管你是不是做技术的、是不是创业者，都能跟上——因为这本质上讲的是「谁说了算，怎么说了算」。我们开始。

## 缘起：一场所有人都会记住的演讲

先说这篇文章是怎么来的。上周 YC 办了一场活动，Airbnb 的创始人 Brian Chesky 上台做了一场演讲。在场的每一个人，事后都记住了它。Paul Graham 说，他后来聊过的多数创始人都讲，这是他们这辈子听过最好的一场演讲。有个细节特别有画面感：Ron Conway——硅谷的资深投资人——这辈子头一回，忘了做笔记。你想想那是什么样的一场演讲，能让一个习惯记笔记的人听到忘了记。

Graham 说他不打算在文章里复述那场演讲，他想谈的是这场演讲引出的一个问题。而 Chesky 演讲的主题，你看白板上最上面这一行——「传统智慧是错的」。具体错在哪？随着 Airbnb 越做越大，很多善意的人来建议 Chesky：公司要想 scale、要想做大，就必须用某种特定的方式来运营。这些建议，乐观地概括成一句话，就是——"hire good people and give them room to do their jobs"，翻成人话：雇一批好人，然后给他们空间，让他们把活儿干好。

听起来没毛病吧？Chesky 也是这么想的，他照做了。结果呢？原文用的词是 disastrous——灾难性的。于是他只能自己摸索出一条更好的路，其中一部分方法，是去研究 Steve Jobs 当年怎么运营 Apple。目前看，这条自己摸出来的路奏效了：Airbnb 现在的自由现金流利润率，free cash flow margin，已经跻身整个硅谷最好的那一档。

更关键的是，当天在场的，是 YC 投过的最成功的一批创始人。Chesky 讲完，他们一个接一个地站起来说：一模一样的事，也发生在我身上。公司长大的时候，我被喂了同样的建议，而这套建议非但没帮到我的公司，反而损害了它。所以这不是一个人的偶然，这是一群人的共同经历。这就是白板上第一层——缘起：传统智慧是错的。

## 诊断：他们教的，是「经理模式」

那 Graham 最大的困惑就来了：为什么所有人都在给这些创始人喂错的东西？这些建议的人也不是坏人，是善意的。琢磨了一阵，他得出一个答案，也就是白板上往下这第二层——那些人教的，其实是「如何运营一家你没有创立的公司」。换句话说，是「如果你只是一个职业经理人、professional manager，你该怎么管这家公司」的方法。

这里有一句话，是这篇文章的题眼，我原样念给你听：

"There are things founders can do that managers can't, and not doing them feels wrong to founders, because it is."

翻成人话就是：有些事，是创始人能做、而经理人做不了的；不去做这些事，创始人会觉得哪里不对劲——而他这种不对劲的感觉，是对的，因为确实不对。你记住这句话，它是整篇文章的支点。这套职业经理人的做法——原文用了个词叫 m.o.，modus operandi，就是「惯常做法」——对创始人来说，效果差到「感觉像是坏掉的」。不是不好用，是像一个坏了的工具。

## 两种模式，在这里分岔

好，讲到这儿，这张图最重要的那个分岔点就出现了。Graham 说：本质上，运营一家公司有两种方式——founder mode，创始人模式；和 manager mode，经理模式。你看白板中间，这里分出了两条路。

到目前为止，连硅谷的大多数人，都默认了一件事：把一家 startup 做大，就等于要「切换到 manager mode」。做大 = 切经理模式，这被当成理所当然。但 Graham 说，我们其实能从两个地方，反推出「还存在另一种模式」：第一，是那些试过 manager mode 的创始人的沮丧——他们浑身不对劲；第二，是他们逃离 manager mode 的那些尝试，恰恰成功了。一个让你难受、另一个让你成功，这两件事加起来，就证明了对面还有一条路。

那这条路，我们了解多少呢？几乎为零。Graham 说得很直白：据他所知，没有任何一本书是专门讲 founder mode 的，商学院根本不知道它的存在。我们现在手上有的，只是一个个创始人各自摸索出来的实验，零散的。但他说，好在现在我们知道要找的是什么了——知道要找什么，就能开始搜寻了。他希望几年之后，founder mode 能像 manager mode 一样被充分理解。而现在，我们已经能猜到它会在哪些地方不一样。接下来，我就带你把这两条路分别走一遍。先走左边这条，manager mode。

## 左路：经理模式，把组织当黑箱

先看左边这条路。经理被教的运营方式，Graham 打了一个特别好的比方——它很像工程里的「模块化设计」，modular design。什么意思？你把公司的组织架构图想象成一棵树，你手底下的每一个直接下属，各自领着一棵子树。模块化的做法是：你把这些子树，当成一个个「黑箱」，black box。你只告诉你的直接下属「做什么」，至于「怎么做」，那是他们箱子里面的事，你不介入细节。

为什么不介入？因为在这套逻辑里，介入细节就叫「微观管理」，micromanaging——而微观管理是公认的坏事。所以经理被训练成：站在黑箱外面，下指令，然后放手。

"Hire good people and give them room to do their jobs."——雇好人，给他们空间。你看，这句话这样一描述，听起来是不是特别美好、特别有格局？但是，根据一个又一个创始人在现实里的反馈，这句漂亮话在实践中，往往变成了另外一句。Graham 原样写了出来：

"hire professional fakers and let them drive the company into the ground."

雇一群「专业的装模作样者」——professional fakers，就是那种特别会表演、特别会汇报、但其实不干实事的人——然后，任由他们把你的公司，一路开进沟里。你看左边这条路的尽头，就是翻车。同样一句「雇好人给空间」，理想里是放权，现实里是失控。

那为什么会这样？这里 Graham 观察到一个很扎心的主题，叫 gaslighting。gaslight 这个词，指的是精神操控——就是有人不断让你怀疑自己的判断，怀疑到你都觉得「是不是我疯了」。Chesky 的演讲里、以及事后的交谈里，Graham 都反复听到这种感觉：创始人觉得自己被两边同时 gaslight。哪两边？一边，是那些告诉他「你必须像个经理一样运营公司」的人；另一边，是当他真的照做了之后，那些为他工作的人。上面有人说你不对，下面有人让你怀疑自己，两头夹击。

正常情况下，当你周围所有人都不同意你的时候，你的默认假设应该是——是我错了吧。对不对？大多数时候这个默认假设是对的。但 Graham 说，这是极少数的例外之一。为什么是例外？他给了两个很硬的理由：第一，那些没当过创始人的 VC，本来就不知道创始人该怎么运营公司，他们没那个经验；第二——这句话他说得很不客气——C-level 高管作为一个群体，包含了这世界上最会撒谎的一批人。他在注释里补了一句更外交辞令的说法：资深的 C-level 高管，往往非常擅长一件事，叫 "managing up"，向上管理。懂这个圈子的人，不会否认这一点。所以在这一个特殊场景里，周围人都反对你，恰恰可能是你对。

好，左边这条路我们走完了，小结一下：manager mode 就是把组织子树当黑箱、只通过直接下属下指令、信奉「雇好人给空间」——听起来很美，但对创始人来说，它常常通向失控和翻车。现在，我们回到中间那个分岔口，走右边这条路。

## 右路：创始人模式，打破那个「封装」

右边这条路，founder mode。它具体包含什么，我们现在还说不全，但有一点已经非常清楚了：founder mode 一定会打破一条原则——「CEO 只应该通过他的直接下属，来跟公司互动」这条原则。左边那套黑箱、那套封装，在右边这里，被打破了。

一个最直接的变化：skip-level 会议。skip-level，就是「跨层级」——CEO 越过中间那一层，直接去跟下下级、跟一线的人开会。在 manager mode 里，这种事罕见到什么程度？罕见到人们专门给它起了个名字，好像它是个特例。而在 founder mode 里，Graham 预测，skip-level 会从「罕见的特例」变成「常态」。你看右边这条路，这个箭头，是从 CEO 直接穿透好几层，扎到底下去的。而且他提醒一句：一旦你放弃了「只通过直接下属」这条约束，你面前可选的排列组合，数量就极其庞大——玩法一下子就多起来了。

给你举一个具体的例子，一个特别生动的。Steve Jobs 当年，每年会办一次务虚会、一次 retreat，请的是他心目中「Apple 最重要的 100 个人」。注意这句话的关键——这 100 个人，并不是组织架构图上职位最高的 100 个人。你品一下这个区别：不是按官大官小请，是按「谁真正重要」请。你能想象，在一家普通公司里做这件事，需要多大的意志力吗？一个位子不够高、但被老板点名请去开最高级别务虚会的人，和那些位子很高却没被请的人——这里面得顶住多少组织政治的压力。可你再想象一下，这件事能多有用——它能让一家已经很大的公司，重新感觉像一家 startup。

Steve Jobs 想必不会年复一年地办它，如果它没用的话。但 Graham 说，他从没听说过第二家公司这么干。所以问题来了：这到底是个好主意，还是坏主意？Graham 的回答很诚实——我们仍然不知道。而「我们连这个都还不知道」这件事本身，恰恰说明了：我们对 founder mode，了解得有多么少。他在注释里还开了个很妙的脑洞：如果哪天连那些被政治主导的成熟大公司，都开始办这种务虚会了，我们甚至可以用一个指标来量化一家公司的「衰老程度」——就看它请去开会的那些人，在组织架构图上的平均深度有多浅。请的人层级越高、越浅，说明这公司越老。

## 更复杂，但更好用

那你可能马上会问：难道 founder mode 就是创始人什么都自己管、事无巨细全插手吗？不是的，这一点 Graham 讲得很清楚。他说，很显然，创始人不可能用「公司只有 20 个人时的方式」，去运营一家 2000 人的公司。那不现实。所以，总得有一定程度的授权，delegation。右路不是不授权，是重新划授权的边界。

那这个「自治的边界」落在哪儿、划得有多清楚？Graham 说，这大概会因公司而异；甚至在同一家公司里，它也会随时间移动——随着那些经理们逐渐赢得信任，as managers earn trust，创始人放手的边界就会往外挪。今天你还盯得紧的事，明年这个经理证明了自己，你就放了。所以你看，founder mode 是动态的、是活的。

正因为这样，Graham 给了一个很重要的判断：founder mode 会比 manager mode 更复杂。这是白板上这一层要记住的——右边这条路，不是更简单，是更复杂。因为它没有「一刀切当黑箱」那么省心，它需要你不断判断哪里深入、哪里放手。但是——他紧接着说——它也会更好用，work better。这一点，我们已经从那些一路自己摸索过来的创始人身上，看到了证据。更复杂、同时更好用，这两件事在这里是不矛盾的。

## 一个预测，和一个风险

Graham 还给了几个预测，我带你过一下，因为它们能帮你更完整地理解 founder mode 这个东西。

第一个预测，是乐观的：一旦我们真正搞清楚了 founder mode 是什么，回头会发现——早就已经有一批创始人，基本上走到那一步了。只不过在当时，他们那些做法，被很多人看作是「古怪的」，eccentric，甚至更难听的评价。换句话说，未来被追认为「founder mode 先驱」的人，在今天，往往正被当成异类。

第二个预测，就没那么乐观了，我觉得这一点特别值得你记住。Graham 说：一旦 "founder mode" 这个概念被正式确立、变成一个流行词，人们就会开始滥用它。怎么滥用？两种人。第一种，是那些连「本该授权的事」都授权不了的创始人——他们会拿 founder mode 当挡箭牌，「我这是 founder mode」，其实只是不肯放权。第二种，是那些根本不是创始人的经理——他们会决定「我也要像个创始人一样行动」。Graham 说，这或许在某种程度上也能管点用；但当它失灵的时候，会一团糟，messy。而相比之下，左边那套模块化的、黑箱的做法，至少有一个好处：它能限制住一个坏 CEO 所能造成的破坏——把伤害关在一个箱子里。所以这两条路，各有各的代价，你要知道自己在换什么。

## 收束：像 Steve Jobs，而不是 John Sculley

好，我们快讲到这张图的落点了。这里有一个特别奇妙的地方：Graham 说，「我们对 founder mode 仍然知之甚少」这件事本身，反而是令人鼓舞的。为什么鼓舞？你想想看——创始人们在几乎完全不了解这套方法、全靠瞎摸的情况下，已经做出了这么多成就。而且这一切，还是顶着一股「坏建议的逆风」做出来的，headwind of bad advice——一路上所有人都在给他们喂错的建议，他们还是干成了。

那么，文章的最后一句，也是整张图的落点，我原样念给你：

"Imagine what they'll do once we can tell them how to run their companies like Steve Jobs instead of John Sculley."

想象一下——一旦我们真的能教会创始人，像 Steve Jobs 那样、而不是像 John Sculley 那样运营他们的公司，他们会做出什么。这里补一个背景你就全懂了：John Sculley，就是当年在 Steve Jobs 之后接掌 Apple 的那位职业经理人 CEO——他，就是 manager mode 的化身。所以这句话在说的是：别再把创始人训练成 Sculley 了，去帮他们成为 Jobs。

我们把这张图从头再走一遍：最上面，缘起——传统智慧是错的，Chesky 照做，翻车；往下，诊断——他们教的其实是「经理模式」，是教你怎么管一家你没创立的公司；中间，分岔成两条路；左边，manager mode，把组织当黑箱、只通过直接下属、雇好人给空间，听着美、常常失控；右边，founder mode，打破封装、skip-level 成常态、Jobs 的百人务虚会，更复杂但更好用；最后落到一句话——像 Jobs，而不是 Sculley。这就是 Paul Graham 想立此存照的东西：一种我们才刚刚开始命名、却已经被证明有效的运营方式。它还没有书、没有商学院课程，但从今天起，你至少知道它长什么样了。我是你的 tutor，我们下一讲见。
