现在我们能说清 loss function development 到底特别在哪了。
大多数人用 Agent 造产品，几小时从零到上线。
但坑在长尾。
那些 spec 从没想到的边缘情况，只会在生产环境里一条一条冒出来。
你在日志里没抓到的，就由用户来报——这是发现 bug 最贵的方式。
Elvis 自己有个 Agent 叫 Zoe，每天盯着错误日志，看到新错误就派 Codex 去修，自动开 PR。
可就算这样，长尾还是要拖上几个月。
LFD 干的事，是把这条长尾快进。
如果你能提前拿到真实的期望输出，也就是"好"到底长什么样，而且是成规模的，那你就能在上线之前先做一次浸泡测试。
几百个边缘情况，在一次优化里一起砸向 Agent。
而不是一个季度一个季度地，等 bug 报告慢慢滴下来。
这里有个根本的区别。
测试套件是有限的，跑绿那一刻就结束了。
而一个一千条的评测集，卡在百分之九十五，是一个你只能不断往下降、却永远够不到底的目标。
为什么这很重要？
因为 Agent 会做出几百个你永远看不见的决定。
每一个决定，都要有个东西来裁决。
如果目标不是你写的，Agent 就自己挑一个——而它挑的，永远是最省事的那个。
