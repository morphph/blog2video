[SLIDE 1: cover] (0:00 - 0:30)

你把团队的编码规范、领域最佳实践，全塞进了系统提示词。

结果 Agent 答得还行，但一碰到具体项目约定，它立刻跑偏了。

问题不是提示词不够长——而是越塞越多，Context Window 迟早撑爆。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Google Cloud Tech 关于 ADK Agent Skill 设计模式的深度解析。

今天我们就来搞清楚：Agent 到底该怎么「装」领域知识——按需加载，用时再拿，不占Context。

[SLIDE 2: principle] (0:30 - 2:00)

先说一个反直觉的事实：Agent Skill 不是工具。

很多人以为 Skill 是一种特殊的 Tool，能执行代码、调用 API。

其实完全不是。Skill 是一个**知识包**——它不执行任何东西，它只是教 Agent「在这种情况下应该怎么做事」。

换句话说，Skill 是资格证书，不是瑞士军刀。厨师拿到米其林培训认证，才知道怎么用手边的刀——这里的"认证"就是 Skill，"刀"才是 Tool。

那 Skill 怎么做到按需加载的？Google ADK 给出了一个叫**渐进式加载**的三层架构：

第一层，L1 元数据——Agent 随时都能看到的书名目录，记录了每个 Skill 的名字和用途，写在 YAML 文件头里，永远可见。

第二层，L2 指令——真正的行为准则，写在 SKILL.md 的正文里，只有当 Agent 判断需要用这个 Skill 的时候才会加载进来。

第三层，L3 资源文件——references 目录里的参考文档、assets 目录里的模板，按需拉取，用完就放回去。

Agent 看到的永远只是一小块，但能做的事远超你的想象。这就是渐进式加载的价值：你把全套领域知识都准备好了，但 Context Window 从不会被撑爆。

[SLIDE 3: comparison_cards] (2:00 - 5:30)

好，三层架构讲完了。接下来看三种最常用的 Skill 设计模式。

**第一种：Tool Wrapper——纯知识注入。**

这是最简单的模式。你不需要写任何脚本或模板，只需要把领域规范放进去。

怎么运作的？SKILL.md 里定义触发关键词，当 Agent 识别到这个场景，就调用 load_skill_resource 去拉取 references/conventions.md——里面装着你团队的编码规范、框架最佳实践、领域潜规则。

Agent 一旦加载了这个文件，立刻变身领域专家。

关键洞察在这里：没有脚本，没有模板，只有纯知识。就像老员工带新人，不给你代码，给的是「在这个公司做事的规矩手册」。

适用场景：教 Agent 理解特定框架的约定、团队编码标准、行业特定术语。

**第二种：Generator——模板驱动输出。**

这个模式适合你需要 Agent 每次产出格式一致的结构化内容。

它把"怎么写"和"写什么"分开管理。SKILL.md 定义生成流程，然后从两个地方加载资源：references/style-guide.md 定义语气和格式规范，assets/report-template.md 定义输出的具体结构。

就像一份填空题卷子加上评分标准——两样都有，每次输出格式再也不会乱。

适用场景：生成报告、技术文档、配置文件，或者任何需要格式稳定的内容。

**第三种：Reviewer——可替换的评审标准。**

这个模式让 Agent 变成质量检查员。

用户提交代码或任何产出物，SKILL.md 定义三步流程：加载规则、应用规则、输出报告。Agent 从 references/review-checklist.md 拿到按严重程度分级的规则清单，然后输出包含评分和建议的审查报告。

这里最关键的一点是：**换一份 checklist，就能换一种审查类型。**

同样的流程，换一份清单就能从代码审查变成安全漏洞审计，再换一份变成可及性检查，或者文档质量评估。就像同一个检查员，拿不同的检查表，就能从食品安全检查员变成消防安全检查员。

[SLIDE 4: checklist] (5:30 - 6:00)

好了，三种模式梳理完了。你怎么判断自己的场景用哪个？

三个信号：

第一，你是不是经常需要 Agent 遵守某个特定框架或团队规范，但每次都要在提示词里重复写？——这是 **Tool Wrapper** 的信号。

第二，你的 Agent 需要产出结构化内容，但格式总是不一致？——这是 **Generator** 的信号。

第三，你需要对某类产出物进行重复性的标准评审，而且评审标准可能因场景而变？——这是 **Reviewer** 的信号。

这三种模式覆盖了日常 Agent 开发里百分之九十的使用场景。

[SLIDE 5: summary] (6:00 - 6:30)

最后总结一下今天的核心：

Skill 是知识包，不是工具。三层渐进加载——L1 元数据永远可见、L2 指令按需加载、L3 资源文件按需拉取——让 Agent 按需变身领域专家，而不是把所有知识堆进一个提示词里撑爆 Context Window。

你现在就可以做这一件事：给你下一个 ADK 项目创建第一个 Tool Wrapper Skill。新建一个 SKILL.md，写上触发关键词，把你团队的编码规范或领域最佳实践放进 references/conventions.md，让 Agent 随时按需加载。就这一步，比你再改一百遍系统提示词有效得多。
