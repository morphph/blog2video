不是锦上添花 · 是它能 work 的根本原因
讲到这里,如果故事就停在这——四个步骤里只剩第四步还没讲——你可能会想,最后一步无非是"让 AI 自我反思一下",老套路。
但这个 prompt 真正的设计含义,比"反思"狠得多。
Stanford 团队在自己的论文里,亲自标注了 STORM 的两个已知失败模式。
一个叫信源偏倚——模型在采样视角的时候,会不自觉地多采它训练分布里更熟悉的那一类声源。
一个叫事实张冠李戴——模型会把 A 视角里的事实,误装到 B 视角的论证里。
这两个 bug 不是猜的,是 Stanford 自己在 limitations 章节写明的。
第四个 prompt 就是精确对着这两个失败模式打的补丁。
它强制 Claude 给五条核心发现打可靠度分、找出自己最不自信的那一条、做偏倚检查指出哪个视角在综合里被过度代表、追问有没有一个第六视角被漏掉、
最后给整份简报打一个 Stanford 教授会打的分。
这是把别人论文里 limitations 章节的措辞,直接翻译成 prompt 设计的工程化案例。
它不是锦上添花。
它是这套方法之所以能在你的桌面上 work,而不是变成又一个被高估的 ChatGPT trick 的根本原因。
