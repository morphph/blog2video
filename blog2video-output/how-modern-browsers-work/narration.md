# 你以为浏览器是一个程序？它其实是几十个进程

## Hook

你以为浏览器是一个程序？打开任务管理器看一眼，你会被吓到。

你只开了一个标签页，可它背后悄悄站着五六个进程，互相之间还谁都不信谁。

这事是 Chrome 团队的工程师 Addy Osmani 讲透的。他写了一篇文章，把这个我们每天用上几个小时、却从来没真正看清过的黑盒子，整个拆开了。

而拆开之后我才发现，浏览器根本不是一个老老实实渲染网页的程序。它更像一座监狱。

每打开一个网页，它都默认这个网页是个潜在的罪犯，单独关进一间牢房，剥夺它读你硬盘的权利，还要押着它跑得飞快。

今天就讲清楚，这座监狱里到底发生了什么。

## 为什么一个标签页要拆成一群互不信任的进程

先说那个最反直觉的事实：浏览器不是一个进程，是一群。

Chrome 里有一个主进程，叫 browser process，它管地址栏、书签、菜单，管你眼睛看得见的那层壳。然后每开一个标签页，它就单独拉起一个 renderer process，渲染进程，专门跑那个网页的内容。

你可能会问，为什么这么麻烦？一个程序跑所有网页不是更省事吗？

因为早期的浏览器就是那么干的，结果一个网页里的脚本崩了，整个浏览器跟着一起死。所有标签页、你填了一半的表单，全没了。

拆成多进程之后，一个标签页崩溃,顶多就那一个标签页弹出「哦,不」,你重新加载它就行,旁边的标签页毫发无损。这就是为什么现在某个网页卡死,你还能淡定地关掉它。

但稳定还只是顺带的好处。真正的杀招在安全。

## 默认把每个网页当罪犯关进牢房

这里就要讲那个最狠的设计了。

渲染进程,也就是跑你网页代码的那个进程,被浏览器当成彻头彻尾的危险分子。它能算、能渲染、能把页面画出来,但它碰不到你的系统。

它想读你硬盘上的一个文件?不行。想开你的摄像头?不行。想开麦克风?还是不行。

这些动作全部被操作系统级的沙箱锁死。在 Windows 上靠 job object,在 Linux 上靠 seccomp 过滤系统调用。渲染进程被关在一个几乎什么权限都没有的笼子里。

它要做任何越界的事,必须老老实实向 browser 主进程打报告,由主进程审批。所以你注意过没有,网页想用你麦克风的时候,那个权限弹窗其实是浏览器自己弹的,不是网页弹的。是狱警在问你,要不要放这个犯人出来透口气。

为什么要这么偏执?因为浏览器干的是一件极度危险的事——执行陌生人的代码。

你每打开一个网站,就是在自己电脑上运行一段完全不认识的人写的程序。浏览器的安全模型,索性就假设这段代码已经被攻陷了。就算它真的坏,它也只能在沙箱里折腾,碰不到你的真实世界。

## 一个 2018 年的漏洞,逼出了整套牢房制度

可你也许会想,把每个网页关进自己的进程,是不是有点过头了?

还真不是过头,是被逼的。逼它的,是 2018 年那个叫 Spectre 的幽灵漏洞。

Spectre 证明了一件让所有人后背发凉的事:一段恶意的 JavaScript,可以利用 CPU 的推测执行机制,偷偷读到本来根本不该让它读的内存。

这意味着什么?如果你的网银和一个恶意网站,恰好被放在同一个进程里,那个恶意网站理论上就能把你网银页面在内存里的数据,一点一点摸出来。

这个漏洞最可怕的地方在于,它钻的是 CPU 硬件层面的空子,软件补丁很难根治。Chrome 团队想来想去,发现唯一靠得住的办法,就是干脆不让两个网站共享一个进程。

于是在 Chrome 67 那个版本,严格的站点隔离,site isolation,被设成了默认开启。每个站点关进自己的进程,谁也偷不到谁。

它狠到什么程度?连页面里嵌的跨站 iframe 都不放过。比如一个正经网站里嵌了一个来自 evil.com 的小框,浏览器会强行把这个小框踢到另一个独立进程去。所以你这一个标签页,背后可能正同时跑着好几个进程,各自为政,靠进程间通信协同。

截至 2024 年,百分之九十九的 Chrome 桌面用户,默认都开着这套隔离。Firefox 也用一个叫 Fission 的项目跟了上来。

但这份安全是要付钱的。

## 安全是用内存买来的

代价,就是内存。

每多一个进程,就要多加载一份 V8 引擎,多开一块独立的地址空间。进程越多,内存吃得越凶。站点隔离这一项,本身就让 Chrome 多吃百分之十到十三的系统资源。

Chrome「吃内存」的恶名,很大一部分就是从这儿来的。它不是写得烂,是它选择了用内存换安全。

所以你会看到,在低端设备上,比如安卓手机,Chrome 反而会把网络、界面这些服务合并回少数几个进程,省着点用。Firefox 干脆用一个八个进程的池子,而不是一个标签页一个进程,来折中。

没有完美方案。把网页当罪犯单独关押,牢房是真的安全,但牢房也是真的贵。这就是浏览器每天都在替你权衡的那笔账。

## 为什么同一个动画,有的丝滑有的卡成幻灯片

讲完监狱,我们走进牢房内部,看看一个网页是怎么被画到屏幕上的。这里藏着另一个你天天遇到、却从没想明白的现象。

为什么有的网页动画丝般顺滑,有的却卡成 PPT?大多数人以为是机器性能不行,是显卡太弱。错了。真正决定它的,是你改的到底是哪个 CSS 属性。

浏览器把一个网页变成像素,走的是一条流水线:先从 HTML 建出 DOM 树,再算样式,然后布局——也就是算清楚每个元素多大、摆在哪个坐标;接着绘制;最后合成,把一层层画面叠起来送到屏幕。

关键就在这条流水线上,有一个独立的角色,叫合成线程,compositor。它跑在渲染进程里,但故意和主线程分开。主线程是干什么的?跑 JavaScript、算样式、算布局,全是它。合成线程的活儿,是把已经画好的图层挪位置、叠起来,这些它直接交给 GPU 去做。

现在,魔法来了。

## transform 几乎免费,改宽高就要全页重排

如果你的动画,改的只是 transform 或者 opacity——也就是平移、缩放、透明度——那这个活儿,合成线程一个人就能干完。它根本不需要惊动主线程,不需要重新布局,也不需要重新绘制。它只是把一个现成的图层,在 GPU 上换个位置贴一下。

结果就是:哪怕你的主线程正被一段沉重的 JavaScript 卡得死死的,这个动画照样能稳稳跑满六十帧。因为它走的是一条完全绕开堵车路段的小路。

可如果你改的是 height、是宽度、是背景色呢?

那就麻烦了。改尺寸,意味着整个布局可能要重新算一遍——这个元素变大了,它周围的、它下面的所有元素,位置全得跟着挪。这叫重排。算完还得重新绘制。而这些重活,全压在主线程身上。

主线程要是同时还在忙别的,跟不上每秒六十帧的节奏,你看到的就是卡顿。

所以你看,同一个动画,改 transform 和改 top,性能可能差出好几个数量级。这根本不是显卡强不强的问题,而是「这一帧,你的动画能不能绕开那条最堵的主线程」的问题。

这不是要你去背「transform 比 top 快」这种口诀。背口诀没用。你真正该装进脑子里的,是那条流水线,和那个永远在替主线程分担压力的合成线程。心智模型有了,口诀自己就长出来了。

## 同一段 JS,跑着跑着会被偷偷换成机器码

还有最后一件,浏览器背着你干的事。它会把你的代码,偷偷升级。

你有没有遇到过,一段循环,跑头几次慢吞吞,跑久了反而莫名其妙变快了?这不是错觉。是 V8 引擎,在背后动了手脚。

Chrome 跑 JavaScript 用的是 V8。而 V8 执行你的代码,不是一条道走到黑,它准备了整整四个档位,越热的代码,爬得越高。

最底下一档叫 Ignition,解释器。代码刚进来,它先用这一档跑起来,图的就是一个快字——尽快让页面动起来,别让你干等。这一档慢,但启动代价极低。

可它一边跑,一边在悄悄记笔记:这个函数被调了多少次?这个变量,是不是一直都是整数?

## 越热的代码,爬得越高

一旦某段代码被反复执行,V8 就开始给它升级。

第二档叫 Sparkplug,基线编译器,把字节码快速翻成机器码,不做什么深度优化,图个比解释快一点。第三档叫 Maglev,2023 年才上的中间层,专门照顾那些「温热」的代码——跑得挺勤,但还没烫到值得动用最高档。Maglev 生成的代码,比 Sparkplug 慢上大概二十倍,但比最顶那一档快十到一百倍,刚好补上中间那段空白。

最顶上一档,叫 TurboFan。当一个函数被调用了上百万次,V8 就拿出这门重炮,用它一路记下的类型笔记,把这段代码编译成高度优化的机器码,该内联的内联,该省的检查全省掉。

所以你那段循环为什么越跑越快?因为它跑热了,被 V8 从解释器一路偷偷抬上了机器码的宝座。同一段你写的 JavaScript,字一个没改,在底层却被换了四种身体。

## 但升级是有代价的

可这套魔法,也有它的软肋。

JavaScript 是动态类型的语言。V8 之所以能优化得这么狠,是因为它大胆假设——「这个变量,我看它一直是整数,那我就当它永远是整数来优化」。

可万一你哪天,突然往这个变量里塞了个字符串呢?

假设崩了。之前那套精心优化的机器码,瞬间作废。V8 只能灰头土脸地退回到低优化的版本,重新来过。这个动作叫去优化,deopt。

这就是 JIT 的代价。一是预热——刚加载的代码必然先慢一阵,跑热了才快;二是,你的代码类型越不可预测,V8 越容易猜错,峰值性能就越难维持住。

天下没有白来的速度。浏览器替你跑得飞快,但它需要你的代码,别太善变。

## 浏览器不是一个程序,它是一座监狱

现在我们把三件事拼到一起看。

它把每个网页当罪犯,单独关进互不信任的进程;它在牢房内部,精心调度主线程和合成线程,决定哪一帧走廉价的快车道、哪一帧得全页重排;它还在背地里,把你的代码从解释一路升级到机器码,跑热了再换。

它在管理进程,管理线程,管理内存,管理权限审批,管理任务调度。

你发现没有,这些事——进程隔离、权限管控、内存回收、调度——本来全是操作系统该干的活。

所以浏览器到底是什么?它是一个跑在你操作系统之上的、第二层操作系统。一个迷你 OS。我们每天把它当成一个「应用」点开,可它内部干的,是一整套操作系统的本职工作。

而它做这一切,只为了在「执行陌生人代码」这件极度危险的事情上,既要够快,又要够安全。

你每打开一个网页,浏览器都默认它是个潜在罪犯——单独关进一个进程、剥夺它读硬盘的权利、还要押着它跑得飞快。浏览器不是一个程序,它是一座监狱。

## 下次打开浏览器,你会想起这座监狱

下次你按下那个 Shift 加 Esc,打开 Chrome 自己的任务管理器,一行行进程列在你面前的时候,你不会再觉得它「怎么这么吃内存」了。

你会知道,那每一行,都是一间牢房,关着一个浏览器默认不信任的网页。那些内存,是它替你买下的安全。

把浏览器从一个黑盒,变成一个你看得懂内部结构的迷你操作系统——这就是今天这趟拆解,最值钱的地方。

AI 世界很吵,精读一篇,胜过刷一百条。我们下期再见。
