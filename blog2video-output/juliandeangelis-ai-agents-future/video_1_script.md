# Video 1 Script: 给AI写代码，你写的需求才是真正的代码？

[SLIDE 1: cover]

AI帮你写代码，返工三次才搞定？

你让 Agent 帮你加个后台功能，结果它猜错了数据库、猜错了权限模型、猜错了 API 接口。改了三轮，还不如自己写。问题到底出在哪？

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是来自 Julián 的一篇 Twitter 长文，关于 Spec-Driven Development，规格驱动开发。

[SLIDE 2: principle]

先说一个反直觉的结论：在 AI 编程时代，你写的规格说明，才是真正的代码。

这句话什么意思？打个比方。你装修房子，不会让装修师傅看着毛坯房自己猜你想要什么风格吧？你得给施工图纸。图纸画得越细，装出来的房子越符合你的预期。

Julián 提出的 SDD，也就是 Spec-Driven Development，核心理念就是这个。传统开发流程是人写代码，但现在 Coding Agent 可以帮你生成代码。那人类的核心工作变成了什么？写规格说明。

这套方法分四个阶段：Specify，定义需求和边界。Plan，设计架构和技术选型。Tasks，把计划拆成可执行的具体任务。Implement，Agent 执行，写代码、测试、部署。

关键洞察是：从第一步到第四步，模糊性在逐步递减。整个 SDD 的目的，就是在写代码之前，把不确定性彻底消灭。

[SLIDE 3: comparison_cards]

到底模糊性会带来多大的问题？我们来看一个对比。

你给 Agent 一句模糊指令："给后台加个管理功能。"Agent 被迫在四个关键问题上瞎猜。用哪个后台系统？调哪个 API？用什么权限模型？错误处理怎么做？结果就是：猜错用户权限、数据模型对不上、架构冲突，反复返工。

换成一份规格说明呢？你明确写出四个要素：接口必须满足幂等性要求，仅管理员可以访问，只能调用内部 API，请求和响应要有 JSON Schema 定义。Agent 拿到这份规格，一次就能写对。

这就像点外卖。你说"随便来一份"，厨师大概率猜错。但你说"要一份微辣的宫保鸡丁、米饭少一点"，出错的概率就低得多。模糊性才是 AI 编程真正的瓶颈。

[SLIDE 4: checklist]

那具体怎么做？下次用 AI Agent 写代码之前，花十分钟检查这四项。

第一，架构决策写清楚了吗？比如明确指定用 NextJS 的 App Router，而不是让 Agent 自己猜。第二，数据模型定义了吗？比如告诉 Agent 复用已有的 UserEntity，只需要加一个 provider 字段。第三，权限模式明确了吗？比如指定遵循项目里的 auth-rules 模式。第四，性能约束量化了吗？比如要求登录接口响应时间小于一百毫秒。

原文里展示了一个惊人的对比。没有规格时，Agent 连"这到底是 NextJS 还是普通 React"都搞不清楚。有规格时，NextJS 组件结构一致、auth-rules 模式集成成功、性能测试通过、连 Figma MCP 设计稿都能匹配上。

[SLIDE 5: summary]

总结一下。AI 时代，你写的规格说明就是你的代码。规格越清楚，Agent 写得越好。记住 SDD 四步法：Specify 定义需求、Plan 设计架构、Tasks 拆分任务、Implement 交给 Agent。

下次写代码前，先花十分钟，把架构、数据模型、权限和性能约束写进规格里。把模糊性在动手之前消灭掉。

不过你可能会问：规格到底要写到什么程度才够？写太少不行，写太多又浪费时间。下一集，我们会讲 SDD 的三个层级，帮你找到那个最适合你的平衡点。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
