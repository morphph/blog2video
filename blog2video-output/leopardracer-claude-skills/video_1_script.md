# Video 1: Anthropic刚发布的Skills功能，为什么说它比提示词强10倍？

[SLIDE 1: cover] (0:00 - 0:30)

Anthropic 刚发布了 Claude Skills 2.0。一个 Skill 的元数据只消耗几十个 Token，但它能让 AI 永远记住你的工作流程。

你每天是不是还在反复给 AI 解释同样的规则？今天这篇文章，可能会彻底改变你使用 AI 的方式。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Anthropic 官方关于 Claude Skills 的工程指南。

[SLIDE 2: principle] (0:30 - 2:00)

先说一个场景你肯定熟悉。你跟 AI 说："帮我写一份周报，用公司的格式。"AI 说好的，然后给你一份完全不对的格式。你又解释一遍，它改了，但下次对话又忘了。

这就像你招了一个实习生，每天早上来都失忆。你得从头教一遍公司规则、代码规范、文档模板。教了一百遍，它还是记不住。

Claude Skills 要解决的就是这个问题。它的本质是什么？就是给 AI 写一份标准操作手册，也就是 SOP。你把工作流程写进一个叫 SKILL.md 的文件，AI 以后每次遇到相关任务，自动按照这个手册执行。教一次，永远会。

但这里有一个很妙的设计。SKILL.md 不是一股脑全塞进 AI 的记忆里。它用了一种叫 Progressive Disclosure 的三层架构。第一层是 YAML 元数据，相当于手册的目录，只占几十个 Token。第二层是正文指令，只在触发时才加载。第三层是外部引用文件，处理更细节的内容。

这意味着什么？你可以装很多个 Skill，而不会拖慢 AI 的性能。这就像公司有一整面墙的操作手册，但员工不需要每天把所有手册都背一遍，只在接到具体任务时才翻开对应的那本。

[SLIDE 3: comparison_cards] (2:00 - 3:30)

那 Skills 跟 MCP 到底是什么关系？很多人搞混了。

用一个厨房的比喻来说。MCP 是专业厨房，它提供刀具、烤箱、食材，定义的是你能做什么。而 Skills 是菜谱，它告诉你该怎么做，先放油还是先放盐，火候多大，步骤是什么。

原文作者分享了一个真实经历。他最初搭建了 MCP 服务器，以为给 AI 提供工具就够了。结果发现，AI 有了工具却不知道按什么流程使用。引入 Skills 之后，MCP 负责能力，Skills 负责流程，两者配合才完整。

再说说 SKILL.md 怎么写。官方建议控制在 500 行以内。超出的部分拆成独立的引用文件。结构很简单：上面是 YAML Front Matter，定义元数据；下面用 Markdown 写具体指令。

指令的自由度也有讲究。文本类任务给高自由度，让 AI 自己发挥。流程类任务用伪代码，给中等自由度。关键操作就写死具体脚本，零自由度。就像导航，有时候你让它自己选路，有时候你必须指定走哪条。

[SLIDE 4: checklist] (3:30 - 4:20)

那怎么创建你的第一个 Skill？Anthropic 提供了一个叫 Skill-creator 的工具，本质上是一个帮你写 SOP 的老师傅。

流程只有五步。第一步，告诉它你想要什么技能。第二步，它自动生成 SKILL.md 草稿。第三步，用测试提示词实际运行一遍。第四步，评估结果，提出改进。第五步，重复迭代，直到满意为止。

有几个关键原则。只写 AI 不知道的东西，比如你公司特有的规则和流程。不要写通用知识，那是浪费 Token。另外，Anthropic 官方有一个 Skills 市场，提供现成的插件，包括处理 Excel、Word、PPT 的文档技能，还有可视化设计等社区技能。

[SLIDE 5: summary] (4:20 - 5:00)

总结一下。Claude Skills 的本质不是让 AI 变得更聪明，而是让你的工作经验变成可复用的资产。通过 SKILL.md 的渐进式披露架构，几十个 Token 的元数据就能管理整套工作流程，装再多技能也不影响性能。

给你一个具体的行动建议：打开你的项目，在 .claude/skills 目录下创建第一个 SKILL.md，把你每天重复最多的一个流程写进去，用 Skill-creator 迭代三轮，你会发现 AI 真的变成了你的老员工。
