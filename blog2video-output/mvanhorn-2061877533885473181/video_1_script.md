# 22 招让你一年内成为重度 Agent 用户

[SLIDE 1: cover] (0:00 - 1:15)

"Agentic Engineering" 这套打法，最近三个月在 X 上从一个新词变成了一种新工种——一个 Agentic Engineer 和一个普通工程师的差别，不是会用多少 AI 工具，是同时能指挥 5 个 Claude 一起工作。Matt Van Horn 是这条线最直接的代表，3 月版 91 万阅读，6 月升级版把整套方法论又推前一步。22 招。他靠这套打法这一年 ship 了 27K star 和 4K star 两个开源项目，自己说："高中之后我没发过任何有人在乎的软件，是这套工作流让我重新开始 ship 东西。"今天挑最反直觉的 5 招聊透。

[SLIDE 2: principle] (1:15 - 3:00)

先讲第一条颠覆。它颠覆了大多数人对 plan.md 的理解。

大家以为 plan 是写给自己看的——理清思路、做备忘、留个记录。但他的用法完全相反。他每个新想法落地的第一个动作，就是让 Agent 写一份 plan.md，然后他几乎从来不读这个 plan。

他的原话有点扎心——"plan 是给 Agent 的作业，不是给你的。"

那为什么还要强迫 plan 存在？因为他观察到：有 plan 的 Agent 交出的是成品，没 plan 的 Agent 偷工减料、提前收工。Plan 这个动作逼着 Agent 承诺一种方案、把验收标准写清楚、然后机械地命中。所以 plan 的真正作用是约束 Agent 的牢笼，不是给人类阅读的文档。

[SLIDE 3: checklist] (3:00 - 4:20)

那如果他不读，怎么知道方向对？两个动作——遇到不放心的地方，直接在会话里追问一句"等等，为什么用这个方案？"或者一句"eli5 this plan"，让 Agent 用一段话把整个 plan 解释清楚。他不会去逐行读三百行 markdown。

这一个观念翻转，把传统开发的 80 比 20 彻底倒过来了。过去是 80% 写代码、20% 想，现在是 80% 都灌到 plan 里，写代码这个动作变成机械执行。

[SLIDE 4: image] (4:20 - 6:30)

他还把这套 plan 流程用到了非编程工作上。文章里举了一个具体例子。他跟一位前 Google Ventures 的研究合伙人见面聊一个商业难题，对方让他读自己写的一本书，免费 PDF。换成以前，他会随便翻翻就过去。

这次他把那本 PDF 加上两个小时的会议转录都丢给 Agent，对它说："帮我做一个 plan，规划你打算怎么读这本书、怎么挖这份转录、最后怎么产出一份我能用的文档。先不要写文档，写文档是后面的工作，现在只要一份'怎么写文档的 plan'。" Agent 花了 45 分钟做出了一份他形容为"史诗级"的 plan。

他说这是让 LLM 不偷懒的最佳技巧——直接问交付物它会偷工减料，但你让它先 plan 出一个生产流程再执行，它每次都会跑深度版本。

[SLIDE 5: principle] (6:30 - 8:10)

第二个反直觉点是 YOLO 模式。

Claude Code 默认每个操作都要你点 Y 确认，单 session 这是合理的安全设计。但他的日常工作状态是同时开 4 到 6 个 cmux tab，每个 tab 一个独立 session——一个在写 plan，一个在 build 另一个 plan，一个在跑 last30days 做调研，还有一个在修他刚才测试时发现的 bug。

6 个 session 并行的时候，你根本没办法挨个去点确认。所以他在配置文件里直接打开 bypassPermissions，永不询问。这不是任性，是这套工作流的物理前提。

[SLIDE 6: image] (8:10 - 10:00)

但单纯打开 YOLO 还不够。失去逐一确认带来的最大问题是——你不知道哪个 session 进展到哪了。所以他配了一个让我觉得整篇里最妙的补偿机制：Claude Code 有一个叫 Stop 的 hook，会在每个 session 完工的瞬间触发，他在这个 hook 上挂了一行命令——播放 Mac 系统自带的提示音 Blow.aiff。

人离开屏幕去倒咖啡，听见声音回来，就知道某一个 session 刚刚完工。原本"逐一确认"提供的反馈通道，被换成了一个声音通道。这才是他能在物理上并行跑 6 个 session 的真正基础。

他还有一个把这种"打开 YOLO"做到更激进的细节——他直接把终端的默认启动命令改成了 claude，而不是 zsh。开一个新 tab，直接进入 Claude Code 会话，连 cd 切目录的步骤都省了。他的原话很有意思："开一个新 session 的成本变成一个按键的时候，你会启动远多于之前的 session。"

还有一个值得一提的细节——他帮一个朋友配置 Claude Code 打开 YOLO 的时候，Agent 自己主动劝朋友别开。他说："你得对它强硬一点。"

[SLIDE 7: principle] (10:00 - 11:30)

第三条非常反直觉，是关于 Codex 的。

他每天有大量代码是 Codex 在写，但他几乎从来不打开 Codex 的命令行。表面上看，Claude Code 和 Codex 都是编程 Agent，订阅两套像是浪费钱。他的视角不一样——他订阅了两个 200 美元的月度 plan，Claude Code Max 一个，Codex Max 一个。他说这是字面意义上的"第二台引擎"。

分工是这样的：Claude 负责规划和品味判断，Codex 负责重型 build。两个引擎都拉到推理最高档 reasoning xhigh。Claude 的 fast mode 他特意关掉，因为在 200 美元 Max 之上还要按 token 额外收一次钱，他认为不划算。Codex 的 fast mode 一直开着。

[SLIDE 8: comparison_cards] (11:30 - 13:00)

那他怎么把活从 Claude 派给 Codex？他给自己设计了三个路径，全部留在 Claude 这一侧——一个是 Codex 提供的 IDE 扩展，他在 Claude 会话里直接派任务给 Codex，结果出来后选择是否应用；另一个是 Compound Engineering 插件里的 --codex 参数，让"执行"这一步直接走 Codex；第三个是他自己的 Printing Press 项目，生成新 CLI 时在 prompt 末尾加一个 codex 词，build 就交给 Codex。

他从不离开 Claude 这个会话。Claude 是大脑，Codex 是肌肉，两个 200 美元的订阅就是他买的两台引擎并联运行。他原话提到一个补充——有些朋友的搭法刚好反过来，Codex 负责 build，Claude 负责 review，看你哪一边的 taste 你更信任。

[SLIDE 9: principle] (13:00 - 14:30)

讲到这里你可能还会觉得这是程序员玩具升级。但这篇长帖真正的破圈时刻，在第 20 个 hack。

他和合伙人做了一个项目叫 Printing Press——一组专为 Agent 设计的命令行工具，把现实世界的服务一个一个包装成 CLI。配套一个叫 Agent Cookie 的东西，负责把你浏览器里的真实登录状态交给 CLI，让 CLI 以"你"这个身份去办事，不用粘贴密码、不用重新登录。

这一套接管了他一个真实的下午——

[SLIDE 10: checklist] (14:30 - 16:30)

孩子十分钟后要上车，他对 Agent 说一句"preheat the car to 72"，Tesla CLI 触发，车在他们走出门之前已经热好了 22 度。

老婆说 Costco 配送要加啤酒，他一句"add Corona to Costco on Instacart"，Instacart CLI 直接把酒加进购物车。

晚上有场球赛，他不想自己刷比分，让一个 session 帮他盯着 ESPN，只在比分接近时给他一个通知。整场比赛他没主动刷过一次手机。

孩子暑假要订机票，他在足球场边看孩子踢球的时候，让 Alaska Airlines CLI 拉所有可能航班的机票、查 Atmos 里程余额、再把全部数据扔给 /ce-plan 让 Agent 出一份订票策略——最便宜的日期、最划算的换乘组合、什么时候必须下单的提醒。从足球场边订完。

[SLIDE 11: quote] (16:30 - 17:40)

他说这才是 Agentic Engineering 离开终端的瞬间。不是 AI 帮我写代码——是 Agent 帮我办杂事、看球、热车、订机票，全部在我做别的事情的时候同步发生。

这一节是整篇长帖里最有"破圈感"的部分。前 19 个 hack 都在终端里打转，听起来像程序员玩具升级。但当 Tesla 预热、Instacart 加啤酒、ESPN 比赛提醒、Alaska 机票这些事情变成一句话指令时，整套体系突然有了非编程的意义。

[SLIDE 12: quote] (17:40 - 19:00)

最后这一段是整篇文章最让我尊敬的地方。

他在第 21 节标题里直接写了一个词："The Honest Part: AI Psychosis"。

他说：Agent 本来是替我们干活的，结果我所有朋友都在自己生命里前所未有地拼命。这不是缺乏休息的问题，是上瘾的问题。用 Agent 造东西是有史以来最好玩的电子游戏，这个反馈回路太好了。

他认识一些他真心担心的朋友——被"能造任何东西"这件事点燃，然后什么别的都不做。Launch 出去没用户，但还在继续 build。陷阱不是发布失败，是你消失在了建造里、丢掉了身边的人。

[SLIDE 13: checklist] (19:00 - 20:10)

他建议三件事——休息，去摸摸草。跟你爱的人聊天。问一问你做的东西到底有没有人要。如果答案是"只是为了你自己"，那也可以，他说自己造过最好的东西里有几样从头到尾就只给自己用。

我觉得这一节比前 20 个 hack 加起来都重要。所有那些技巧让你在一年里从"高中之后没发布过任何有人在乎的软件"变成"今年发了三个开源项目、其中一个 27 千 star"——他自己的转变就是这种节奏。但代价是你身边的人。

[SLIDE 14: principle] (20:10 - 21:40)

回过头看，这 22 招里我最想留住的不是任何一招的具体配置，是这个整体形状——

传统开发是 80% 写代码、20% 规划。他的工作日是 6 个并行 session、人只贡献品味和方向、Claude 做计划、Codex 做 build、CLI 顺手接管开车买菜订机票。

Agent 不是更强的 IDE。Agent 是你工作流和生活流之间那扇被拆掉的门。门拆掉之后你能多做很多事，但也再没有一个明确的下班时刻。

整篇长帖最值得记住的一句话，是他对自己工作角色的重新定义——"当你跑 6 个 Agent，你的工作不是干活，是当那个信号。Agent 提供量，你提供品味、方向、和反馈纠偏。Agent 是手，你是大脑。"

[SLIDE 15: summary] (21:40 - 22:30)

如果你只能从这 22 条里挑一条今天就做的，挑第二条——做计划，但不要读计划。让 Agent 写 plan.md，你只看一行标题，让它直接开干。如果有疑问就在会话里追问 "TLDR" 或 "eli5"，不要去逐行读 markdown。这一个动作改变之后，你会发现自己再也不想回去做"那个手动批准每一步的人"。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
