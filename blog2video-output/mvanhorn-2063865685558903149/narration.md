# 两百万人转的那句话，没人会解释

## Hook

这周你的时间线大概率被同一句话刷屏了——"别再 prompt agent 了，去设计 prompt agent 的 loop"。Peter Steinberger 发的，单条 220 万阅读。底下追问"那这玩意儿实战长什么样"的回复，被一句话压成了表情包——"除了他和 Boris，没人知道。" Matt Van Horn 这周做的事就是把这句话拆开。今天只聊一件事——为什么两百万人转的口号，没人会解释。

## 两百万阅读 + 一句"没人知道"

这条 tweet 我在 timeline 上至少看到了三十次。每个转的人都像在传递一个新共识。但只要你点进底下的回复区，立刻就崩了。

Varadh Jain 问了一个最朴素的问题——"那这个东西在实战里到底长什么样？" 最高赞的回答只有六个字，原话是 "nobody knows but him and boris"。除了 Steinberger 自己和 Boris Cherny，没人能说清。

这就是这周 AI Twitter 的真实状态。讨论的体量和理解的清晰度严重脱钩。两百万人转一句话，不是因为他们懂了，是因为转这条话本身是一种身份——我在最前沿。

Boris Cherny 是 Claude Code 的作者，Anthropic 的 MTS。他和 Steinberger 是讨论里被默认"懂的那一边"。但他们说的 loop，和底下转发的人理解的 loop，根本不在一个层上。

要把这件事讲清，得先把 loop 这个词的家谱摊开。

## Loop 不是新词，是一个被嵌套了五层的旧词

我把这周看到的所有讨论按时间顺序排了一下，整理出五层。听完你就知道吵架的人各自站在哪一层。

第一层是 2022 年的 ReAct 论文。学术界的 while 循环——模型推理一下、调一个工具、读一下结果、再推理。一个模型、一个 loop，人在旁边盯着。这是 loop 这个词最早的技术含义。

第二层是 2023 年的 AutoGPT。第一次让 agent 自驱循环——给它一个目标，它自己 prompt 自己。这个版本最有名的不是它能干什么，是它经常陷在死循环里干不动。整整两年人们说"agent 是玩具"，根源就在这次失败。

第三层是 2025 年 7 月 Geoffrey Huntley 那篇 ralph。他的发明朴素到让人尴尬——一行 bash 把同一个 prompt 文件反复 pipe 给 agent。但真正的新东西是纪律——每一轮迭代都把上下文重置回固定的几个锚点文件，不让对话越长越脏。Huntley 用这个 loop 花了不到 300 美元，搭出了一整门编程语言。

第四层是 2026 年春天。Codex 和 Claude Code 几乎同时上线了 /goal 命令——把 ralph 那套自驱循环产品化，加了一个小验证模型判断"完成没"。

第五层就是 Steinberger 和 Boris 现在说的那个 loop。它真的新，不只是改名。

四件事变了。Loop 自己变成了工作单元，不再是任务。Loop 开始监督其它 loop，并发地、按调度地跑。人类启动这个动作被调度器替代了——loop 不再等你按回车，它在基础设施时间里跑。最后一件——状态变得 durable，存进 git，崩了能恢复，因为这种 loop 默认你的笔电是关着的。

Ralph 假设终端开着，2026 版假设终端关着。

所以那条最接近正确答案的回复，是一个 ID 叫 Trash Panda 的人写的——"这不是 ralph 或 /goal 的 loop，那已经老掉牙了。这是某种持续编排的循环，去监督别的线程和别的 agent。" 他一句话点穿了——单 agent 的 ralph 是老东西，多 agent 互相监督的编排 loop 才是新的那层。

## Boris 把这个职业升了一格

Boris 自己在 6 月 2 号 WorkOS 的活动上，给过 loop 一个干净的定义。他说他现在不再 prompt Claude 了，他写 loop，那些 loop 在 prompt Claude，决定要做什么。他原话是——"我的工作是写 loop。"

这句话听起来像炫技，但他给了一个让人没法反驳的收据。过去三十天，他对 Claude Code 这个项目的贡献，100% 是 Claude Code 自己写的。他本人 land 了 259 个 PR。他在 2025 年 11 月就删掉了 IDE，再没打开过。

他描述的状态是这样的——几百个 agent 在背后读他的 GitHub、他的 Slack、他的 Twitter，自己决定下一步要构建什么。

我个人的感受是，被 timeline 普遍误读的不是"prompt engineering 死了"这件事——是这件事的真正分量。Boris 没有说工程师没用了。他明确说了相反的话——决定要造什么、跟客户聊、协调团队这些事还是要人做，而且好工程师比以往更重要。变化的不是工程师消失，是这份工作整体被往上抬了一格——从写代码，升到写"写代码的那个东西"。

## "Cron 改个名而已"——这句吐槽是对的吗？

讨论区里最让我笑出声的一句吐槽只有四个字，原话是 "Cronjobs have funny re-branding rn"——cron 最近改名改得真热闹。

这句话戳到了一个真问题。所以我想认真回它一下，不打哈哈。

它说对了一半。调度那一层就是 cron。Boris 自己的 loop 跑在 cron 上。Claude Code 里的 /loop 命令底层也用 cron。如果你对 loop 的定义就是"按时间跑一个东西"，那这事我们 1975 年就发明了，可以散了。

但 cron 从来没有的，是中间那一段。Cron 跑的是固定脚本。Loop 跑的是一个模型——它看当前状态，决定下一步做什么，做完之后判断有没有效果，再决定要不要继续。决策权在模型手里，不在你预先写好的 if-else 里。

把这一层抠出来再叠加——一个 loop 调度并监督其它 loop，所有 loop 共享一份持久化的状态——这就是 cron 表达不了的东西了。

最诚实的描述不是"loop 是新魔法"，也不是"loop 是 cron 重命名"。准确的说法是——loop 等于 cron 加上一个会做决定的脑子。所有真正有意思的工程，都在这个脑子周围搭——怎么让它别跑飞、跑偏、跑死。

## 一行起手式 + Boris 的五条 tip

讲到这你可能在想，那我怎么开始。其实入口只有一行。

Claude Code 的 /loop 命令已经上线，Boris 自己给的起手式可以直接抄过来改名词——"/loop babysit all my PRs. Auto-fix build issues, and when comments come in, use a worktree agent to fix them." 翻译过来就是——盯住我所有的 PR，构建挂了自动修，有评论进来用 worktree agent 处理掉。

Boris 几天后又发了五条让 Opus 自驱跑几小时甚至几天的 tip。前四条都是工程化标配——权限开 auto 别老来问、用 dynamic workflow 编排成百上千个子 agent、用 /goal 或 /loop 推它跑到完成、把任务挪到云上跑可以关笔电。

但真正决定能不能信任这个 loop 的，是第五条——Claude 必须有办法端到端验证自己的工作。

这一条 hype 跳过去了，实战的人盯死了。一个写完代码但没办法判断自己写对没的 loop，本质就是一台高速生产"看起来自信的错误"的机器。Trash Panda 提到的那种持续编排的真实样子，1 月份 Steve Yegge 已经开源出来了，叫 Gas Town——20 到 30 个 Claude Code 实例由一个 Mayor agent 协调，巡逻 agent 跑持续 loop，状态全存进 git，崩了能恢复。

而所有人更焦虑的另一面，是有人在做 commit 级的验证。一个叫 DanKornas 的开发者在做一个工具叫 roborev，后台对每个 commit 自动 review，把发现回喂给 agent，趁上下文还热的时候纠正。

我自己看完这一层的体会是——loop 这种范式真正的天花板，从来不在它跑得多快，在它能不能信任自己的输出。

## 钱包反转：模型几乎免费的时候，loop 才是最贵的东西

讨论里最锋利的一句反讽，来自一个完全没有名气的工程师，ID 叫 rohit_jsfreaky。

他说——"我今年 ship 的每一个所谓 AI agent，都是一个 for 循环、一次 LLM 调用、加一段 try/catch 包住 JSON 解析。它唯一'agent'的地方，是月底那张 Anthropic 的账单。"

这条话刺心的地方在于它不是段子。这周最具体的一张账单——Uber 给每位工程师 Claude Code 和 Cursor 各设了 1500 美元每月上限，原因是四个月就烧光了全年的 AI 预算。

当模型几乎免费写代码的时候，钱就转移到跑 loop 的那一层。另一个 ID 叫 runes_leo 直接定性——"AI 编程里最贵的事，已经不再是写代码，是管理 agent loop。"

而 loop 在生产里最让人恐惧的失败模式，根本不是写错——是不会停。一个叫 cv_usk 的人说——"没有护栏，你会拿到无限循环和比预算高一个数量级的账单。"

所以这周我看到的所有严肃 loop 文章，全部收敛到同一组三件套护栏——最大迭代数、no-progress 检测、token 或者美元的预算上限。

Loop 浪漫版的故事是——你写 loop，几千个 agent 一夜之间把你的公司搭出来。生产版的故事是——你写 loop，然后你大部分时间在确保它能停下来。

Gartner 现在把 agentic AI 放在炒作峰值，真正部署的组织只有 17%。Timeline 上的喧闹和账本上的收据之间，有一道很大的缝。

## Loop 是水管，skill 才是水

Matt 看完这一周之后，给了一个我觉得是整条讨论里唯一一个把 Steinberger 和 Boris 缝起来的判断。

Loop 是水管。真正的资产，是 loop 里调用的那个 skill。

Steinberger 那条 tweet 火，但他另一条没那么火、更耐用的主张是——任何你做超过一次的事，把它变成自动化的 skill；任何你做过的难事，事后写成 skill，下次就免费。

一个 loop 里头如果没有可复用的 skill，本质上就是一个 while-true 套着一个陌生人——每轮你都让一个完全没记忆的实习生从头来一遍。一个 loop 调用一组被命名、被测试、被反复打磨过的 skill，才是会复利的系统。

Reddit 上 r/ChatGPTCoding 一个用户写得最准——"很多人在 Twitter 上翻白眼，但我耳朵立起来了。"

WTF is a loop 这个问题的真正答案，不是关于 prompt engineering 死活的热门 take。是这样的——别再做那个待在 loop 里的人。Loop 写一次，给它能调的 skill、给它能自检的反馈、给它能停下来的上限，让它跑在 cron 上，你去想下一步要造什么。

Steinberger 和 Boris 在说同一个东西的两面——一边强调外壳，一边强调装填物。真懂的人是已经搭过一个的人。而本月起，搭它的入口，是一个 slash 命令。

## Closing

我把这周的几条线压成一句话——loop 不是新词，是被嵌套了五层的旧词；新一层的实质朴素到讽刺，cron 加一个会做决定的脑子，配上让它停下来的护栏。两百万人转那句口号，是因为转它本身就是入场券——而真去搭过的人，已经在为 skill 写第二个版本了。

入口便宜得像玩笑——一行 /loop，加一组你认真写过的 skill，加三件套护栏。剩下的事情交给基础设施时间。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
