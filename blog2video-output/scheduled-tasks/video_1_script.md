[SLIDE 2: principle] (约0:30 - 约2:00)

其实你不用自己盯。

Claude Code 内置了一套调度系统，可以让 AI 在后台帮你轮询、提醒、重复检查。你去干别的，它替你守着。

用法极简单。输入 `/loop 5m` 加上你要问的问题，Claude 就会每 5 分钟自动跑一次——部署结束没？测试过了没？有没有新的报错？

不需要额外安装任何东西，这是 Claude Code 的内置功能。

背后用的是 Cron 表达式。Cron，就像给任务设定闹钟：几点、哪天、每隔多久，用 5 个数字描述一个时间规律。你不用手写 Cron，Claude 自己生成，你只管说"每 5 分钟查一次"就行。


[SLIDE 3: comparison_cards] (约2:00 - 约3:30)

这里有几个细节值得注意。

**`/loop` 默认间隔是 10 分钟。** 你不写时间，它就每 10 分钟跑一次。你也可以写 `30m`、`2h`、`1d`，单位都支持。有一点：如果你写秒，比如 `30s`，它会自动向上取整到分钟，因为 Cron 的精度就是分钟级。

**每个会话最多 50 个定时任务。** 同时跑 50 个任务，够用了。

**还有一个隐藏的工程细节，很多人不知道：** 定时任务有一个"抖动"机制。每个任务触发时，会被随机延迟最多周期的百分之十，最长不超过 15 分钟。

比如你设了每小时一次，它不会整点准时触发，而是会在整点之后随机晚几分钟。这是防拥塞设计——就像地铁站出口，如果所有人同时冲出来，一定堵死，自然分散才顺畅。

这个延迟是基于任务 ID 计算的，固定不变，同一个任务每次都是同样的偏移量。


[SLIDE 4: checklist] (约3:30 - 约4:30)

但有一件事你必须清楚：这些任务是会话专属的。

像便利贴，贴在屏幕上很方便，但你关掉窗口，便利贴就消失了。没有持久化，重启之后什么都没了。

另外，循环任务有一个 3 天的自动过期机制。创建 3 天之后，它会自动失效并删除。这不是 bug，是故意设计的——避免遗留任务一直跑。

所以定时任务适合什么场景？

- 等待 CI/CD 构建结果，用 `/loop 5m` 轮询
- 等待某个 API 限流解除，每 15 分钟检查一次
- 临时提醒自己：45 分钟后记得推分支
- 监控长时间运行的脚本有没有异常

不适合什么？永久性的监控、跨会话的定期任务——那些得用系统级的 Cron 或者其他工具。
