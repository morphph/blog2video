# Insight Memo: The Ten Commandments for Building Product

## title_zh
AI 让造产品更容易，也让你更容易骗自己

## one_sentence_thesis
在 AI 大幅降低构建成本的今天，真正决定产品成败的不再是执行力，而是你是否愿意承受与现实的第一手接触——所有看起来像进展的东西，大多数是在原地踏步。

## why_this_video_exists
这条视频提供了一个 AI 时代的反直觉警告：当 AI 把"造东西"的成本降到近乎零，所有经典的自我欺骗手段——提前搭好百万用户架构、让 AI 写好正确架构再找客户、用代码行数衡量进展——都披上了"效率"和"生产力"的外衣，变得更难识别。这篇文章的作者是一线创业工程师，用三次真实失败（不是事后复盘的成功故事）把这些陷阱一个个拆穿。

## judgment_lines

- "AI 自动化的恰好是从来都不是真正难点的那部分" — 来源：文章结尾明确指出，AI 会写架构、生成 feature、跑 demo，但不会替你找到用户、被用户拒绝、判断什么才是真实需求；判断力才是当下的稀缺资源
- "突破 ≠ 产品，中间那步翻译工作本身就是全部" — 来源：ChatGPT 底层模型早于产品存在很久；Minecraft agent 能合力造出 300+ 物品获得 HN 热度，但始终没找到真实需求；Cursor 和 Claude Code 是专门的产品努力，不是研究成果自然生长的结果
- "自我表达可以是产品的种子，但永远不能是产品的认证书" — 来源：用自己的品味替代用户判断的区别：前者是假设，后者是事实；Fairies 的失败根源是团队想让白领成为用户，而白领并不这么认为
- "越提前搭好百万用户架构，你就越在用'真实的硬工作'来逃避还没来的用户" — 来源：scaling 是工程师最舒适的拖延，因为它是真实的、合理的、你擅长的——正因如此它是最完美的藏身之所
- "注意力是火花，产品才是燃料——火花打在空油箱上，秒灭" — 来源：Humane AI Pin 和 Rabbit R1 有史上最强发布声量，数月内崩盘；Cursor 几乎零营销靠口碑爆炸；Shortcut 发布视频病毒传播后 DAU 瞬间拉升又几乎同速跌落，留下用户的是产品质量

## evidence_map

- [具体 bug 场景] Fairies（通用桌面 Agent）的核心问题：空白聊天框 + "能做任何事"的定位 = 用户什么都看不出它是做什么的，使用方式的设计负担被完全转嫁给用户，而团队自己也无法解释它解决什么问题
- [具体对比数据] Shortcut（Excel Coworker）vs Fairies：Shortcut 第一天界面就是"电子表格 + 旁边的 Agent 面板"，用户一眼看懂无需解释；Fairies 同样定位 AI Agent，但零 affordance，从未找到用户
- [具体事实] Minecraft agent 团队：agent 能建造钻石镐、多 agent 协作造出 300+ 物品，登上 X 和 Hacker News，但始终无法确认这个技术能力对应任何人的真实需求
- [一手引用] Sam Altman（Vinod Khosla 对谈，2025）：ChatGPT 早期留存"惨不忍睹"，但少数留下来的用户使用量持续上升，这条上升曲线才是信号；他的经验法则：哪怕 5% 留存也是好信号，因为新产品默认留存是零
- [具体数字] YC 负责人炫耀每天 37000 行 AI 生成代码、连续 72 天——直到有开发者看了代码，发现全是臃肿和低级错误；行数从未度量价值，现在连努力程度都不度量了
- [具体事实] OpenAI 路径：2020 年上线 GPT-3 API，整整两年多后才有 ChatGPT；产品是从开发者真实使用 API 的方式中学出来的，不是从研究成果直接跳出来的
- [具体对比数据] Humane AI Pin + Rabbit R1（发布声量极大，数月崩盘）vs Cursor（几乎零营销，口碑爆炸）vs Claude Code（作为模型发布的附属 preview 悄悄上线）vs OpenClaw（GitHub 非聚合类项目最多 star）
- [具体事实] Shortcut 发布视频：DAU 病毒式拉升，随后几乎同速跌落；最终留住用户、拉动长期增长的是产品质量，而非发布热度
- [具体场景] Fairies 团队错误 feature：开发者加了"让 agent 改 app 主题颜色"功能，一句话让整个 app 变色，感觉很 agentic 很酷——但上线前没人能说清楚为什么它该存在、它服务哪个用户的哪个真实问题
- [具体事实] Excel 用户细分教训：从"所有 Excel 用户"慢慢找到真正有价值的子集——金融领域做高标准高质量工作的人。"打开 Excel 随手记几个数字"的人从未成为用户，追他们会失去真正的用户

## non_obvious_points

- "Jobs/Musk 式确信"是一个双面陷阱：人们模仿的是他们的确信，但确信本身是从无数错误和疤痕中挣来的窄范围判断，而不是对一切都正确的状态——模仿者拿走确信、去掉疤痕，就把"不愿意发现自己错了"伪装成了"有远见" — 为什么不显而易见：Jobs/Musk 的叙事通常只呈现"他们是对的"，而非"他们在哪些地方反复错了又如何重建"；人们直觉上把确信视为能力，而非代价的证明
- 日志/数据是早期最危险的逃避方式之一，因为它看起来最"科学" — 日志只捕捉行为痕迹，剥离了上下文和意图；你需要的是 why，日志给你的是 what；早期根本没有足够体量做统计挖掘，所以你用一个薄数据源替代了唯一的富信息源（直接观察用户），还给自己一种"数据驱动"的心理安慰 — 为什么不显而易见：数据被普遍视为客观，用数据代替用户访谈的决定在文化上被认可甚至鼓励，很少有人说这是一种逃避
- "用户知道自己的问题，不知道解决方案"这个原则的边界比通常理解的更锋利：用户是自己痛苦的可靠证人，但是不可靠的治疗方案设计师——因此深挖问题应该无限信任用户，而设计解法时必须完全独立判断，这两件事不能混淆 — 为什么不显而易见：大多数产品方法论要么说"听用户的"，要么说"别听用户的"，很少精确划出"在什么问题上听、在什么问题上不听"的分界线

## tradeoffs_and_limits

- [急于验证 vs. 产品完整度的真实张力] 文章鼓励尽早面对市场判决，但 Shortcut 的例子本身也说明：发布视频带来的病毒传播是虚假信号，真正的信号是之后的留存。这意味着"早发布"是必要的，但如果产品还没过基本质量线，早发布只会更快收到"没人留下"的答案而不是"为什么没人留下"的洞察。作者没有明确回答这个边界在哪——具体表现：团队仍然需要在"质量足够触发真实判断"和"别再等了"之间做不依赖规则的主观判断
- [传教式销售的成本] 文章要求创始人亲自做 missionary，但这与同时进行深度用户观察、产品迭代存在时间竞争——具体表现：早期创始人精力极度有限，文章要求你同时做的事（亲自销售、亲自坐在用户旁边观察、亲自迭代产品）在时间上互相挤压，文章对如何取舍着墨不多

## what_to_leave_out

1. **不该进入的素材**
   - 三个产品（Minecraft coplayer、Fairies、Shortcut）的完整产品史——细节太多会让视频变成创业故事复盘，观众关注的是可提取的原则，不是这家公司的编年史
   - Commandment 8 中关于"研究基础设施 vs 产品基础设施"的区分——是合理的细化，但受众（产品创始人）不是研究者，这个分支对他们的决策无实质影响
   - OpenAI API → ChatGPT 的具体时间线细节（2020 年上线 GPT-3 API 等）——可作为佐证一笔带过，但不应展开，否则变成 OpenAI 历史课

2. **应避免的叙事方向**
   - 不要把这十条当作"成功公式"逐条解析——作者明确说"遵循全部十条只是获得了也许成功的资格"，如果视频叙事变成"做到这十点你就能成功"，会误导观众且背离原文精神
   - 不要以"颠覆 AI 创业"为 hook 框架——原文不是反 AI，而是反"AI 让自我欺骗变得廉价"；前者是争议性标题党，后者才是真实论点
   - 不要平均分配十条的篇幅——原文自己也说前三条是同一个失败在三个深度的表现，视频应该有主次，用 2-3 条最有力的案例深挖，而非十条平铺
