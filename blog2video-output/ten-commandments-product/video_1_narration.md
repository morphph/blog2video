# AI 让造产品更容易，也让你更容易骗自己

## Hook

你有没有见过那种创业团队——代码写得飞快，每天几千行，架构也很漂亮，但就是找不到用户？

这篇文章的作者 Feitong Yang，是一家 AI Agent 创业公司的创始工程师。他们做过三个产品：Minecraft 里的 AI 队友、通用桌面 Agent、还有一个叫 Shortcut 的 Excel 协作 AI。

他亲眼看着前两个失败，第三个才勉强找到感觉。

他把这三次经历提炼成十条诫命。不是成功秘诀，是失败教训。我把里面最重要的几条拆给你看。

## 突破不等于产品

先从最普遍的一个陷阱说起。

过去几年，模型能力跳得太快了。很多工程师和研究员开始有一种感觉：技术突破本身就证明了价值，就像 ChatGPT 把研究成果直接变成了产品。

但那是一个神话。

ChatGPT 底层的模型，在产品发布之前就存在很久了。真正让它成为现象级产品的，是那个最普通的聊天框。而且就算这样，Sam Altman 自己说，早期留存"惨不忍睹"。

他们也犯过同样的错。

Minecraft Agent 项目里，他们做到了一件很酷的事：多个 Agent 协作，能一起造出三百多种物品，还能建钻石镐。登上了 X 和 Hacker News，获得了很多关注。

但他们始终没搞清楚一件事：这个能力，解决了哪个真实玩家的什么真实问题？

关注不是需求。技术壮举不是产品。

中间那步翻译工作——搞清楚是谁的问题、他们怎么用——才是全部的工作，不是注脚。

## 你以为你知道你的用户

说到"用户是谁"，他们在三个产品里犯了同一个错，犯了三次。

做 Minecraft Agent 的时候，他们说用户是 Minecraft 玩家。后来仔细一看：有人玩这个游戏是为了建造，有人是为了 PvP 对战，有人就是想跟朋友在一起。三种人要的是三个不同的产品。

做通用桌面 Agent Fairies 的时候，他们说用户是"白领工作者"。更诚实的说法是：他们希望白领是用户，但白领根本不这么看自己。

做 Excel Agent Shortcut 的时候，他们说"所有 Excel 用户"。后来才慢慢找到那个真正有价值的子集：金融领域里，做高标准高质量工作的人。

每次都是同一个移动：把模糊的标签当作"知道了用户"。

文章里有一句话我觉得说到位了：日志告诉你用户做了什么，但你真正饿着的是"为什么"。早期最危险的逃避，恰恰是那些最"科学"的东西——数据分析、漏斗报告——因为它们看起来像进展，但都是在重建用户行为的脑补版本。真正的办法只有一个：去坐在他们旁边，看他们在自己的环境里怎么用。

## 产品说什么，比产品做什么更早发生

Fairies 和 Shortcut 的对比，我觉得是这篇文章里最具体的一个教训。

Fairies 是一个空白聊天框，定位是"通用 Agent，能做任何事"。问题在于，"能做任何事"在用户眼里等于"不知道它能做什么"。团队自己都说不清它解决什么问题，用户更没办法自己想明白。使用方式的解释工作，被全部甩给了用户，而用户没有义务替你想这个。

Shortcut 第一天的界面是：一张电子表格，旁边一个 Agent 面板。

就这样。用户一眼看懂，零解释，直接开始。这个形式本身就是产品说明书。

因为用户一秒就看懂了，团队才能把精力放到真正重要的事上：他们到底在乎 Excel 里的什么？答案是准确性和公式正确性，排在第一位。

清晰的形式没有结束工作，它让真正的工作得以开始。

## AI 时代最危险的拖延

文章里有一个观察，我认为是这十条里最值得单独拎出来的。

以前，"搭百万用户架构再找用户"是工程师的经典拖延。现在，AI 让这个拖延升级了。

Coding Agent 让你在第一天就能搭出"正确的最终架构"，感觉像是跳过了探索阶段，直接到达了终点。但这是最新版本的幻觉，而且 AI 是它的推销员——它卖给你一个幻想：你可以在开始就全知全能，永远不需要发现任何事情。

YC 有个负责人炫耀说，自己的项目每天生成 37000 行 AI 代码，连续 72 天。后来有开发者看了那些代码，发现全是臃肿和低级错误。

行数从来不度量价值。现在连努力程度都不度量了。

正确的系统是随着产品找到用户的过程生长出来的。它不是由某个人在开始就设计好的蓝图——那个人以为自己已经看见了全貌，其实他什么都没看见。

## 注意力是火花，产品是燃料

第十条讲的是这个：

Humane AI Pin 和 Rabbit R1，发布时声量是近年来最大的。数百万次观看，预购售罄，媒体说这是未来。然后在几个月内双双崩盘。火花打在了空油箱上，秒灭。

另一边，Cursor 几乎没有营销，靠口碑爆炸式增长。Claude Code 是作为一个模型更新的附属预览悄悄上线的，没有发布会，没有倒计时。

他们自己的 Shortcut 也经历了这两面。发布视频有一个真实的病毒时刻，DAU 瞬间拉升——然后几乎以同样的速度跌落。

那次冲击从来不是真正的赢。

最终留住用户、让数字在视频被遗忘之后继续爬升的，是产品质量。发布热度让人看到了你，产品质量决定他们会不会留下。

## Synthesis

这十条诫命背后只有一个共同的敌人：所有让你感觉在前进、但实际上在回避第一手现实的东西。

读日志而不是看用户。用自己的品味认证市场。让 AI 搭好架构再找客户。用代码行数衡量进展。

这些动作以前就存在，只是当时代价够大，你不太容易沉迷其中。现在 AI 把建造成本降到了接近零，所有这些逃避手段都披上了"效率"和"生产力"的外衣，变得几乎无法识别。

文章结尾有一句话，我觉得是这篇文章的核心：

AI 自动化了那部分从来都不是真正难点的工作。真正难的那部分——判断你是为谁做的、他们需要什么、他们会不会回来付钱——这些还是你的。

## Closing

所以下次当你发现自己在想"再搭好这个架构就去找用户"，或者"再加这个功能就发布"——那个念头本身就是信号。

去找一个真实的人，坐在他旁边，看他怎么用。

AI 世界很吵，精读一篇，胜过刷一百条。我们下期再见。
