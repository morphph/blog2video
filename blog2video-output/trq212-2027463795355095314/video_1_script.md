# Video 1: Claude Code内部人揭秘：一个工具迭代3次才能用？

[SLIDE 1: cover] (0:00 - 0:30)

一个提问工具，迭代了三版。

Claude Code团队想让AI学会提问，第一版直接把模型搞懵了，第二版模型倒是学会了，但老是多加句子、漏掉选项。到底怎么才能造出一个模型"愿意用"的工具？

这里是精读AI。AI世界很吵，每期帮你从全球顶级AI团队的一手文献里，读透一篇最值得读的。今天我们精读的是Claude Code团队成员Thariq的最新分享。

[SLIDE 2: principle] (0:30 - 1:45)

Thariq提出了一个框架，叫Seeing like an Agent，像Agent一样看世界。

什么意思？给你一道数学难题，你想要什么工具？数学一般的人，一张纸就够了。数学好的人，计算器效率更高。程序员呢，给台电脑最好。

关键是，工具要匹配使用者的能力。Agent也一样。你给它设计工具，不是看功能完不完善，而是看它能不能理解、愿不愿意调用。

Thariq总结的核心教训：工具好不好，不是你说了算，是模型说了算。

[SLIDE 3: comparison_cards] (2:00 - 4:00)

来看具体的翻车现场。

Claude Code团队要做一个AskUserQuestion工具，让AI在执行任务时能主动问用户问题。听起来不难，对吧？

第一版，直接在ExitPlanTool上加了一个问题参数，让模型同时输出计划和问题。结果Claude搞混了。计划说"往东走"，问题却在问"要不要往西"。计划和问题互相冲突，模型不知道听谁的。

第二版，让Claude输出特殊格式的Markdown，用列表写问题，括号里放选项。Claude确实能输出，但不保证格式正确。它会多加一句总结，漏掉选项，或者干脆换一种写法。

第三版，做成独立工具。Claude随时可以调用，触发后弹出模态框让用户回答。

最关键的发现是什么？Claude"喜欢"调用这个工具。输出稳定，调用合理。就像填表格和自由写报告的区别。表格格式统一，自由发挥千奇百怪。

[SLIDE 4: comparison_cards] (4:00 - 5:00)

工具要随模型进化，这一点在TodoWrite上体现得最明显。

Claude Code早期，模型做着做着就忘了目标。团队给了它TodoWrite工具，写待办、打勾完成。即便如此Claude仍然会忘，团队只好每隔5轮对话插入系统提醒："别忘了你的待办清单。"

但模型在进化。Opus不仅不需要提醒，反而被提醒搞得更死板。系统每5轮催一句"看看你的Todo List"，Claude就觉得必须死守清单，不敢灵活调整。

而且Opus的子Agent能力变强了，多个子Agent需要协作，但TodoWrite是单机版待办，没法跨Agent共享。

所以团队用Task Tool替换了TodoWrite。Task不只是"记得做什么"，而是Agent之间的通信协议。能设依赖、跨子Agent同步，还能随时修改删除。

小孩骑车先装辅助轮，骑熟了辅助轮反而碍事。TodoWrite对新模型来说，就是那对辅助轮。

[SLIDE 5: summary] (5:00 - 5:30)

总结一下。工具设计的终极标准不是功能完备，而是模型能不能理解它、愿不愿意用它。模型在进化，你的工具也得跟着迭代。

给你一个马上能用的方法：给你的Agent加新工具之前，先让模型跑10次，观察它愿不愿意调用、输出格式对不对，再决定是否上线。
