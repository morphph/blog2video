# Video 2: Claude Code只有20个工具？不加工具也能加功能的秘密

[SLIDE 1: cover] (0:00 - 0:40)

Claude Code功能越来越多，但工具数量一直只有20个左右。你问它怎么配MCP、Slash Command怎么用，它不靠搜索工具，也不靠塞系统提示词。那它到底怎么做到的？

这里是精读AI。AI世界很吵，每期帮你从全球顶级AI团队的一手文献里，读透一篇最值得读的。今天我们继续精读Claude Code团队成员Thariq的技术分享。

上期我们看到Claude Code团队设计一个提问工具就迭代了三版，工具好不好用完全取决于模型买不买账。这期，我们来聊一个更反直觉的问题：怎么不加工具，也能给Agent加功能？

[SLIDE 2: principle] (0:40 - 2:20)

先说一个让我很意外的事实。Claude Code最早给模型提供上下文，用的是RAG向量数据库。听起来很合理，对吧？提前把代码库做好索引，模型需要什么直接检索。但后来团队把RAG整个砍掉了，换成了一个Grep工具，让模型自己去搜。

为什么？因为RAG需要提前索引和配置，换个环境就容易出问题。更关键的是，RAG是"你喂给模型什么，它就看什么"。模型没有选择权。

打个比方。RAG就像老师提前把参考资料挑好，复印好，发给学生。学生只能看到老师觉得有用的那几页。但如果你给学生一台能上网的电脑，让他自己查资料呢？他可能找到老师都没想到的角度。

Claude Code团队发现，模型自己搜到的上下文，比你精心筛选后喂给它的，反而更准确。这就是从RAG到自主搜索的转变。

[SLIDE 3: comparison_cards] (2:20 - 4:40)

好，模型能自己搜了。但搜索能力毕竟有限，总不能什么问题都靠Grep吧？Claude Code团队用了另一个策略：渐进式信息发现，英文叫Progressive Disclosure。

这个概念你可以这样理解。想象你在读维基百科。你读一篇关于"机器学习"的文章，里面有个蓝色链接指向"梯度下降"。你点进去，又看到一个链接指向"学习率调优"。每一层都是按需展开的，你不需要一次性看完所有内容。

Claude Code的Skills系统就是这个思路。模型读到一个Skill文件，文件里会引用其他文件。模型觉得需要，就继续读下一层。层层递进，最终精准定位到它需要的信息。

这里有一个数据让我印象很深：一年前，Claude完全不会自己构建上下文。现在，它已经能嵌套搜索好几层文件，精准找到需要的信息。模型能力的提升，让这种"不加工具也能加功能"的策略变得越来越可行。

再来看一个具体的例子。用户问Claude Code："怎么添加一个MCP？"这个问题该怎么回答？团队考虑过三种方案。

第一种，把所有使用说明塞进系统提示词。问题是，用户很少问这类问题，但每次对话都要带上这些内容。这会造成上下文浪费，影响模型做主要工作：写代码。

第二种，给模型一个文档搜索工具。能用，但模型会把一大堆搜索结果全部塞进上下文，其实你只需要一个简洁的答案。

第三种，也是最终方案：做一个Claude Code Guide子Agent。这个子Agent专门处理"怎么配置Claude Code"这类问题，它有详细的搜索文档的指令，知道该返回什么、不该返回什么。

注意，这个方案没有给主Agent加任何新工具。它是通过Prompt里的指令，让模型在遇到特定问题时启动子Agent。能力增加了，工具数量没变。

[SLIDE 4: checklist] (4:40 - 5:30)

所以，当你想给自己的Agent加新功能时，先别急着写新工具。问自己三个问题。

第一，这个功能是否可以通过让模型自己搜索来实现？如果可以，给它搜索工具，而不是预先喂数据。

第二，这个信息是否可以写成文件，让模型按需读取？如果可以，用Skills或者文档引用，不要塞进系统提示词。

第三，这个任务是否可以交给子Agent？如果可以，通过Prompt指令路由，而不是加一个新的Tool。

记住Claude Code团队的标准：目前约20个工具，加新工具的门槛非常高。因为每多一个工具，模型就多一个选择，选择越多，决策越慢，出错概率越高。就像餐厅菜单只有10道菜你很快能选，200道菜你反而不知道点什么。

[SLIDE 5: summary] (5:30 - 6:00)

总结一下。不要急着加工具，先想能不能让模型自己找到答案。从RAG切换到自主搜索，用Skills实现渐进式信息发现，用子Agent扩展能力边界。工具越少，模型反而越聪明。

你现在就可以做一件事：在你的Agent项目里创建一个skills目录，把常用操作的说明文档放进去，文档之间互相引用。让模型通过阅读文件来获取新能力，而不是调用新工具。
