你以为最可怕的是那些完全没想到的坑。
但真正烧钱的，是这些"看到才认得"的标准，拖到写代码阶段才浮现。
因为 spec 一点点变动，就能让代码实现天差地别，而 agent 很难把之前的改动干净地退回去。
所以要趁做原型、改起来还便宜的时候，把它们先逼出水面。
计划做得再足，未知的未知照样潜伏。
agent 做着做着，可能撞到代码里一个边界情况，被迫改道。
