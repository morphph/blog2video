# Video 1: Claude Code居然有7层？99%的人只用了第1层

[SLIDE 1: cover] (0:00 - 0:35)

Claude Code有七层，你用了几层？大多数人每天打开终端，问它写代码、改 Bug，以为这就是全部了。但这只是最表面的第一层。真正释放效率的那几层，百分之九十九的人根本没碰过。更离谱的是，其中有一层完全不依赖模型判断。就算 Claude 想跳过，也跳不过去。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Tw93 的 Claude Code 深度指南。

[SLIDE 2: principle] (0:35 - 2:20)

先来看全貌。Claude Code 的能力不是铁板一块，而是分成了清晰的七层。

想象一栋七层大楼。大多数人只在一楼大厅转悠，问问路、查查信息。但楼上还有会议室、实验室、甚至监控中心。你不上去看，根本不知道这栋楼能做什么。

这七层分别是什么？第一层，CLAUDE.md 和 rules，负责告诉 Claude"你是谁"。第二层，Tools 和 MCP，赋予它动作能力。第三层，Skills，按需加载的方法论。第四层，Hooks，强制执行规则的拦截器。第五层，Subagents，隔离上下文的独立工作者。第六层，Verifiers，验证闭环，确保结果可信。

这里有一个反直觉的关键点。这七层不是功能列表，而是设计维面。每一层解决的是完全不同维度的问题。搞清楚这个区别，你才真正开始理解 Claude Code。

[SLIDE 3: comparison_cards] (2:20 - 4:30)

那 Claude Code 到底是怎么工作的？核心是一个叫 agentic loop 的运行模型。

就像一个侦探破案。第一步，收集线索。读文件、搜索代码、查看 git 历史。第二步，采取行动。写代码、运行命令、调用工具。第三步，验证结果。跑测试、检查输出、审查变更。

这三步不断循环，直到任务完成。而且你可以在任何时刻介入，打断它、调整方向、补充上下文。它不是一个黑盒。

从这个循环出发，官方把整套架构归纳为五大设计维面。Context surface 决定哪些信息常驻、哪些按需加载。Action surface 决定 Claude 能做什么。Control surface 管住哪些操作必须被约束。

Isolation surface 决定哪些任务需要隔离上下文。Verification surface 判断任务是否真的完成了。

五个维面，对应五类完全不同的设计决策。

[SLIDE 4: checklist] (4:30 - 5:30)

那在这七层里，有一层特别值得单独说。就是 Hooks。

你在 CLAUDE.md 里写了一堆规则，Claude 有时候听，有时候不听。因为那只是"建议"。但 Hooks 不一样。它是硬编码的拦截器，在 Claude 执行操作的前后自动触发。不是跟孩子说"别碰插座"，而是直接装上插座保护盖。物理层面阻断，模型想绕都绕不开。

而且 Hooks 有一个被低估的优势。它的运行完全在模型之外，零上下文成本。不占用你宝贵的上下文窗口，却能强制执行规则。这比任何 prompt 约束都靠谱。

[SLIDE 5: summary] (5:30 - 6:00)

总结一下。Claude Code 不是一个简单的终端助手，它是一个七层可编程系统。真正的效率提升，不是学会更多命令，而是理解每一层解决什么维度的问题。

你现在就可以做一件事。打开你的 Claude Code 项目，检查一下你用了七层中的哪几层。至少把 CLAUDE.md 和一个 Skill 配置起来，感受一下"第二层"以上的世界。
