# 你的AI记忆，正在被大厂悄悄锁死？

## Hook

全球最大的 Agent 开发框架 LangChain，创始人 Harrison Chase 刚发了一篇博客权威解释。核心观点就四个字：Your Harness, Your Memory。Agent 的 Harness 和记忆是深度绑定的。用了闭源的 Harness，就等于把记忆的所有权交了出去。而这恰恰是 Anthropic、OpenAI 这些大厂正在主动推进的锁定策略。今天只聊这一件事。

## Brand Intro

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天精读的就是这篇 Your Harness, Your Memory。

## Agent Harness 不会消失

先搞清楚一个概念。Agent Harness 是什么？简单说，就是包裹在大模型外面的那套系统。模型本身只会生成文字。但一个 Agent 需要调用工具、读取数据、管理上下文。这些事情都不是模型干的，是 Harness 干的。

有一种很流行的说法：模型会越来越强，迟早会把这些外围系统全部吸收掉。听起来很有道理，但事实恰恰相反。

Claude Code 的源码泄露之后，大家发现里面有 512k 行代码。这些代码全部是 Harness 层的。连 Anthropic 自己——世界上最强模型的缔造者——都在重度投资 Harness。如果模型真的能吸收一切，他们为什么要写五十万行代码？

确实，2023年需要的很多 scaffolding 现在不需要了。但它们不是消失了，而是被新的 scaffolding 替代了。Agent 的定义就是大模型加工具加数据。只要这个定义不变，就永远需要一个系统来协调这三者。这个系统就是 Harness。

## 记忆不是插件，而是 Harness 的核心

接下来是今天最关键的一个认知。很多人觉得 memory 是一个独立的服务。就像数据库一样，接上就能用，拔掉也不影响。

但实际上不是这样的。

你想想 memory 到底涉及什么。对话消息怎么管理？工具调用的结果太大了怎么压缩？system prompt 怎么加载？跨会话的记忆怎么读写？什么信息在上下文压缩的时候保留，什么丢弃？

这些问题，每一个都由 Harness 来决定。Memory 脱离了 Harness，根本无法独立运作。

用一句话概括：Harness 怎么管理上下文和状态，就决定了 Agent 的记忆是什么样的。

这不是我的判断。Letta 的 CTO Sarah Wooders 说得很直接：管理上下文，也就是管理记忆，是 Agent Harness 的核心职责。

## 闭源 Harness 的三层代价

好，如果记忆和 Harness 是深度耦合的，那问题就来了。如果你用的 Harness 不是你自己的，你的记忆也不是你自己的。

这个问题有三个层次，一个比一个严重。

第一层，算轻微的。你用了 OpenAI 的 Responses API，或者 Anthropic 的服务端压缩。你的对话状态存在他们的服务器上。哪天你想换个模型，想接着之前的对话继续？做不到了。状态在别人手里。

第二层，比较糟糕。你用了一个闭源的 Harness。它怎么跟记忆交互的，你不知道。它在本地生成了一些文件，但这些文件的结构是什么，另一个 Harness 该怎么读取，完全是黑箱。你的记忆变成了一种无法迁移的格式。

第三层，最糟糕的情况。整个 Harness，包括长期记忆，全部藏在一个 API 后面。你看不到记忆的内容，不知道它的结构，甚至不知道它存不存在。你对自己 Agent 的记忆，零所有权，零可见性。

## 大厂正在主动推进锁定

你可能会问，这是不是想太多了？大厂真的会故意这么干？

答案是，他们已经在干了。

Anthropic 推出了 Claude Managed Agents。这个产品把所有东西都放到了 API 后面。Harness、记忆、状态管理，全部锁在他们的平台上。

OpenAI 的做法更巧妙。Codex 是开源的，代码你都能看到。但它生成的 compaction summary 是加密的。什么意思？就是 Agent 在压缩上下文的时候产生的摘要，只有 OpenAI 的系统能解读。你拿到了代码，但拿不到状态。开源外壳，闭源记忆。

还有一个容易被忽略的细节。当 OpenAI 和 Anthropic 说"我们把 web search 内置到 API 里了"，听起来像是模型变强了。但实际上呢？这不是模型的能力。这是他们在模型外面包了一层轻量的 Harness，通过 tool calling 去调搜索 API，然后以模型 API 的形式呈现给你。Harness 没有消失，只是被藏到了 API 后面。

## 为什么他们要这么做

为什么模型提供商这么执着于锁定记忆？因为光靠模型本身，锁定不了用户。

想想看，现在换一个模型有多容易。API 格式几乎一样。调整一下 prompt，换个 endpoint，就能跑起来。模型本身是无状态的，切换成本极低。

但一旦有了记忆，一切都变了。

你的 Agent 用了三个月，积累了你的写作风格偏好、你的工作流习惯、你对不同类型任务的处理方式。这些数据越积越多，迁移的代价就越来越大。

有一个真实的故事。Harrison Chase 自己内部有一个邮件助手。用了几个月，Agent 已经学会了他的语气、他的偏好、他处理邮件的习惯。然后有一天，这个 Agent 被意外删除了。

他用同一个模板重建了一个。但体验断崖式下降。他不得不从头教这个 Agent 所有的东西。

这个故事让我意识到两件事。第一，记忆的价值比我们以为的大得多。第二，没有记忆的 Agent 根本没有壁垒。任何人只要有同样的工具，就能复制你的 Agent。记忆才是唯一的专有资产。

## 锁定效应会随时间加速

这里有一个不太直观的点。记忆的锁定效应不是线性增长的，而是加速增长的。

你用一个 Agent 一周，切换的代价很小。用一个月，有点不舍得。用半年，你会发现你已经离不开了。因为 Agent 对你的理解是累积的，每一次交互都在加深这种理解。

这就是为什么模型提供商如此积极地把 memory 锁进自己的生态。他们不需要在模型能力上永远领先。他们只需要在你切换之前，积累足够多你的数据。

模型 API 可以一天换一个。但你的 Agent 记忆一旦交出去，就再也拿不回来。

## 开放 Harness 的代价与现实

说到这里，我必须讲一下另一面。用开源、开放的 Harness 不是没有代价的。

最大的代价是运维复杂度。Memory 的存储、索引、检索，全部要自己搞定。对于大多数团队来说，这不是一个轻松的选择。

而且坦率地说，现在整个行业对 memory 的理解还在非常早期。没有通用的抽象，没有最佳实践。很多团队连 MVP 里都还没加入长期记忆。先让 Agent 能用起来，再考虑个性化。

所以短期内，闭源 Harness 的体验可能确实更好。大厂有资源把记忆系统做得更精致、更无缝。

但这恰恰是最危险的时刻。因为你在享受便利的同时，你的数据飞轮正在别人的服务器上转动。等你意识到要迁移的时候，代价已经高到你迁不动了。

## Synthesis

回过头来看这件事的本质。过去三年，大家的注意力一直在模型能力上。哪个模型更强，哪个 benchmark 更高。但模型能力的竞争格局正在收敛，各家的差距越来越小。

真正的竞争正在悄悄转移到另一个战场：谁拥有用户的状态和记忆。

这不是一个技术问题，这是一个所有权问题。你的 Agent 越好用，你积累的记忆越多，你就越被锁在当前的平台上。而这正是平台希望看到的。

所以在选择 Agent 平台的时候，除了看模型能力、看功能列表，还有一个问题值得认真想一想：我的 Agent 记忆，到底存在哪里？我能带走吗？

## Closing

如果你正在构建 Agent 应用，现在就该考虑记忆的所有权。不是等到被锁定了再想办法。选择开放的 Harness，选择你能控制的记忆存储。短期可能多花一些功夫，但长期来看，这是你唯一真正拥有的东西。
