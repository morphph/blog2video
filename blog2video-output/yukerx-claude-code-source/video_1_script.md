# Video 1: 51万行代码只为一件事：让AI安全敲命令

[SLIDE 1: cover] (0:00 - 0:30)

你敢让一个 AI 直接操作你的电脑吗？Cursor 不敢，Copilot 不敢，但 Claude Code 敢。因为它为一个 Bash 工具写了 18 个安全文件、9 层审查机制。今天我们从泄露的源码里，拆解这套安检系统到底怎么运作的。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是安全研究者从 Claude Code 泄露源码中发现的安全架构。

[SLIDE 2: principle] (0:30 - 2:30)

先讲个故事。假设你要雇一个远程程序员，给他你电脑的远程访问权限。你会怎么做？

第一种做法：让他坐你旁边，每次敲命令之前你看一眼，点一下"允许"。简单粗暴，但你得一直盯着。这就是 Cursor 的做法。

第二种：给他一台全新的虚拟机，让他在里面随便折腾。搞完了把代码提交上来，你审核后合并。安全，但他看不到你本地的环境。这是 GitHub Copilot Agent 的思路。

第三种，也是最难的：让他直接用你的电脑。但你给他配了一套极其精密的安检系统。他能做什么、不能做什么、哪些操作需要你点头，全部写得清清楚楚。这就是 Claude Code。

三种完全不同的安全哲学。旁观式、隔离式、安检式。

为什么 Anthropic 选了最难的那条路？因为只有这样，AI 才能用你的终端、你的环境、你的配置来干活。这才是"真正帮你写代码"，而不是"在一个干净房间里写一段代码然后复制过来"。

但代价是什么？51.2 万行 TypeScript 源码，1903 个文件。

[SLIDE 3: comparison_cards] (2:30 - 5:00)

这些代码到底在干什么？我们来看看一条命令的真实旅程。

大多数人以为 AI 编程工具是这样的：用户输入，调用大模型接口，返回结果，完事。四步搞定。

但 Claude Code 实际的链路，远比你想象的长。

当你输入一条指令，它会先动态组装 7 层系统提示词，把你项目的 Git 状态、团队约定、历史记忆全部注入上下文。然后，大模型从 42 个工具中选一个来执行。

选完之后，关键来了。假设大模型决定执行一条 Bash 命令，比如 rm -rf。这条命令不会直接跑。它要过 9 层安全审查。

第一层，AST 解析。把命令拆成语法树，看它到底想干什么。第二层，ML 分类器上场。用机器学习模型判断这条命令的风险等级。第三层，检查沙箱状态，看当前环境是不是受保护的。

还没完。接下来是权限竞争解析。什么意思？就是本地键盘配置、IDE 规则、Hook 脚本、AI 分类器，四个来源同时在说"我觉得该允许"或者"我觉得该拒绝"。系统要解决它们之间的冲突。

这里有一个非常精妙的设计，叫 fail-closed。就像银行金库的门，断电时自动锁死，而不是自动打开。只要有任何一层说"不确定"，默认就是拒绝。

最后，即使所有审查都通过了，系统还会强制加一个 200 毫秒的延迟。为什么？防误触。给你一个反悔的窗口。

这 9 层审查，就是 Claude Code 写了 18 个安全文件才实现的。

[SLIDE 4: checklist] (5:00 - 5:40)

那怎么判断你手上的 AI 编程工具，安全做得到不到位？这里有几个信号。

打开你工具的设置页面。它有没有权限管理入口？你能不能看到它到底能访问你电脑的哪些目录？它执行危险命令之前，会不会弹确认？如果连权限管理页面都没有，说明它根本没在认真对待安全问题。

还有一个更根本的问题：它到底是在你的环境里跑，还是在一个远程沙箱里跑？如果是远程沙箱，它当然安全，但它也看不到你本地的真实配置。

[SLIDE 5: summary] (5:40 - 6:00)

最后总结一下。Claude Code 之所以好用，不是因为 AI 更聪明，而是因为它敢让 AI 直接操作你的环境。这个"敢"的背后，是 51 万行代码构建的安全网。9 层审查、fail-closed 设计、200 毫秒防误触，全部是为了一件事：让你放心把键盘交给 AI。

今天先拿一个动作回去：打开你的 AI 编程工具设置页，看看它到底能访问你电脑的哪些权限。
