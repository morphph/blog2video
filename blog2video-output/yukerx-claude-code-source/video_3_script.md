# Video 3: AI也要睡觉整理记忆？Claude Code的3大隐藏机制

[SLIDE 1: cover] (0:00 - 0:40)

你有没有发现，Claude Code 聊到后面越来越懂你？你告诉它"我不喜欢用 mock"，三天后它还记得。更神奇的是，它在你不用的时候会偷偷"整理记忆"。这背后是三套你从没见过的系统。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Claude Code 的记忆、多Agent和上下文压缩机制。

上期我们拆解了 42 个工具的按需加载和提示词编译架构。今天聊最后三个秘密：它怎么记住你，怎么一个变一群，怎么让对话永远不超限。

[SLIDE 2: principle] (0:40 - 2:40)

先说记忆。你肯定用过手机的相册搜索功能。你输入"猫"，它能找出所有有猫的照片。但它怎么找的？不是文件名匹配，是用一个小模型扫一遍所有图片，挑出最相关的。

Claude Code 的记忆检索也是这个思路。它用另一个 AI，Claude Sonnet，来决定哪些记忆和当前对话相关。不是关键词匹配，不是向量搜索。是让一个小模型快速扫描所有记忆文件的标题和描述，选出最多 5 个最相关的，注入当前上下文。

策略叫"精确度优先于召回率"。宁可漏掉一个可能有用的记忆，也不塞进一个不相关的记忆污染上下文。

但更惊人的是记忆的整理方式。代码里有一个叫 KAIROS 的特性标志。在这个模式下，白天的对话记忆存在按日期的追加式日志里。然后有一个 /dream 技能，在低活跃期运行，把原始日志蒸馏成结构化的主题文件。

比如今天的日志蒸馏完，变成两个文件：一个叫用户偏好，一个叫项目背景。AI 在"睡觉"的时候整理白天的记忆。这不是工程，这是仿生学。

[SLIDE 3: comparison_cards] (2:40 - 5:00)

记忆解决了"认识你"的问题。但还有一个难题：复杂任务怎么办？

答案是：它不是一个 Agent，是一群。

当你让 Claude Code 做一个大任务，它可能悄悄生成了好几个子 Agent。AgentTool 这个工具可以创建子进程，在后台并行工作。

但有一个关键设计。每个子 Agent 被创建时，系统会注入一段"自我意识"。原文是这么写的：你是一个工人进程，不是主 Agent，不要再生成子 Agent，自己执行。

为什么？防止递归。你想想，如果子 Agent 也觉得任务复杂、也去雇人，那就无限套娃了。

更精妙的是 Coordinator 模式。在这个模式下，主 Agent 变成纯粹的项目经理，自己不写代码，只分活。Phase 1，派 3 个 worker 并行搜索代码库。Phase 2，主 Agent 综合所有发现。Phase 3，派 2 个 worker 分别改不同文件。Phase 4，派 1 个 worker 跑测试。

核心原则：只读任务并行跑，写文件任务按文件分组串行跑。不会出现两个 Agent 同时改一个文件。

还有一个极致的优化。所有子 Agent 的工具返回值都用同一个占位符。为什么？因为 Claude API 的 prompt cache 基于字节级前缀匹配。10 个子 Agent 前缀完全一致，只有第一个冷启动，后面 9 个直接命中缓存。

[SLIDE 4: checklist] (5:00 - 6:00)

最后一个秘密：三层压缩。所有大模型都有上下文窗口限制，Claude Code 怎么让对话"永不超限"？

第一层，微压缩。只动旧的工具调用结果。比如你 10 分钟前读的那个 500 行文件，替换成一句"内容已清除"。对话主线完全保留。

第二层，自动压缩。当 token 消耗到上下文窗口的百分之 87 时自动触发。还配了一个熔断器：连续 3 次压缩失败就停止，避免死循环。

第三层，完全压缩。让 AI 对整段对话生成摘要，替换所有历史消息。这里有一条严厉的前置指令：只输出文本，不准调用工具，工具调用会被拒绝。为什么这么凶？因为如果总结的时候又去调工具，就会产生更多 token，适得其反。

压缩后还留了精确的预算：文件恢复 50000 个 token，每个文件上限 5000，技能内容 25000。

[SLIDE 5: summary] (6:00 - 7:00)

拉到最高处看一眼。三期下来，我们拆解了安全审查、提示词编译、工具调度、记忆系统、Agent 蜂群、上下文压缩。

51 万行代码，1903 个文件。你猜真正调用大模型 API 的部分占多少？不到百分之 5。剩下百分之 95 是安全检查、权限管理、上下文管理、错误恢复、多 Agent 协调。

这就是 Anthropic 给出的答案。Claude Code 不是一个 AI 编程助手，它是一个操作系统。42 个工具是系统调用，权限系统是用户管理，技能系统是应用商店，记忆系统是文件系统，Agent 蜂群是进程管理，上下文压缩是内存管理。

今天带走一个动作：在你的 AI 工作流里加一个记忆层。每次对话结束后，让 AI 总结 3 条关键决策存到文件里，下次对话开头注入。你的 AI 助手会质变。
