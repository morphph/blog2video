# Video 1: 10x程序员变40x？Notion创始人的秘密

[SLIDE 1: cover] (0:00 - 0:40)

一个人顶40个工程师。

Notion的联合创始人Simon，原来是标准的10x程序员。但现在他几乎不亲手写代码了。他同时操控三四个AI coding agent，午饭前把任务排好，睡觉的时候Agent仍然在跑。一个人的产出，直接从10x飙到了30到40x。

这到底是怎么做到的？更关键的是，为什么你目前做不到？

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Notion CEO Ivan Zhao 的文章 Steam, Steel, and Infinite Minds。

[SLIDE 2: principle] (0:40 - 2:10)

Ivan Zhao 提了一个特别有意思的比喻。

80年代，Steve Jobs 说电脑是"心智的自行车"。后来我们又修了"信息高速公路"。但你发现没有？过了几十年，大部分知识工作者仍然在高速公路上骑自行车。

AI Agent 的出现，终于让一部分人从自行车升级到了汽车。Simon就是第一批"开上车"的人。

但问题来了。为什么只有程序员先享受到了这个红利？

因为编程有两个天然优势。第一，上下文高度集中。代码、终端、仓库，所有信息都在一个地方。第二，结果可以验证。跑一遍测试就知道对不对，报错信息直接告诉你哪里出了问题。

模型厂商利用这个特性，通过强化学习不断提升AI写代码的能力。但其他知识工作呢？就没这么幸运了。

[SLIDE 3: comparison_cards] (2:10 - 3:50)

Ivan Zhao 指出了两个必须先解决的瓶颈。

第一个瓶颈：上下文碎片化。

想象你要写一份产品 brief。你得从 Slack 里翻对话记录，从 Google Doc 找战略文档，从数据看板拉指标。更麻烦的是，有些关键信息只存在同事的脑子里。

你就是那个复制粘贴的胶水，在十几个工具之间来回切换。AI Agent 想帮你？它连完整的上下文都拼不出来。

第二个瓶颈：工作不可验证。

代码写得对不对，测试一跑就知道。但一份战略 memo 写得好不好？一个项目管理得怎么样？没有明确的判分标准。

没有验证机制，模型就没办法自我提升。所以目前，人必须留在回路里做监督。

[SLIDE 4: quote] (3:50 - 4:30)

但"人在回路里"本身也有讲究。

1865年英国出了一个红旗法案，要求每辆汽车前面必须有个人举着红旗开路。听着荒唐吧？但这就是现在很多公司的状态：让人逐条审批每个 Agent 的输出。

Ivan Zhao 的观点很清楚：人应该在回路的上方做监工，而不是在回路里面做门卫。

从骑自行车，到开车，再到自动驾驶。这才是知识工作者的终局路线图。

[SLIDE 5: summary] (4:30 - 5:00)

所以核心结论是：AI Agent 的终局不是 Copilot，而是让你从骑车变成自动驾驶。但前提是，你的工作得先变得可整合、可验证。

今天你就可以做一件事：列一张清单，标出哪些任务的上下文分散在三个以上工具里，哪些任务有明确的对错标准。后者，就是你最先可以交给 Agent 的活。
