[SLIDE 1: cover] (0:00 - 0:30)

你知道吗？AI 每搜一次网页，花掉的 Token 里，有百分之八十都在读垃圾信息。

整个 HTML 页面，广告、导航栏、页脚，全部塞进上下文窗口。这就像你让实习生去查一个数据，他把整个图书馆搬回来了。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。今天我们精读的是 Anthropic 官方文档。

Anthropic 刚刚发布了 web search 工具的新版本，版本号 web_search_20260209。这次更新只做了一件事，但这件事可能会改变 AI 搜索的底层逻辑。

[SLIDE 2: principle] (0:30 - 2:00)

先说个反直觉的事实。

以前 Claude 搜网页，流程是这样的：发起搜索，拿到结果链接，然后把整个网页的 HTML 拉进 Context Window。你的上下文窗口就像一张办公桌，大小有限。你把一堆无关的文件往上堆，真正要用的资料反而没地方放了。

Token 消耗暴增，回答质量反而下降。信息越多，噪音越大。

新版本的核心功能叫 Dynamic Filtering，动态过滤。

它的原理特别巧妙。Claude 不再直接把网页内容塞进上下文了。它会先写一段代码，对搜索结果进行预处理。只有被代码筛选过的、真正相关的内容，才会进入上下文窗口。

打个比方。以前是实习生把整个图书馆搬给你。现在呢，实习生先翻一遍书，把划了重点的段落抄出来递给你。你拿到手的全是干货。

[SLIDE 3: comparison_cards] (2:00 - 4:00)

这个功能有几个关键细节，值得你注意。

第一，动态过滤依赖 Code Execution 工具。Claude 需要在服务器端执行代码来过滤内容。这属于 Server-side Tool Use，服务端工具调用。就像你点外卖，骑手自己决定走哪条路最快，你不用操心。

第二，目前只有两个模型支持动态过滤：Claude Opus 4.6 和 Sonnet 4.6。其他模型只能用基础版搜索。

第三，一个容易忽略的点。基础版 web_search_20250305 支持 Zero Data Retention，也就是阅后即焚，数据不保留。但新版动态过滤默认不支持 ZDR。因为代码执行过程中会产生中间数据。如果你一定要 ZDR，可以手动关闭动态过滤。

第四，Claude 在一次请求中可能执行多次搜索。它会根据问题的复杂程度，自己决定搜几次、怎么过滤。每次搜索按次计费，10 美元 1000 次。

这才是最让人兴奋的地方。AI 不只是在搜索，它在给自己雇了一个助理，先筛选，再阅读。

[SLIDE 4: summary] (4:00 - 5:00)

总结一下。Claude 的动态过滤，让 AI 搜索从大海捞针变成了精准狙击。用更少的 Token，得到更好的答案。

你现在就可以做一件事：把项目里的 web_search 工具版本从 20250305 升级到 20260209。一行配置的改动，立刻享受动态过滤带来的搜索体验升级。
