给 AI 加上搜索能力，只需要一行配置。

但如果你不知道接下来这几个隐藏参数，搜索费用可能翻好几倍，搜索结果也可能一塌糊涂。

这里是精读AI。AI 世界很吵，每期帮你从全球顶级 AI 团队的一手文献里，读透一篇最值得读的。

上期我们聊了 Claude 的动态过滤，让 AI 搜索从大海捞针变成精准狙击。这期，我们来看怎么在你的项目里把 Web Search 配置到位。

[SLIDE 2: principle] (0:30 - 2:00)

先说定价。Web Search 每 1000 次搜索收 10 美元，听起来不贵对吧？

但这里有个坑。每次搜索拉回来的网页内容，全都算 input token，额外收费。

你想想，一个复杂问题，Claude 可能自己触发十几次搜索。每次搜索拉回一大堆网页。单次对话成本，轻松破 1 美元。

这就像你办了一张信用卡，月费很便宜，但每笔消费都有隐藏手续费。不设限额，月底账单能吓你一跳。

所以 Anthropic 给了你一个参数叫 max_uses。它限制 Claude 在一次对话里最多能搜多少次。

设成 3 到 5 次，就够大多数场景用了。超出次数，API 会返回 max_uses_exceeded 错误，直接刹车。

这一个参数，就能帮你把搜索成本压到可控范围。

[SLIDE 3: comparison_cards] (2:00 - 4:30)

控制了次数，下一步是控制搜索范围。

Web Search 支持域名过滤，分两种：allowed_domains 白名单，和 blocked_domains 黑名单。

注意，这两个不能同时用。选一个就好。

白名单特别适合严肃场景。比如你只想让 Claude 搜官方文档，就把 allowed_domains 设成 docs.example.com。

这里有个细节：子域名自动包含。你写 example.com，docs.example.com 和 api.example.com 都会被覆盖。但反过来不行，你写 docs.example.com，就只搜这一个子域名。

通配符也有规矩。星号只能在路径部分使用，而且只能用一次。example.com/star 可以，star.example.com 不行。

再说地理定位。user_location 参数支持城市、地区、国家、时区四个维度。搜本地新闻、本地价格的时候特别有用。

最后一个大招：prompt caching。搜索结果可以被缓存。你只需要在请求里加一个 cache_control 断点，系统会自动缓存到最后一个搜索结果。多轮对话时，之前搜过的内容不用重新计费。

就像浏览器缓存一样，访问过的页面下次直接读本地，省流量又省时间。

还有一个边缘情况：pause_turn。如果 Claude 搜索时间太长，API 会暂停并返回 pause_turn 状态。你需要把响应原样提交回去，让它继续。别以为是报错就丢掉了。

[SLIDE 4: checklist] (4:30 - 5:30)

好，实操清单来了。你下一个 Claude API 项目，照着这几步配。

第一，加入 web_search 工具，type 设成 web_search_20250305 或者更新的 20260209 版本。

第二，max_uses 设 3 到 5。除非你确实需要大量搜索，否则别放开。

第三，用 allowed_domains 锁定可信源。官方文档、权威媒体，精准搜索比大海捞针强一百倍。

第四，如果是多轮对话，加上 cache_control 断点，省 token 就是省钱。

第五，处理好 pause_turn，别让长时间搜索的结果白白丢掉。

五步下来，你就拥有了一个可控、精准、经济的 AI 搜索助手。

[SLIDE 5: summary] (5:30 - 6:00)

今天的核心就一句话：Web Search 的关键不是"能不能搜"，而是"怎么控制搜索"。

用好 max_uses、域名过滤和缓存，搜索才能变成生产力工具，而不是烧钱机器。
